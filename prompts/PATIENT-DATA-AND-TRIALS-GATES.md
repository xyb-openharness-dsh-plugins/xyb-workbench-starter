# 三条硬闸门：患者数据 / 资料目录 / 临床试验（v1.0，2026-11-12）

> 来源：Behçet 与同批两个工作台在同一天踩的三类共性错误。它们都能通过语法、包清单、面板契约、文案红线，
> 但用户拿到手**无法真正使用**。本文件把「必须做到什么 + 怎么证明」写死；与 `FULL-CYCLE-KICKOFF.md`、
> `ZERO-TO-DEV.md`、`NEW-CANCER-WORKBENCH.md` 一起执行。与病种无关，所有社区患者工作台适用。

## 0. 一句话

**能新建自己的档案并落 sqlite、能真的选本机目录、临床试验入口四段齐且能算分。** 三条缺一条，
不允许报「可用」或「已交付」；报告里必须写「未实现」。

## 1. 患者数据：demo 之外必须有真实入口

必须同时满足：

1. **档案级新建入口**：顶栏或首页有「＋ 新建患者 / 新建档案」（不是"新建一条记录"）。
2. **服务端真写库**：`POST /api/<slug>/subjects`（或 `/profiles`）→ `INSERT INTO subjects(...)`；
   `profile_key` 不依赖姓名（同名不同人是两个人），新建档案 `is_demo=0`。
3. **多档案**：能列出、切换、删除自己建的档案；demo 档案不可删、不可覆盖。
4. **记录真的保存**：用户新增/更正一条记录后，刷新或重开仍在；保存失败要显示原因，
   记录留在页面并明确提示"别刷新"，不许静默吞掉。
5. **demo 与真实并存**：demo 行有 `is_demo=1` 或等价标记；demo 数据可以是前端合成语料，
   但不能是唯一数据源，也不能把 demo 的修改写进用户档案。

反例（当天真实发生）：只有两套合成档案，顶栏没有任何新建入口，README 截图和 `npm run check` 全绿，
用户无法记录自己的事。**页面数量不等于可用。**

闸门：

```bash
node scripts/check-patient-create.mjs .        # 四条：入口 / 接口+INSERT / 多档案 / demo 标记
node scripts/check-patient-create.mjs --self-test   # 反例必须红
```

## 2. 资料目录：按钮必须真的挂载

必须同时满足：

1. **真实选择动作**：调宿主 `uiWorkspace.pickDirectory()`（或 `showDirectoryPicker`）；
   按钮点开的是系统选择器，不是说明弹窗。
2. **拒绝清单**：主目录本身、桌面、下载根目录、tmp（以及文件系统根 `/`）一律拒绝。
   **前端与服务端各判一遍**；服务端必须再校验一次，不能只信前端。
3. **落点接上**：`cordis.patch.yml` 有 `config.root: !!js dshHomePath('<slug>')`，
   `dsh/index.js` 真的读取 `config.root`；用户切换后写入 `app_setting`，重开 Desktop 优先用用户选的目录；
   切换失败回滚原库，不能把数据根弄丢。
4. **未挂载提示只在降级路径**：`「本原型为示意，目录未真实挂载」`只允许出现在宿主确实没有
   `pickDirectory` 能力的分支；有选择动作却仍只弹这句话 = 假入口，红。
5. 失败/取消都要有人话提示；取消不产生空目录、不留空会话。

反例（当天真实发生）：开发版根本没实现目录选择，弹窗正文写「本原型为示意，目录未真实挂载」；
所有既有检查全绿，因为它既不报错也不违反字符串规则。

闸门：

```bash
node scripts/check-data-dir.mjs .        # pickDirectory / 拒绝清单 / config.root / 假入口
node scripts/check-data-dir.mjs --self-test
```

## 3. 临床试验：四段链路，三张子页，分数带分母

### 3.1 四段链路（35 号）

1. **建档**：只有"已确认入库"的字段参与匹配；未核对候选不参与。
2. **检索**：本地快照（`research/<slug>/trials*.sqlite|jsonl`，带 snapshotDate 与"会过期"提示）
   + 在线通道；**FAILED/DENIED 不算查过，不计覆盖**。
3. **匹配**：三态证据链（✓符合 / ✕不符合 / ?待确认）+ 条件类别 + 硬性标记 +
   "记录里是：… · 条件要求：… · 原文：…"；四档分层：**字段都对得上 / 部分对得上 / 需补充信息 /
   硬性条件不满足**（最后一档单列，不参与首位排序）。
4. **呈现/收藏**：候选线索可收藏（`saved_trial`，零副作用），状态是手工标记，不画假进度条。

### 3.2 三张子页（用户确认的形状）

- **基础档案**：年龄、性别、诊断确认、受累部位、当前/既往用药、妊娠状态。没填 = 待确认。
- **匹配检查**：关键词 / 状态 / 研究类型筛选；卡头写候选池口径「已载 N · 命中 M · 返回 K（不是全库扫描）」；
  这一步不产生分数。
- **结果分析**：大号百分数 + **固定分母**（`n/m 项对得上 · k 项待确认`）+ 分层标签 +
  证据链表 + 收藏。

### 3.3 分数纪律（缺一条就是"分数骗人"）

1. `pct = 符合项 ÷ 已对照项`；**待确认不进分母**；因此只会偏低、不会偏高。
2. **可对照项 < 2 条不给百分数**，只写「需补充信息」；病理/诊断未确认时整页不排名。
3. **药物靶点不进退分母**（DLL3 / B7-H3 / PD-1 / VEGF 是"药打哪里"，不是"我查出什么"）。
4. 排除条件含限定语（"感染性葡萄膜炎""眼部激素使用""TNF 抑制剂洗脱 4 周"）**不自动反转成不符合**，
   只标"待核对原文"；反向条件必须显式反转，词表两侧同源。
5. 每条结果固定带：来源通道与终态、snapshotDate、"登记状态，未核实"、
   登记状态 ≠ 有效 ≠ 可入组；百分数旁固定写"这不是入组资格，也不代表效果"。

### 3.4 裁剪不是想裁就裁

不能用「候选池会长期是个位数」「罕见病召回不可靠」这类**推断**裁掉整条功能线。
若确实裁剪：必须给出**实测**（N 条 / 快照日期 / 来源终态）与裁剪后仍保留的替代路径。
包里有快照却只放一个「裁剪说明页」= 数据在、入口是假的，红。

闸门：

```bash
node scripts/check-trial-chain.mjs .        # 四段齐 or 裁剪有实测；有数据却只有说明页 → 红
node scripts/check-trial-chain.mjs --self-test
```

## 4. 交付前必须一起跑的闸门

```bash
npm run check        # 三件新闸门已在这条链里；不许删
npm run test         # 失败项按实际报，不把 SKIP 计为通过
npm run audit        # 家族一致性
```

报告必须分三态写：**已实测 / 骨架 / 未实现**，并附命令、输出数字、环境、限制。
「装上了能打开」不等于可用；「check 绿」不等于用户能记录自己的数据。
