## 0. 运行模式

有人值守：开工前一轮提问（不超过 4 问：服务主体、病程覆盖、MinerU 是否接入、品牌占位名），用户不答按推荐项执行并写进 DEV-REQUIREMENTS §五「可回退默认值」；除"服务谁"之外不停等，闸口等到真实确认。

无人值守夜间：不提问、不停等，默认值同样落入 §五 并汇总进晨审报告待追认；时间盒到期停止开新里程碑，完成当前原子步骤即收尾；额度、鉴权、套餐类错误同一处最多重试 2 次，仍失败立即停跑并写报告，不整夜空转。

两种模式共用同一验收标准，夜间不降级；评审强度用检查器断言与独立评审轮次补足。

## 1. 闸口与签认

每道闸口（G1 / G2 / G3 / V1 / V2 / V3）逐项实测，禁止用"大体完成"代替逐条结论。单项结果只许四类：通过 / 失败 / 跳过（注明原因）/ 待人工（注明缺什么证据）。

有人值守：留确认人、日期、文档或代码版本、范围，由用户真实确认；用户只确认方向不等于该闸口通过，沉默、自动测试、先前版本的确认都不能推断新版本已确认。

无人值守：写 `docs/signoffs/<闸口>-自动签认.md`，字段固定为闸口、日期时间、commit、逐条结果与证据路径、未达标项、返工轮次、结论；结论只许「自动签认通过（待晨审追认）」「返工」「停闸」。一切自动签认不得表述为用户已确认。不达标自动返工最多 2 轮并追加复测记录，仍不达标即停闸，把余下时间用于写停闸报告（卡在哪项、证据、晨间建议）。

无人值守对外动作：允许认领 issue 与 `/claim`、建私有仓、本地 commit、项目内文件与脚本、装到本机 DSH Desktop profile；冻结 M7 的 tag 与 GitHub release、M8 的回填 PR，只备好草稿存 `docs/release-draft/` 并列进报告；禁止公开发布、向他人仓库推送、删除既有仓库或 issue。

每完成一个里程碑：本地 commit 并更新 `PROGRESS.md`（当前里程碑、已完成、下一步、阻塞、各闸口结论）。启动时若目标仓已存在且 `PROGRESS.md` 有未完成记录，按续跑处理，不重复认领、不重建仓。

夜班收尾写 `MORNING-REVIEW.md`，固定六节：一句话结论（到哪个里程碑或闸口、是否停闸）；原型审查入口（打开方式、截图位置与清单）；自动签认清单（全部待追认）；待用户决策项（默认值、停闸原因、冻结待发）；消耗（时长，token 以客户端可见数据为准，拿不到写未取得）；未验证与异常。

## 2. 省 token 的工作方式

省的是重复与搬运，不是证据。默认做法：

1. 先定位再读。用 grep / glob 找位置，按 offset 读片段；同一文件不重复通读；改动用精确替换，不整文件重写。
2. 搬运交给子代理。批量检索、多仓对照、大文件清洗、逐页扫描派只读子代理，只回收结论与 `file:line`，不回收过程。
3. 输出只留信号。命令输出取尾部并截断（默认 4000 字节）；构建与测试日志只留错误行加汇总数字；不粘贴整段日志、不重述已汇报内容、不 recap 已确认事项。
4. 门禁按整体跑。check 链与测试单次全量执行，失败只重跑相关子集，收尾再全量一次；未改动的模块不重复验证；已实测且未变的结果不重复声明。
5. 文档写结论与证据路径，不复制大段原文，引原文只引必要行；阶段简报固定五行（做了什么、关键文件、实测数字、仍缺什么、下一步）。

不许省的部分：闸口逐项实测、隐私三出口断言、真实视口与装机证据、失败与跳过如实记录、回流后的 starter 自检。

## 3. 开始之前

1. 读当前仓库 README、任务台账、AGENTS、线上宿主规范（`https://dshdesktop.com/workbench/docs/development.md`，读不到就声明未核对最新规范）与相关编号文档；查工作树、已确认事项、宿主可用性。保留用户改动；并行代理不同时改同一文件，合流后检查。
2. 检索 BACKLOG、开放 issue 与相关仓，按第 4 节领取。
3. 建私有仓并运行实际可用的 dsh-wb-cli；核对 package 的 dsh 块、repository、patch 与服务端配置。配置了 `config.root` 不等于服务端声明、读取并使用该目录，缺口记未接通。

## 4. 自动领取（先做，别问）

1. 读 `https://github.com/xyb-openharness-dsh-plugins/.github/blob/main/BACKLOG.md`，选未认领病种：优先 T0/T1、随访天然结构化、与已有仓差异化明显；查 issue 列表确认无人正在做；有认领者撤回时核实其释放记录。选择理由写进 DEV-PLAN。
2. 按实际存在的模板提 issue：分级判定卡六项加差异化矩阵至少 3 条（场景、功能、怎么验），评论 `/claim` 等 `claimed`。模板缺失或 404 时记录事实并按权限修复认领流程，确认 claimed 后才算认领成功。
3. `gh repo create xyb-openharness-dsh-plugins/<英文>-workbench --private`，clone 到目标目录，再 `node <starter>/bin/dsh-wb-cli.mjs init <目录> --config <json>`。
4. 接线前置（缺一装机必挂）：`cordis.patch.yml` 补 `config.root: !!js dshHomePath('<slug>')`（注释放条目后），核对 `package.json` 的 `dsh` 块与 `repository`。

### 阶段强化

M0–M1：单一证据台账，来源分级、版本、待决与失败 URL 一并留痕；原件、题录、二次来源、未取得分开标；中国适应证只认中国官方来源。指南只定内容边界，不转成自测或选治疗；未过临床审核的阈值与求助短语作待核占位。家族对照读实际导航、截图与交互代码，逐字保留名称并说明口径；场景、功能、页面、数据、交互、验收建双向映射，逐项列孤儿页、空壳、暂缓项，数量算术不等于验收通过。HVT 五层记录真实缺口，用户确认方向不等于 HVT 通过。

M2：按标准的「两组合成档案与一致性」「指标卡、一图秀和治疗线」「隐私、解析和宿主」三节执行，另加两项：X1–X4、C1–C12、MT01–MT15、P 项逐条记证据、缺项与版本哈希；独立评审 P0 清零后以确切版本过 G2。

M3–M6：G2 后冻结数据合同与迁移，标明字段语境、私密策略、来源、未知值、排序与禁止持久化的派生判断。移植验证版本、产物与 UI parity；真实数据、原生 AI、MinerU 各按接口契约验证成功与失败，桩件注册通过不等于宿主可用，API 跨界与 private 出口要有正反例。装机只向实际 DSH Desktop（`io.dsh.desktop`）加载的 profile 安装，排除被继承 `DSH_HOME` 指向的 CLI profile；真实核验包内容、依赖、bundle、重启后新会话、界面与业务路径。Web GUI、dev server、SSH 成功都不等于 Desktop 装机；不可用时如实写未验证，继续做不依赖装机的工作。

## 6. 硬纪律

- 不修绿：不改断言、哈希、迁移；不虚报：实测、骨架、未实现三态分清；装上了能打开不等于可用。
- 数据层：ORDER BY rowid、显式 null、in_use、分节 `*_title`、分类不进趋势、演示唯一源。
- 前端：页脚贴底、`[hidden]`、字号 12.5–15、面板 25–45% 可拖可收、无判读列、private 三出口代码级过滤。
- 工程：改包必升版；public 与原型逐字符（ui-parity）；并行写同仓以 check 链为准合流并立即提交；BACKLOG 改前先 pull。
- 测试：结果分通过、失败、跳过、待人工；检查器不支持的形态记未检查，不把 SKIP 计为覆盖；测试等实际加载与事件就绪，避免快照竞态，并用失败反例证明检查器有效；实测内容、命令、环境、版本、限制一并留痕。
- 汇报：实际成果、文件、测得数字、未完成项、下一步；患者与临床审核、真实宿主、外部服务、签认状态分别说明。

## 7. 经验回流

1. 每轮至少一条下一轮直接受益的回流（新文档、新检查器、新模版、新断言），否则视为 M9 未完成。
2. 优先级：可断言 > 文档 > 口头。能写成 check 的坑必须写成 check（computed fill、tgz 占位=0、版本十处同源）。
3. 模版化：本病种跑通的结构（32 号折叠卡、05 号计时组件、search 模块 API 化）抽象进 `templates/` 与编号文档，并在 ZERO-TO-DEV 交付清单挂钩。
4. 回流后跑 starter 自检（`node scripts/check-starter.mjs` 加 `npm test`）；坏文档等于坏模版。
