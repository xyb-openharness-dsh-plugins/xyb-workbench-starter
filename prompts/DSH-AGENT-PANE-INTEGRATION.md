# DSH 原生 Agent 对话面板集成提示词（可复用）

把本提示词作为 DSH Desktop 工作台的 UI/宿主集成设计与实现合同。先读取项目 `AGENTS.md`、README、SPEC、HTML 原型、`docs/02-DSH-CONTRACT.md` 与当前会话；继承用户已确认的行为。**首轮先向用户展示本提示词实际路径，并用原型对照/当前实现证据说明集成状态，再讨论未决差异；不要先编码或把默认分栏当成符合需求。**

## 目标与布局原则

将 DSH Desktop **原生 Agent 对话**集成到工作台。工作台是用户当前任务的核心，必须处于中间/主工作区并获得主要空间；Agent 面板固定在工作台右侧，默认关闭或以可配置窄栏打开（项目 SPEC 决定默认值）。禁止把对话放在中间覆盖/挤占工作区，禁止把工作台推到边缘或缩成次要内容。宽度不足时，优先保留工作台可操作宽度；Agent 可折叠为右缘入口，不能覆盖关键表格、图表或主操作。

CustomFrame 桌面工作台的可复用宽度基线：Agent 展开时默认占工作区 **35%**，可拖动范围 **25%–45%**；分栏顺序为“中间工作台、最右侧 Agent”。仅在产品或用户明确确认其他尺寸后才偏离此基线。工作区宽 **620–760px** 时，工作台顶栏改为两行/可换行布局；左侧导航仍显示图标和文字。只有工作区进一步窄于 **620px** 时才折叠导航文字。断点须用工作台容器宽度而非整窗宽度计算。

### AI-IDE 配套设计交付

这里的“AI-IDE 集成”特指把 DSH Desktop 原生 Agent/会话 UI 嵌入业务工作台，不是在业务侧仿造一个聊天应用。产品设计必须同时交付工作台主区与原生 Agent 右栏的配套状态稿；单独一张业务页原型不足以批准宿主集成。HTML 状态稿应可操作地展示默认关闭/打开、35% 默认宽、25% 与 45% 宽度、拖动分隔边、隐藏后重开、620–760px 顶栏换行且导航保留文字、窄于 620px 后的导航折叠，以及加载/失败和原生草稿冲突状态。草稿状态要显示“保留用户现有输入、阻止覆盖或发送”的结果。

状态稿中的对话内容必须标明“宿主模拟 / 非真实 DSH 会话”；不能以假聊天框证明原生 UI 接通，也不能在设计稿中虚构会话已绑定、已发送或已回复。原生 conversation 组件只在指定 Desktop/Harness RC 的实机里验证。宽度、断点、入口、收起/重开、AI-IDE 行为和业务主区层级需同步记录在本项目 `docs/AGENT-PANE-DESIGN.md` 与原型索引中，确保需求、HTML 状态稿和实现可逐项追踪。

集成的是 DSH Desktop 自带的会话与消息 UI：不在业务 WebView 里仿制聊天窗口，不自行实现第二套消息记录，不改变 DSH 官方 Desktop 或 DSH Web。确认目标为用户指定的 Desktop / Harness RC 版本，并以该版本官方合同核对 API；未知接口不得猜名调用。

## 用户可见交互合同

1. **入口明确**：工作台顶栏右侧提供“AI 对话”按钮，图标加文字/可访问名称；状态文案区分“未打开”“正在连接”“已连接/会话名”“暂不可用”。按钮旁提供单独的收起/隐藏控件。不能只靠隐藏在面板内部的关闭按钮。
2. **显示位置**：点击入口后在业务工作台右侧打开 DSH 原生对话面板。主工作台仍为中间主列；左侧导航位置遵循已确认原型。面板与业务之间有清楚的竖向分隔线和可拖动 splitter。
3. **拖动宽度**：鼠标/触控可拖动 splitter 调整右栏宽度，最小/最大宽度按项目内容确定并在窄窗保护主区；提供键盘可访问的 splitter（方向键调整、Home/End到边界、ARIA `separator`/`valuenow`）；可有明确的窄/标准/宽快捷按钮。拖动过程不卡顿，不能导致工作台页面滚动位置或筛选/草稿丢失。项目重开时恢复已保存宽度；存储方式和隐私范围写入SPEC。
4. **隐藏与重开**：关闭/隐藏仅关闭面板，不清除工作台数据、筛选、草稿或已选上下文；右上“AI 对话”按钮变为“打开 AI 对话”并可复开同一会话。另提供独立的“关闭当前会话”仅在 DSH 合同支持且用户确实需要时设计，不能把隐藏等同于删除/结束会话。
5. **自动创建衔接打开**：用户首次明确点击“AI 对话”时，检查本工作台的会话归属并复用已绑定的会话；无绑定会话时通过受支持的创建流程创建一次、建立本工作台与会话的明确关联，然后打开原生面板。重复点击、并发渲染、慢速异步返回不得重复创建会话。失败时保留工作台状态，显示可重试原因与入口；所有权未知/不匹配时不可发送或偷偷切换会话。除非用户明确要求，不在工作台加载时静默新建会话。
6. **上下文衔接与一键发送**：可从工作台各功能提供“与 Agent 讨论”按钮；将当前页面/选中资料/患者已确认事实/未决问题整理成可预览草稿，标出资料来源、时间、核对状态和缺项。用户点击“带入对话”后再把草稿填入**原生会话输入框**；若 DSH 合同支持明确提交，可给出“发送”二次动作或一键发送偏好，但默认不绕过可见确认，不自动发送未预览的医疗信息。若产品实现一键发送，设置必须显式启用，按钮文案写明将发送哪些材料，并在发送前给出确认/撤回路径。AI 回复仍由 DSH 原生界面展示，工作台不得擅自把回复写成病历事实、治疗计划或已接受建议。
7. **草稿与冲突**：若原生输入框已有草稿、附件或提交状态，不得覆盖、合并或误发。显示冲突提示，允许复制到剪贴板、追加到当前草稿（清楚区分并经用户选择）或取消。保留用户现有输入。复制失败应提供可选择文本的回退。
8. **可恢复性与异步状态**：会话加载、切换、超时、网络/宿主错误、无权限、版本不兼容、窗口变窄、面板重开都有明确状态。晚到的旧会话响应不能覆盖当前所选工作区/会话；切换项目时清除旧项目上下文快照，不清除原生会话历史。

## 医疗产品边界

患者/家属是产品主要用户。AI 可帮助按用户授权的个人资料提供带来源的解释、整理问题和可讨论选项，帮助理解与准备决策；医疗处置由专业团队确定。只有用户挑选并确认的资料可进入草稿；私密心理记录、未核实抽取候选、遗传家属信息等按业务隐私合同排除或逐项授权。清楚区分本人记录、报告原文、AI 草稿、已发送内容和团队确认；不得将 AI 输出自动沉淀为临床事实。

Web UI 若另有独立 AI 功能，遵守仓库 AGENTS 的 AI Elements / FastGPT Edge 规范；本提示词只约束 DSH 原生会话嵌入，不通过浏览器直接持有 FastGPT Key，也不以 Web 聊天替代 DSH 原生 Agent。

## 设计和开发过程

1. 建立 **UI Parity 表**：逐项列原型位置/控件、现状 DOM/宿主能力、缺口、修改目标、验收方法；分别核对主页、复杂图表、指标翻面、临床/病理、检索/详情、设置和原生会话。文案相似或有导航入口不等于交互复刻。原型已有已确认行为时，必须保留内容层级、布局、事件、动画和状态；偏离需先记录原因、风险、替代与用户确认。
2. 先给出右侧面板低/中/高宽度的可交互 HTML/宿主仿真草图，展示默认、拖动、收起、重开、窄窗、空会话、已有草稿冲突、加载失败和被拒绝等状态；仿真不得伪称 DSH 原生会话已接通。确认后才实现宿主接入。
3. 按项目使用的 DSH RC 官方 API 与类型检查会话创建/复用、ownership、conversation 组件、输入 draft/submit、resize/customFrame 或 split contract。记录验证过的 Desktop、Harness、API 版本。桌面宿主要求时安排重启后人工验收；Agent 正运行在目标 Desktop 内时，不由 Agent 自行关闭/重启。
4. 数据模型与 UI 解耦：面板展开/收起/宽度属展示偏好；会话归属/会话ID属宿主绑定，不作为患者病情事实；一次性上下文草稿与已保存事实分开，默认不持久化完整草稿。列出迁移与旧版恢复行为。

## 验收清单（全部需可观察）

- 工作台仍处于中间主区域；右侧面板打开、关闭、重开位置正确；默认宽度不压缩关键区域。
- splitter 鼠标和键盘均可调整，边界受限，ARIA 状态正确，重启后按合同恢复；窄屏折叠可用。
- 首次点击至多创建一个正确归属的原生会话；再次打开复用；项目/会话切换和异步竞态不串资料。
- 显式预览/选择的上下文才能带入；现有原生草稿/附件不被覆盖；发送状态清晰；隐藏面板不丢失页面状态。
- 错误、无权限、接口不可用、RC 不兼容均不产生假成功，并可保留工作台继续使用。
- DSH原生对话在指定 RC 实际渲染、可输入、可回复；开发自测和静态 DOM 不能代替已安装 Desktop 验收。
- 高精度原型既有业务页按 parity 表逐项对照；关键功能至少覆盖一图秀、指标、临床/病理和检索，确保不是“有页面名却没有交互”。
