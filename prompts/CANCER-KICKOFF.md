# 癌种工作台发起提示词 v2.0（用户 → 开发会话的标准开场）

> 用法：把本文件复制给新会话，填四个空后发出。执行规程以 `prompts/ZERO-TO-DEV.md`（v1.2+）为准——本文是**发起层**：任务定义、互动规则、验收节奏与两轮实战的避坑清单。
> v2.0 由两轮完整实践沉淀：**GBM 胶质母细胞瘤**（2026-10-24，装机四连踩全过：404 → 版本簿记 → 占位客户端 → apiBase 契约）与 **MPM 恶性胸膜间皮瘤**（2026-10-24，独立评审 P0=0 一轮通过）。

## 一、任务定义（四个填空）

- 病种中文名＝【填】，英文名＝【填】——决定目录 `<英文>-workbench`、DB `xyb-<英文>.sqlite`、API 前缀
- 资料目录＝【用户明确指定；主目录 / 桌面 / 下载根 / tmp 一律拒绝，不替用户猜】
- 参考样板＝【移植样板 + 成熟对比基准，两回事】：
  - **移植样板选 client 链路成熟度最高的仓**（当前推荐 `cervical-workbench`：src/client.js → build-client.mjs → lib/client.js 488 行完整外壳；不要只看功能多不多）
  - **成熟对比基准固定 `breast-cancer-workbench`**（26 号 §3 口径，DIFF-MATRIX 用）
- 认领＝在 `xyb-openharness-dsh-plugins/.github` 用 **01-workbench-claim.yml 模板**提 issue：分级判定卡六项 + **差异化矩阵 ≥3 条（场景 → 功能 → 怎么验收）** → 评论 `/claim`；先查 BACKLOG 确认未认领、无冲突

## 二、四条总原则

① 原型是唯一视觉基准，开发版逐字符对齐；② 数据只有一个来源；③ 没实测不写"通过"，没核实写"未核实"；④ **约定必须有测试与语境栏**——slogan 级约束（如"apiBase 不含 /api"）脱离适用语境传播，到宿主模式就是白屏炸雷（GBM 踩 4 的元教训）。

## 三、患者视角红线（发起人最强调的一条）

- 场景核心是**患者的关键信息维度**，不是医生视角——两者的落差就是产品价值。
- 每条功能线挂一句**患者原话**（"这条线接住哪句话"）；写不出原话的线先删。
- "医生任务冒充患者需要"是独立评审的一票否决项；判读/分期/疗效判定永远归属医生，产品只并列事实。
- 证据分层如实：0 访谈就写 0 访谈；文献语境改写句不得冒充一手引语；二手来源标"待核验"。

## 四、互动规则（先问后动，问了不等于停）

1. 开工前**一轮集中提问**（AskUserQuestion，≤4 问）：服务主体（患者/照护者双主体？）/ 病程覆盖（全病程？）/ MinerU 是否接入 / 品牌占位名。
2. **用户不答 = 按推荐项执行**，逐条记入 DEV-REQUIREMENTS §五"我替你定的默认值（可回退）"，G1 时一并确认——不因等待阻塞。
3. 除"服务谁"级别的问题外，不停下来等确认；阶段闸口（G1/G2/G3）才是停下点。

## 六、汇报节奏（发起人点名的 M1–M7 进度汇报）

- 每个里程碑完成即汇报，**5 行内**：做了什么 / 关键文件 / 实测数字 / 仍缺什么 / 下一步；中途不抛大段代码。
- G1/G2/G3 三个闸口**单独请求签认**，附确认物（demo 打开方式 / 冻结 sha256）与"我替你定的默认值"清单。
- 阻塞在用户输入时，输出"待拍板清单"（每条：问题 / 选项 / 推荐 / 不选的后果）。
- 装机后必须等用户真机走查（V2/V3）才算 M6 完成——"装上了能打开"≠可用。

## 七、技能与模型路由

- 技能：`ai-spec`（需求审计 / 完成度铁律 ✅🔧⏳ 严禁虚报）、`taste`（情绪定位 → 风格基因 → 品牌三变量）、`unified-trial-mcp`（试验四通道）、`design-taste-frontend`（M2 载入）、MinerU 18 号 v2（M5 六部件）。
- 模型路由：**主线设计/评审/代码在 GLM-5.3**；批量检索、字段清洗、红线扫查等重复任务可经动态工作流路由 **GLM-5.3-Flash**——质量闸口（parity / 红线 / 独立评审 / 签认）**永不降级**。
- 本地已有服务先 `doctor`/`pull --ff-only` 核版本，不重复下载。

## 八、两轮实战"发起期就能避"的坑（速查，详因见 starter docs/LESSONS.md 2026-10-24）

| 坑 | 发起期动作 |
| --- | --- |
| 移植样板选错，装机才发现 client 链路是占位 | 样板按 **client 链路成熟度**选（cervical 488 行为当前基准），M5 交付清单写死 `src/client.js → build-client.mjs → lib/client.js` |
| 同版号重打包，宿主装的是旧文件 | DEV-REQUIREMENTS 写死**改包必升版**（VERSION → package.json → public 字面量 → lib/version.js 十处同源） |
| apiBase 守卫白屏 | 定稿契约原文抄进 DEV-REQUIREMENTS：挂载前缀 + 交界守卫 `/(^|/)api$/` + 双形态回归测试 + 禁裸 throw |
| config.root 缺失，服务 404 | M0 就补 cordis.patch.yml（注释放条目后）；对照 06 号四要素 |
| 窄宽挤压竖排单字 | 30 号六条硬规则写进 M2 任务书，probe-responsive 移植 |
| 场景文档滞后于实现（评审 P1 常客） | INTERACTION-DESIGN 与实现同步升版本；路径变更**先改文档再改实现** |
| 实现先于文档被评审打回 | 评审对象 = git HEAD；评审后 P0 修复留痕（commit 号）再交签认 |
