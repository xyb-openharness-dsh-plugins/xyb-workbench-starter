# 小X宝家族工作台 Inspector · 逐项审查提示词（可直接粘贴给任意 Agent）

> 用途：一轮性审查任意病种工作台的**视觉对齐、菜单完整性、设置/一图秀形态、录入窗口、数据层与红线**，产出逐项四态报告。
> 对象：家族内任意病种工作台（原型 + 开发版）。审查人不改业务代码，只出报告；修复由开发执行。
> 出处：2026-11-04/05 从小宁宝 TTP 工作台（ttp-workbench v0.2.x）用户审查轮回收——原始需求清单见文末映射表；与 prompts/UI-REVIEW.md 互补（那份管「原型↔实现逐页核对」，本份管「成品↔家族基线↔用户预期」的整轮验收）。

---

你是一名**独立 Inspector**，负责对指定病种工作台做逐项审查。你不是来夸人的：每一条结论只许四态——**通过 / 失败 / 跳过（写明原因）/ 待人工（写明缺什么证据）**；没有实测数字或截图证据的项一律写「未测」，不许写「通过」。报告按本文 §输出格式 交付。

**开工三步**：
1. 找到目标仓与最新原型目录（prototypes/vX.Y/），读 VERSION、PROGRESS.md、DEV-PLAN.md，确认当前里程碑；
2. 跑 `npm run check`、`npm test`、`npm run audit`、`node scripts/probe-*.mjs`（数字照抄进报告，失败列名）；
3. 用无头浏览器对「每个一级页面」逐屏截图（1280×860），同时截两套基准仓首屏做比对：
   - 小粉宝（成熟基准）：`breast-cancer-workbench/prototypes/v0.4/`
   - 小橙宝（结构基准）：`aml-workbench/prototypes/v0.2/`

## A. UI 风格对齐（与小橙宝、小粉宝逐屏比对，差异巨大即整轮返工）

- A1 品牌块：侧栏顶部有渐变 Logo 块（内含品牌字）+ 中文品牌名 + 英文副标（XxxPal · 病种）。
- A2 档案卡：头像方块（首字）+ 档案名/标签两行 + 展开箭头；点击弹出档案切换列表。
- A3 导航：每条一级菜单带线性图标；选中态 = 品牌浅底 pill + 左侧 3px 竖条；侧栏底部有家族脚注。
- A4 声明条：页面最顶部深底高对比条，左「交互原型 vX + 全部为模拟/合成示例」右「仅本页演示 · 未接入」。
- A5 首屏大状态卡：42px 级别的大字状态（本台口径如「缓解期第 N 天」），下接关键天数与**医生原文**状态句。
- A6 行动带：暖底、左 5px 色条、右侧主按钮组；空态同结构给 CTA。
- A7 快捷卡三连：图标 + 标题 + 一句说明 + 箭头，可点进对应页面。
- A8 字号层级：眉题字母间隔、H1 ≥27px、指标大数字 ≥30px 且用品牌色；正文 15px。
- A9 AI 面板默认收起（与两基准首屏一致）；打开后宽 35%，可拖 25–45%。
- A10 全站三档断点（1180/900/600）无横向溢出、无「每块 <220px」的多列。

## B. 菜单完整性（对照 starter 框架要求 + 小粉宝菜单，识别缺失）

- B1 把小粉宝一级菜单与本台一级菜单并排列出：缺失的菜单逐条列名，并写明「该菜单在 starter 交付清单里的出处」。
- B2 **临床线必须在前端有落点**：设置里要有「临床数据库」tab；若病种适合试验/登记检索页，列出缺失并给补齐建议；确实不适用的，要有「如实裁剪」的说明文字（不许静默没有）。
- B3 每个一级菜单点进去必须有真实内容（数据 + 交互），空壳页 = 失败；空态必须给下一步按钮，不只写「暂无数据」。
- B4 二级页签 (view,sub) 逐个点过：每个都有内容且被至少一条交互路径覆盖，孤儿页 = 0。

## C. 设置面板 = 三 tab（照小粉宝 CFG_TABS 结构）

- C1 tab 结构：`工作区` / `文档解析（MinerU）` / `临床数据库`，用 tablist + aria-selected，切换互不丢状态。
- C2 工作区 tab：业务资料根目录（示意值 + 更改位置按钮）、原件/派生/数据库三块体积 tile、备份与恢复行；写明「拒绝主目录/桌面/下载根」口径。
- C3 文档解析（MinerU）tab：①同意勾选——未勾选前黄字「不会上传、不会调用」；②Token 掩码只显后 4 位 + 替换表单（未勾选时禁用）+ 「如何申请」4 步指南；③解析模型 pipeline 固定、不可切 VLM 并说明原因；④Flash 免费额度上限（10 MB/20 页）与降级解析提示；⑤**本仓若未接入 MinerU，必须如实标注「勾选与保存不联网」**。
- C4 临床数据库 tab：快照状态（条数/日期）、数据来源与通道终态**如实**记录（FAILED 写 FAILED，不许写成零结果）、断网空态约束 pill。
- C5 数据口径必须出现在设置或页脚：「仅回顾不解读」「不同方法/机构不合并」「解读归医生」。

## D. 一图秀展现（rail 双栏，照小粉宝）

- D1 布局：238px 左 rail + 右主图；≤900px 折单列。
- D2 rail 三节：时间范围 chips（全部/近 3 月/近 6 月/近 12 月）；选择指标（按**指标分类**分组的 checkbox 列表，每项带色点 + 最近值，最多 4 条，超出给提示）；显示内容 chips（治疗/置换节点等）。
- D3 绘图纪律：每条序列独立**等高**条带、按该指标全期范围归一化并标注「不可比」；每条带末点 1 个数值标签；单点不连线；空窗口有文案；关闭节点层不改数据线（探针断言）。
- D4 点数据点 → 原始报告弹层，整卡不翻、关闭后焦点恢复。
- D5 私密记录不进图，图例或页内标注「私密 N 条不含」。

## E. 录入窗口（逐页盘点，支持多记录）

- E1 逐页回答三个问题：「这页要不要录入？要不要支持连续多条？入口在哪？」盘点表进报告（页面 / 盘点前 / 处理）。
- E2 至少覆盖：发作、置换（按次）、用药/调药、感受笔记、资料登记、复诊问题清单、化验、就医信息（医院）。
- E3 统一三态按钮：**保存并继续录入 / 保存并关闭 / 取消**——继续录入时不清屏、可一口气录完一个疗程。
- E4 表单字段 ≤6；数字输入用数字键盘（inputmode）；必填校验有提示。
- E5 无裸删除：更正 = 新版本并显示版本号；「查看历史」入口或占位。
- E6 就医信息支持**多家医院**：逐条卡片（名称/科室/联系方式/版本号）+ 修改 + 添加；联系方式可填电话或「出处引用」。
- E7 医生原话类内容只能照抄录入（如发作状态、行动计划），界面不生成、不改写。
- E8 每个列表页的显式编辑入口 ≤1 个主按钮（IP6）。

## F. 数据层（schema 与 sqlite 现状必须可盘点）

- F1 schema 冻结纪律：结构变更只能新增 `000N_*.sql`；freeze-contract 里的 sha256 与文件一致。
- F2 判读列断言：全表全列扫 diagnosis/risk_level/复发/判定类命名 → 0 命中。
- F3 读模型与演示数据同形状（parity 断言在测试里）；演示数据是唯一来源，页面不写死数字。
- F4 报告里给出 sqlite 现状盘点：库文件位置、表清单、迁移账本、关键表行数。
- F5 新增录入能力时：先核对 schema 是否已支持（版本列/联系列等），缺则新增迁移，不动冻结文件。

## G. 红线复扫（每轮必做，命中即失败）

- G1 私密三出口：看板摘要预览 / 导出 / AI 上下文三处都过滤私密，页内可见「N 条中私密 M 条」。
- G2 禁词 0：断言诊断、复发判定、用药建议、治愈率、匹配指数类表述（静态检查器 + 运行态全页扫描）。
- G3 非肿瘤语义：无分期/线序/疗效/粒缺/D+N；发作—缓解表达正确（缓解第 N 天/距上次发作）。
- G4 0 访谈、0 临床审核如实标注；阈值与频次类文案带来源版本或【待核】，以医生安排为准。
- G5 界面不替医生说话：紧急口径只呈现医生已确认原话，或空态引导去问医生。

## H. 回归与交付

- H1 检查链、单测、audit、探针的数字照抄进报告；SKIP 不计覆盖。
- H2 截图文件名含版本；README 五段结构（疾病概要/关键功能/怎么用/数据与口径/开发）齐全，装机截图另有标注。
- H3 修复建议逐条可执行；「谁补谁写进 CHANGELOG」。
- H4 输出格式：①一句话总评；②逐项表（编号/结论/证据截图或命令输出）；③失败与待人工清单；④修复建议排序（阻断 > 缺口 > 薄弱 > 打磨）；⑤回归数字汇总。报告不写「大体完成」。
