# 35 号 · 临床试验匹配契约（建档 → 检索 → 粗筛符合度 + 证据链）

> 来源：2026-10-25 匹配设计评审（用户确认）；**v2（同日）按用户指示以小胆宝 biliary-tract-workbench match-0.1.0 为参考实现修订**（`prototypes/v0.2/app.js` §临床试验 TRL-01~12）；**v3（2026-10-27）由小肺宝 0.1.2-rc.19 应用层回收**——用户对 G2 demo 的原话是「好多了，按照这个开发」「临床查询做的特别好」，落地形态见 §六、判据纪律见 §七。底座：unified-trial-mcp（M4 四件套）+ 25 号"无法自动匹配≠不适用"格式 + schema `saved_trial` 收藏。
> 一句话定位：工作台产出的是**带证据链的检索线索 + 语义诚实的粗筛符合度**，不是入组资格结论——判定归医生与研究中心。
> 参考实现（可直接对着改）：`lung-cancer-workbench/lib/client-trials.js` + `assets/trials.css`；原型 `docs/prototype/lung-workbench-v4.3.0.html`。

## 一、四段链路（与 34 号同风格：缺一段就是假功能）

| 段 | 谁 | 做法 |
| --- | --- | --- |
| 1 建档 | 业务页 | 基因/病理/IHC 走 `molecular_marker`/`pathology_type` 族表（状态只引用报告原文，无判读列）；**只有"已确认入库"字段参与匹配**，未核对候选不参与 |
| 2 检索 | dsh 读模型 | 双通道：本地快照（research/<病种>/ sqlite，随附 snapshotDate 与"快照会过期"提示）+ unified-trial-mcp 在线通道（statuses 逐来源透传；**FAILED/DENIED 不算"查过"、不计覆盖**） |
| 3 匹配 | dsh 读模型 | 分层规则（§二）+ 逐条证据链，输出三态结果（§三）；pct 只在展示层算，不入库、不写判读列 |
| 4 呈现/收藏 | 业务页 | 结果=候选线索：可收藏（saved_trial）、可拒收零副作用；AI 协助产出的匹配同走候选心智（落待核对不落事实） |

## 二、匹配指数与分层（参考实现：小胆宝 match-0.1.0，语义四规则）

**允许指数**：`粗筛符合度 pct = 符合项 ÷ 已对照项`（整数百分数，粗筛比例）。**四条硬语义**（缺一即违规）：

1. **待确认按 0 计**——未知项永远留"待确认"，不用阴性或符合去填；因此 pct **只会偏低、不会偏高**；
2. **四档分层**：**字段都对得上 / 部分对得上** / 需补充信息 / **硬性条件不满足（单列一组，不参与 pct 排序首位）**。
   v2 的原词「高度符合 / 部分符合」在小肺宝落地时被换掉——它们读起来像医学判断（「这个试验高度符合我」），
   而实际含义只是「登记字段对上了几项」。新词把限定词摆在最前面，检查器 T2b 两套词都认；新项目用新词。
3. **声明随附**：pct 旁固定写"这不是入组资格，也不代表效果"；
4. **偏好不参与计算**：城市/就诊便利等用户偏好只影响排序与"冲突提示"，不计入符合度。

**证据链（逐条必备，与 pct 同屏）**：每条入组/排除条件一行三态（✓符合 / ✕不符合 / ?待确认）+ 条件类别（诊断/分期/基因检测/器官功能…）+ 硬性标记 + "记录里是：…（带来源日期）· 条件要求：…"；未结构化的条件写"条目无法结构化，需人工核对"。先行展示不符合与待确认，其余折叠。

**登记事实纪律**：无核验日期的条目只显示「未核验」，不能显示「招募中」；演示条目一律合成登记号（DEMO- 前缀）并弹窗声明。

## 三、结果三态格式（沿用 25 号纪律，逐条必备）

1. **命中**（结构化/文本/宽口径）+ 命中证据；
2. **无法自动匹配**：本地无对应结构化字段的条件，逐条列出 + 原因（"本地未建档 ECOG 评分"）；
3. **不适用：不产出**——工作台永不写"你不适合/你能入组"；缺字段判"无法自动匹配"，不判"不适用"（25 号 L2-3）。

每条结果固定带：来源通道与终态（SUCCESS/FAILED 语义）、snapshotDate、"登记状态，未核实"、登记状态 ≠ 有效 ≠ 可入组 声明。

## 四、schema 与断言

- AI 不写"建议参加/适合你"；提示词只做"整理命中证据与待问医生的问题"。
- 在线通道查询失败如实展示（哪个来源 FAILED），不静默吞掉装作全域无匹配。
- 指南/登记库临床内容只引用原文片段作证据，不复制整段条件改写。

## 五、红线

- AI 不写『建议参加/适合你』；pct 不叫『适配度/入组概率』；提示词只做『整理命中证据与待问医生的问题』。
- 在线通道查询失败如实展示（哪个来源 FAILED），不静默吞掉装作全域无匹配。
- 登记库临床内容只引用原文片段作证据，不复制整段条件改写。
- 禁止 `eligible`/`suitability` 判读列；收藏只落 `saved_trial(trial_key, saved_at)`；pct 是展示层计算值，不入库为判定列。

## 六、界面形状（v3 新增；用户确认的那一版）

**三个子页，一次只回答一个问题。** 原来是一个页面里塞「检索框 + 结果表 + 弹窗」，检索条件和结果同屏，
用户分不清「我筛了什么」和「它给我推了什么」。

| 子页 | 回答的问题 | 内容 |
| --- | --- | --- |
| 匹配 | 「我这份档案，哪些登记能对上？」 | 档案字段网格 → 偏好（只影响排序）→ 候选池口径 → 匹配卡列表 |
| 检索 | 「我要找某个药 / 某个位点 / 某个编号」 | 关键词 + 病理 + 靶点 + 地区/状态/阶段，**按用户选的条件排，不掺分数** |
| 收藏与跟踪 | 「我留了哪些，各自到哪一步」 | 收藏日期 + 在跟 / 准备问 / 已归档 |

**匹配卡**一行三块：左侧分数方块（大号百分数，下方小字「登记字段符合度」）、中间标题与登记元信息
（NCT / 期别 / 状态 / 申办方 / 中心数）、右侧硬性条件标签。分数方块下固定一行 `n / m 项对得上 · k 项待确认`，
让用户一眼看出分母有多大——**只给百分数不给分母，等于让人误读**。

**详情是右侧浮窗，不是居中弹窗**（与 32 号同源判据：单条目详情不到 1.5 屏、且需要与列表并读）：

- 三个关闭口：遮罩 / 标题栏 ✕ / `Esc`。关掉后焦点回触发那张卡，**不改 hash、不产生导航栈条目**
  ——浮窗是同一页的旁注，不是「另一页」（与 32 号的整页视图分工不同，别混用）。
- 浮窗固定顺序：分数与声明 → 判据逐条三态 → 档案字段 → 登记字段 → 入排原文缺失声明 → 官方登记页出口。
- 快照里没有入排原文时，浮窗必须写「本机快照只存登记的结构化字段，入排标准请到官方登记页核对」。
  留白会被读成「已经判过了」。

**收藏**：只在本机存 `{ nctId, savedOn, state }`（`localStorage`），不进档案库、不新起表；三态是手工标记，
快照没有变更历史时明写「没有登记状态变化时间线」，不要画一条假的进度条。

## 七、落地五条（每条都对应一个已发生的错误，缺一条就会「分数骗人」）

1. **判据只能来自快照里真实存在的字段。** 小肺宝当时的快照只有 15 个结构化字段、**没有 `eligibilityModule`**，
   于是可对照的只有四类：病理类型 / 疾病范围 / 系统治疗记录 / 标志物。写代码前先
   `sqlite3 <快照> '.schema trials'` 数一遍字段；不要按「常识上应该能判」的清单写判据。
   快照没有的写「待确认」，并在文案里指向官方登记页。
2. **药物靶点不进分母。** 登记里的 `DLL3` / `B7-H3` / `PD-1` / `VEGF` 是「药打哪里」，不是「我查出什么」。
   把它当判据，所有靶向/ADC 试验会同时对所有人显示「符合」。靶点只在浮窗单列，注明「不等于你的检测条件」。
3. **可对照项不足 2 条不给百分数。** 只剩病理一条时 `1/1 = 100%`，读起来就是结论。守则：
   `crit.length < 2` 时整卡只给「需补充信息」，不给数字；**病理类型未确认时整页不排名**（不排名优于排错名）。
4. **反向条件必须显式反转，两侧词表必须同源。** 两个真 bug：① 登记写 `EGFR Wildtype` 时，阳性档案被判
   「位点对得上」——凡 `wildtype｜野生型｜未突变｜阴性` 语境，判据方向要反过来；② 档案侧写「晚期转移」、
   登记侧写「晚期/转移」，同一类永远落到「待确认」——比较用词必须来自同一份常量，不要在两侧各写一份中文。
5. **候选池口径写在卡头上。** 按病理类型取最近 50 条就是 50 条，卡头写「已载 50 / 469」并说明「不是全库扫描」。
   用户宁可知道只看了 50 条，也不能以为看完了 805 条。
