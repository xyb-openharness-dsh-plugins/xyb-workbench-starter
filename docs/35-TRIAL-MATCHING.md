# 35 号 · 临床试验匹配契约（建档 → 检索 → 分层线索）

> 来源：2026-10-25 匹配设计评审（用户确认）。底座：unified-trial-mcp（M4 四件套）+ 25 号"无法自动匹配≠不适用"格式 + schema `saved_trial` 收藏。
> 一句话定位：工作台产出的是**带证据链的检索线索**，不是入组资格结论——判定归医生与研究中心。

## 一、四段链路（与 34 号同风格：缺一段就是假功能）

| 段 | 谁 | 做法 |
| --- | --- | --- |
| 1 建档 | 业务页 | 基因/病理/IHC 走 `molecular_marker`/`pathology_type` 族表（状态只引用报告原文，无判读列）；**只有"已确认入库"字段参与匹配**，未核对候选不参与 |
| 2 检索 | dsh 读模型 | 双通道：本地快照（research/<病种>/ sqlite，随附 snapshotDate 与"快照会过期"提示）+ unified-trial-mcp 在线通道（statuses 逐来源透传；**FAILED/DENIED 不算"查过"、不计覆盖**） |
| 3 匹配 | dsh 读模型 | 分层规则（§二），输出三态结果（§三）；不产出数值适配度 |
| 4 呈现/收藏 | 业务页 | 结果=候选线索：可收藏（saved_trial）、可拒收零副作用；AI 协助产出的匹配同走候选心智（落待核对不落事实） |

## 二、分层规则（替代"匹配指数"：透明分层 + 证据链，防伪精度与判定暗示）

| 层 | 判据 | 界面要求 |
| --- | --- | --- |
| **结构化命中** | 建档结构化字段与登记条件中的明确实体重合（如 BRCA1 突变 ↔ 条件含 BRCA1 突变；HER2 阳性 ↔ 条件含 HER2） | 高亮**命中条件原文** + 建档值来源（哪份报告） |
| **文本命中** | 瘤种/药物/分期/机制关键词与登记文本重合 | 列出命中的词与出现位置（标题/条件/摘要） |
| **宽口径命中** | 仅宽口径词命中（如"实体瘤""罕见病"） | 显式标注"宽口径"，排结果末尾 |

禁止：数值化综合分（"匹配度 87%"）；把宽口径排到结构化命中前面；隐藏命中证据。

## 二.5 透明匹配分 + 匹配说明（v2，用户 2026-10-25 确认：匹配结果要「匹配分数 + 匹配说明」）

**允许加分数，但必须是「计分规则全透明的参考分」，且只存在于展示层（读模型/渲染时计算），不落库、不进 schema、不与收藏/筛选耦合。**

计分规则（固定、逐项明示，改动先改本表）：

| 维度 | 分值 | 依据 |
| --- | --- | --- |
| 瘤种一致（病种词命中） | +15 | 登记条件含本癌种词 |
| 结构化字段重合（分子/病理/IHC ↔ 登记条件实体） | 每项 +30，上限 60 | 建档值与条件实体重合，带证据链 |
| 文本命中（药物/分期/机制词） | 每项 +10，上限 20 | 关键词与登记文本重合，带出现位置 |
| 宽口径词命中 | +5（排结果末尾） | 仅宽口径词 |

- 分数旁**必须并列匹配说明**：逐条列出「+30：条件含 dMMR ↔ 建档 PMS2 缺失（IHC 报告 2026-06-10）」这类证据行；无说明的分数不得展示。
- 分数标签固定：**「匹配分 75（字段重合度参考分，非入组资格）」**——防止被读成适配度。
- 展示层计算（读模型渲染时算），**存储仍只落 `saved_trial(trial_key, saved_at)`，不新增 score 列**——计分规则升级时历史记录不受影响。
- 检查器（v2）：允许 `matchScore` 透明计分输出，但必须伴随 `matchNote` 逐条证据行；仍禁止 eligible/suitability 落库列与「综合分=资格」表述。

## 二.6 三步流程（基础 → 查询 → 匹配结果）

试验页按**三步**组织（一步一区块，同页纵向）：

1. **基础（简单）**：基础建档信息一览——病种/分期/分子三态，每项带来源；不看细节也能一眼交代"我是什么情况"。
2. **查询**：双通道检索终态表（本地快照 + 在线逐来源，含 FAILED 与快照日期）。
3. **匹配结果**：按匹配分降序的候选线索列表，每条 = 分数 + 逐条匹配说明 + 收藏/拒收；无法自动匹配的条件单列（不是"不适用"）。

## 三、结果三态格式（沿用 25 号纪律，逐条必备）

1. **命中**（结构化/文本/宽口径）+ 命中证据；
2. **无法自动匹配**：本地无对应结构化字段的条件，逐条列出 + 原因（"本地未建档 ECOG 评分"）；
3. **不适用：不产出**——工作台永不写"你不适合/你能入组"；缺字段判"无法自动匹配"，不判"不适用"（25 号 L2-3）。

每条结果固定带：来源通道与终态（SUCCESS/FAILED 语义）、snapshotDate、"登记状态，未核实"、登记状态 ≠ 有效 ≠ 可入组 声明。

## 四、schema 与断言

- 不新增判读列：禁止 `match_score`、`eligible`、`suitability` 类列；收藏只落 `saved_trial(trial_key, saved_at)`。
- `templates/check-trial-matching.mjs`（init 下发，进 check 链）：①读模型/路由出现匹配输出 ⇒ 必须含三态词（"无法自动匹配"）；②禁止 match_score/eligible 判读列或综合分字面量；③结果渲染必须含"未核实"与快照日期字样。

## 五、红线

- AI 不写"建议参加/适合你"；提示词只做"整理命中证据与待问医生的问题"。
- 在线通道查询失败如实展示（哪个来源 FAILED），不静默吞掉装作全域无匹配。
- 指南/登记库临床内容只引用原文片段作证据，不复制整段条件改写。
