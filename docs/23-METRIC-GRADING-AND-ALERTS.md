# 指标分析与卡片提醒原则

> 沉淀自小粉宝乳腺癌工作台 v0.7.0（2026-10-20 用户定则），v0.12.0（2026-10-22）按 ×ULN 扩项后修订 §2.1 与验收条目。适用于所有带"检验指标 + 身体感受"的工作台。
> 一句话：**指标卡要分组；有国际分级标准的指标直接用标准对照；提醒只并置"感受"与"指标"，不推断、不处置。**

---

## 0. 为什么要有这一份

指标页最容易犯两个错，两个都不报错、都"看起来正常"：

1. **平铺**：一张网格里混着肿瘤标志物、血常规、生化、体重、握力。用户读不出"这是血象还是标志物"，也看不出哪个值在标准里有客观界限。
2. **自己发明严重度**：把 0.8 的中性粒细胞写成"偏低/严重偏低"。这个"严重"没有出处，也没法追溯，等于工作台替医生下了判断。

第三条错更隐蔽：**把感受和指标混成一句话**——"你头晕是因为白细胞低"。这不是整理，这是因果推断。

三条对应三个原则，见 §1 / §2 / §4。

---

## 1. 原则 A：指标卡按类别分组

**规则**

- 指标卡一律分组渲染，组标题写类别名 + 项数；有分级的组额外标"N 项有 CTCAE 对照"。
- 组顺序取**单一来源**（如 `categoryOrder`），与一图秀左侧指标列表同一套次序，不允许两处各排各的。
- 没有记录的指标仍要列出（"没显示 ≠ 正常"），但不要为它编造分级。
- 分组是**渲染层**的事，不改数据层：`metricCards()` 返回扁平数组，分组由页面的一个函数做完（乳腺癌工作台是 `metricGroupsHTML()`），两个页面共用同一个函数。

**判据**：同一份数据下，指标检测页与一图秀的组名、组内顺序、项数完全一致。

**反例**：指标检测页按"重要程度"手工分组、一图秀按 `categoryOrder` 分组——两页对不上，用户以为是两套数据。

## 2. 原则 B：有国际分级标准，就直接用标准

**规则**

- 指标若有国际通行的不良事件分级标准（当前是 **CTCAE v5.0**，NCI/CTEP，2017-11-27），**直接用该标准的阈值做对照**，不自创"轻/中/重"、不写"偏高/偏低"。
- 标准里的条目分**两类**，处理方式不同，**不许用一套规则套两类**（见 §2.1）：
  - **绝对阈值型**：标准直接给数值界限（白细胞、中性粒细胞、血红蛋白、血小板、QTc）。
  - **×ULN 型**：标准给的是「正常上限的 N 倍」（ALT、AST、ALP、总胆红素、肌酐）。
- **×ULN 型必须用这张化验单自带的参考上限**，没有就明写「需参考上限」，**绝不拿成人通用上限凑倍数**。
- 阈值表是**代码里的唯一一份**（乳腺癌工作台：`dsh/ctcae.js`），单测逐个钉住边界；注释写明"以 `assets/reference/ctcae/` 的 PDF 为准，冲突时改代码"。

**已启用的四项（界值取自 CTCAE v5.0，越往下级越重）**

| 指标 | 术语 | 单位 | G1 | G2 | G3 | G4 |
|---|---|---|---|---|---|---|
| 白细胞 `wbc` | 白细胞减少 | 10⁹/L | <3.5–≥3.0 | <3.0–≥2.0 | <2.0–≥1.0 | <1.0 |
| 中性粒细胞绝对值 `anc` | 中性粒细胞减少 | 10⁹/L | <2.0–≥1.5 | <1.5–≥1.0 | <1.0–≥0.5 | <0.5 |
| 血红蛋白 `hgb` | 贫血 | g/L | <120–≥100 | <100–≥80 | <80 | 无数值界限 |
| 血小板 `plt` | 血小板减少 | 10⁹/L | <125–≥75 | <75–≥50 | <50–≥25 | <25 |

三条实现纪律：

1. **单位换算写在表里**：CTCAE 用 g/dL，国内化验单常用 g/L（1 g/dL = 10 g/L）。换算后的阈值必须写注释，不要让人现场心算。
2. **下限近似要标出来**：没有个人化验单的参考范围时用成人通用下限，返回结果带 `approx: true`，界面必须显示"按通用下限"。
3. **没有数值界限的级不给**：贫血 G4 的定义是"危及生命，需紧急处理"，没有数值门槛。本地最多给到 3 级，把"是不是到 G4"留给治疗团队——**少给一级，比给错一级好**。

**反例**：为了"看起来完整"，把贫血 G4 硬编成 `<65 g/L`。这个数字没有出处，且会让人以为过了界线才算严重。

### 2.1 ×ULN 型：必须用这张化验单的参考上限（2026-10-22 起，取代"不启用"）

v0.11 之前的口径是"×ULN 型不启用、也不近似"。这个结论**只对了一半**：不近似是对的，不启用是过度保守——只要化验单自带参考上限，这笔账本来就能算，而且标准原文写的就是 ×ULN。

**两类指标，两套处理，理由不同**

| 类型 | 例子 | 缺参考值时的做法 | 为什么 |
| --- | --- | --- | --- |
| 绝对阈值型（"降低"侧） | 白细胞、中性粒细胞、血小板 | 用**成人通用下限**近似，结果带 `approx: true`，界面写「按通用下限」 | 各实验室下限差异小（白细胞普遍 3.5–4.0），近似误差不改变级别 |
| ×ULN 型（"升高"侧） | ALT、AST、ALP、总胆红素、肌酐 | **返回 `needsUln`，不给级、不近似** | ALT 上限各实验室在 40–55 U/L 之间，差 1.4 倍；拿通用值一除，**2 级会被说成 1 级** |

一句话记法：**下限可以借，上限不能借。**

**实现要点**

1. 参考上限来自**本次记录**（`ref_high` 落库，随指标一起存），不是档案级配置——同一个人换医院、换仪器，上限就变了。
2. 缺上限时返回 `{ needsUln: true }`，**不是** `{ grade: null }`。前者是"算不了，要你补数据"，后者是"算了，在正常范围"。混用会让界面说不出话。
3. 有上限时，卡面同时给**级别 + 区间 + 实测倍数**：`对照 CTCAE v5.0 · 1 级 · >1.0–3.0 ×ULN · 实测 2.4×ULN`。倍数由服务端算，前端不做除法。
4. 边界钉的是**整除不等于越界**：ALT 上限 40、值 120 → `ratio = 3.0` → **1 级**；120.1 → 2 级。单测必须同时钉 120 与 120.1 两个点。
5. 阈值页码写进数据结构（ALT/AST/ALP P84、总胆红素 P85、肌酐 P86、QTc P87），改阈值时必须能回到原文那一页。

**QTc 这类绝对阈值型也有自己的坑**

- **最高只给到 3 级**：原文 G3 还含「较基线增加 >60 ms」、G4 是心律失常定义。本地既没有基线概念、也没有心电结构化数据，所以 `maxGrade: 3`，并在数据里写明"这两条未采用"。**未采用要写成注释，不是不做。**
- **单位不对就提示，不替用户换算**：值填 `0.46`（秒）返回 `needsUnit`，界面写"请按毫秒填写"。自动乘 1000 看着贴心，实际会让"填错单位"永远不被发现。

**界面必须能区分三种"没有级别"**

| 情形 | 返回 | 卡面 | 文案 |
| --- | --- | --- | --- |
| 值在正常范围 | `grade: null` | 无徽章 | 不写任何话，别画一个"正常"徽章 |
| 缺参考上限 | `needsUln` | **虚线徽章**「需参考上限」 | 「要按化验单的参考上限分级，但这条记录里没有上限」 |
| 单位不对 | `needsUnit` | 虚线徽章「单位待确认」 | 「请按毫秒填写」 |

**文案红线（这条写反过一次）**：状态由"缺失"推导出来时，**不能反过来说结果**。曾写「这 N 项**超标了**但缺参考上限」——`needsUln` 根本不看数值，不知道上限就无从判断超标。缺数据只能描述缺数据。

**分组要守住**：`ctcaeCoveredCodes()` 这类"某一页专供"的清单，**不要**为了加项去改它。骨髓抑制页的两列并置靠"只有血液学四项"这个前提，把 ALT、QTc 塞进去会把页面语义搞乱。另开 `ctcaeAllCodes()` / `ctcaeUlnCodes()` 给别处用。

## 3. 原则 C：分级是"对照"，不是诊断

这是产品边界，不是措辞偏好。分级只做一件事：**把记录值放进国际标准的客观区间**。

**固定写法（照抄）**

- 徽章：`对照 CTCAE v5.0 · 3 级`（版本号由读模型透传，前端不硬编码）
- 区间：`0.5–<1 10⁹/L`，近似时补 ` · 按通用下限`
- 免责：`对照不是诊断`

**禁用写法**

| 不写 | 因为 |
|---|---|
| 偏高 / 偏低 / 异常 | 没有出处，且暗示判断 |
| 轻 / 中 / 重度 | 自创分级，与标准对不上 |
| 需要处理 / 建议复查 | 处置建议，越界 |
| 白细胞低导致头晕 | 因果推断 |
| 骨髓抑制（单独作为结论） | 把两个观察压成一个诊断 |

**必须显示的来源**

卡片正面给级别，背面给区间 + 来源；指标分析页给一个可展开的对照说明块，含：标准版本、发布机构与日期、这一版能对照哪几项、为什么另外几项不启用、原文入口。

## 4. 原则 D：卡片提醒 = 表达面 + 指标面，两列并置

**规则**

- 一类"化疗后常见反应"（如骨髓抑制）在**表达上**是身体感受（头晕、疲乏），在**指标上**是血常规下降。提醒要把两侧**并排列出**，不合成一句话。
- 两侧都由**已记录的条目**构成，各自带日期与来源。
- 因果、处置、结论一律不写。收尾只写："只把已经记录的内容并列摆出，不推断因果，也不判断是否需要处理。"

**提醒何时成立（三态，必须实现）**

| 状态 | 条件 | 界面 |
|---|---|---|
| `paired` | 表达面与指标面**都**有记录 | 出现提醒条，两列并置 |
| `labsOnly` | 只有指标落到对照区间，没记相关感受 | **不弹提醒**；指标卡上的分级徽章照常显示（那是"对照"，不是"提醒"） |
| 只有感受 | 记了头晕/疲乏，没有对应指标 | **不生成**——不拿感受去猜指标 |

三态在**读模型**里算（乳腺癌工作台：`marrowSuppression()`），返回 `paired` / `labsOnly` 布尔值，前端只做开关。这样"提醒该不该出现"有单一答案，不会两个页面各判一次。

**文案骨架**

```
<场景>常见反应 · <名称>：你记录到的两侧
表达上是 A、B，指标上是 C、D。分级对照 CTCAE v<版本>（国际标准）的客观区间，
只是把记录值放进区间里——对照不是诊断，是否处理由治疗团队判断。

你记录的感受              | 记录里的血液学指标
A  强度 2/3  <日期>       | C  0.80 10⁹/L  对照 CTCAE v5.0 · 3 级  <日期> · <区间> · <来源>
B  强度 1/3  <日期>       | D  2.60 10⁹/L  对照 CTCAE v5.0 · 2 级  <日期> · <区间> · <来源>
```

场景词（"化疗后" / "治疗期间"）**按实际治疗记录决定**，不要一律写"化疗后"——没有化疗记录的用户看到这四个字会以为工作台认错了档案。

**反例**：提醒条写"骨髓抑制 3 级，建议尽快复查血常规"。三处越界：把两个观察合成一个诊断、给了处置、把对照当成了结论。

## 5. 标准原文的存放与引用

**存放**

```
assets/reference/<standard>/            # 唯一来源，随包分发（package.json files 含 assets）
  <官方文件名>.pdf
  README.md                             # 来源 URL、出版机构与日期、MD5、使用原则、代码对应
```

- 只放**一份**，不要在 `public/` 里复制一份给前端用。
- README 必须写清：下载地址、字节数、MD5、许可证/使用边界（"作为对照依据引用，不作为诊疗建议"）。

**引用**

- 服务端暴露一个只读接口（乳腺癌工作台：`GET /api/reference/ctcae`），文件名取自代码里的元信息常量，并校验解析后仍在目标目录内——**不能变成任意文件读**。
- 前端用普通链接打开（`a[target=_blank]`），不要内联 PDF 查看器（CSP 与移动端都不稳）。
- 元信息常量（版本/日期/机构/URL/本地路径/免责句）与 PDF 放在一起维护，界面文案从这里取，不另抄。

**换版**

1. 替换 `assets/reference/<standard>/` 下的 PDF 与 README（记新 MD5）；
2. 改元信息常量（版本、出版日期、本地路径）；
3. 改阈值表，并同步单测边界；
4. 升工作台 minor 版本，CHANGELOG 写"分级标准从 X 升到 Y，有以下阈值变化…"。

## 6. 分层位置（不要放错）

| 层 | 做什么 | 不做什么 |
|---|---|---|
| `assets/reference/` | 标准原文 + 来源说明 | 不放代码、不放开采数据 |
| 分级模块（纯函数） | 阈值表、单值 → 级别/区间/近似标记 | 不读写数据库、不判断处置 |
| 读模型 | 把级别挂到指标卡、算 `paired`/`labsOnly` | 不落库、不改历史记录 |
| 前端 | 徽章、区间、来源、免责、分组 | 不硬编码版本与阈值 |

分级结果是**派生值**，与臂围差、较前次变化同一类：**读取时算，不落库**。理由：标准会升版，落库等于把旧标准的判断固化成历史事实。

## 7. 验收清单

- [ ] **M1** 指标卡按类别分组，组顺序与一图秀同一来源；两页组名/顺序/项数一致。
- [ ] **M2** 无记录的指标仍列出，但不显示分级徽章。
- [ ] **M3** 绝对阈值型指标照标准给级；**×ULN 型指标只在记录自带参考上限时给级**，缺上限返回 `needsUln` 并显示「需参考上限」虚线徽章，**不出现用通用上限算出的级别**。
- [ ] **M3b** 有上限时卡面同时有级别、区间与实测倍数；倍数由服务端算，前端无反推。
- [ ] **M3c** 单位不符（如 QTc 填 0.46）返回 `needsUnit`，界面提示换单位，**不自动换算**。
- [ ] **M4** 阈值边界有单测：等号归上一级、跨级点逐个钉住（如 ANC 1.5 是 1 级、1.4 是 2 级；ALT 上限 40 时 120 是 1 级、120.1 是 2 级）。
- [ ] **M4b** 参考值落库时校验：非数字、上限小于下限报错；空值先挡 `null/undefined/''` 再转数字（`Number(null) === 0` 会让"没填上限"变成"上限是 0"）。
- [ ] **M4c** 未采用的原文分支（如 QTc 的「较基线 >60 ms」、G4 心律失常定义）在代码注释里写明"未采用"及原因。
- [ ] **M5** 徽章文案是"对照 CTCAE v<版本> · N 级"，没有"偏高/异常/轻中重"。
- [ ] **M6** 用了通用下限的地方显示"按通用下限"；没有数值界限的级不显示（贫血上限 3 级）。
- [ ] **M7** 提醒条只在 `paired` 时出现；`labsOnly` 时指标卡徽章仍在、提醒条不出现；只有感受时不生成。
- [ ] **M8** 提醒条两列并置、各带日期与来源，无因果句、无处置句；场景词按实际治疗记录决定。
- [ ] **M9** 指标分析页能打开标准原文，链接指向随包分发的 PDF（不是外链），且接口不可被用来读其他文件。
- [ ] **M10** 卡片背面（固定高度）在放上区间与免责后，页脚仍可见，没有内容被裁。
- [ ] **M11** 窄窗口（≤760px）下两列提醒自动堆叠，页面无横向溢出。

## 8. 家族落地差异

| 工作台 | 指标面 | 备注 |
|---|---|---|
| 乳腺癌 | 血液学四项（绝对阈值）+ ALT / AST / ALP / 总胆红素 / 肌酐（×ULN）+ QTc（绝对值到 3 级） | v0.12.0 起 22 项字典；×ULN 五项需化验单参考上限 |
| 结直肠癌 | 同上 | 化疗方案不同，关注点一致 |
| 胃癌 / 食管癌 | 同上 + 体重、白蛋白 | 体重与白蛋白**没有** CTCAE 绝对界限，不启用分级，只做趋势 |
| 卵巢癌 | 同上 + CA125 | 标志物不做分级（不是不良事件）；趋势只做记录呈现 |
| 宫颈癌 | 同上 + 放疗相关皮肤/肠道反应 | 皮肤反应按部位与面积分级，本地无面积测量，暂不启用 |
| FSHD（罕见病） | 无化疗 → 不适用 | 功能量表有分级体系但不是不良事件，另议 |

**共同底线**：不因为"这个病种也有化疗"就复制阈值表；阈值表放各仓一份并由单测钉住，避免一处升级另一处忘记。**×ULN 的参考上限也不许进家族常量**——它随每次化验变，是记录的一部分，不是家族参数。

## 9. 三条反例（都真实发生过）

1. **平铺网格**：16 项指标一张网格，用户以为"没显示的那几项就是正常"。→ 改分组 + 无记录也列出。
2. **背面被裁**：卡片高度固定 194px，加上区间与免责后，页脚被 `overflow:hidden` 吃掉。→ 把"方法变更断线"并进同一段提示，并压缩迷你折线高度；改完必须截图看页脚。
3. **基址拼重**：接口基址含 `/api`，前端又拼 `/api/xxx`，得到 `/api/api/state`，整页 404 但控制台只有一行 404。→ 契约固定：基址**不含** `/api`，独立启动为空串，并补一条回归测试。
