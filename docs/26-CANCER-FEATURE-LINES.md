# 功能线框架与跨癌种对比：先定「这条线回答患者的什么问题」

> 来源：2026-10-23 小肝宝（HCC）v0.1 → v0.2.0 的功能线补齐。用户当时的原话是「功能线少了太多了，对比下乳腺癌，比如营养，心理，病情指标分析」，随后要求把这份对比**抽象成框架放进脚手架**。
> 一句话：**工作台的功能线不是页面清单，而是"患者带着一个问题进来，页面必须能接住"的清单。** 页面数一样而问题接不住，等于没做。

---

## 0. 为什么需要这份文档

新癌种最容易犯的错不是"做错"，是**做少了还看不出来**：

- 一级导航 7 个，每个视图函数 18–52 行，一页把内容全铺完 → 看着挺满，实测每个二级场景都是空的；
- 结构上「看起来像工作台」，但患者真正会问的话没人接：*"我瘦了但体重没掉多少，算不算问题？" "我最近特别怕，能跟谁说？" "我儿子要不要查乙肝？"*

这类缺陷在走查时几乎抓不到（页面不报错、不溢出、截图也好看），只能靠**对比 + 提问**发现。

判据先给出来，后面全部围绕它展开：

> **一个功能线合格 = 能说清"它回答哪一句患者原话"，且这句话在本癌种里不是别的线能顺带回答的。**

---

## 1. 三层结构：线 → 页 → 卡

家族里所有工作台都按同一套三层组织，换癌种只换内容，不换骨架：

| 层 | 数量级 | 职责 | 变了会怎样 |
| --- | --- | --- | --- |
| **一级（功能线）** | 8–10 | 一条线 = 一类问题域，对应侧栏一个入口 | 少一条线 = 一整类问题没人接 |
| **二级（子页）** | 24–30 | 一条线内的分步：先看现状、再记、再看资源/导出 | 二级为 0 = 一页平铺，扫读靠滚动，等于没有结构 |
| **卡/块** | 视内容 | 二级页内的最小信息单元（指标卡、事件条、建议块） | — |

经验阈值（不是硬规范，是走查用的下限）：

- **一级 < 8 或二级 < 20 → 直接判定结构性不足**，不要先讨论视觉；
- **二级为 0 的一级线 ≥ 3 条 → 判定"平铺页"，必须拆**；
- 单条一级线内二级 > 6 → 大概率该拆线了（心理线允许 4，因为私密记录与资源页性质不同）。

## 2. 十条候选功能线（家族共通池）

下表是跨癌种提炼出来的候选池。**不是每个癌种都全上**，但每一条都要显式回答"上 / 不上 / 为什么"——沉默地漏掉是最常见的失误。

| # | 功能线 | 它回答的患者原话 | 家族共通度 | 癌种专属部分举例 |
| --- | --- | --- | --- | --- |
| L1 | **看板 / 首页** | "我现在整体什么情况？" | 必上 | 双轨并列（HCC 肝功能储备 × 肿瘤负荷）、复发风险线 |
| L2 | **疾病本体线** | "我这个病到底处在哪一步？" | 必上 | HCC 要拆成「肝」与「瘤」两条，因为两者不同源；乳腺是病理·分子档案 |
| L3 | **治疗与决策线** | "我做过什么、接下来还有什么路？" | 必上 | HCC 有「转化评估」这个独立决策节点；乳腺有术后上肢 |
| L4 | **指标分析线** | "这个数高了/低了要紧吗？比上次呢？" | 必上 | 阈值来源不同（CTCAE 绝对阈值 vs ×ULN 型）、标志物不做分级 |
| L5 | **安全与症状线** | "这个不舒服是不是治疗带来的？" | 必上 | HCC 的出血与脑病；乳腺的淋巴水肿 |
| L6 | **营养与体重线** | "我吃得下吗？掉了的体重要紧吗？" | 强烈建议 | HCC 的肌少症三联（体重+小腿围+握力）与限盐；胰腺的酶与消化 |
| L7 | **心理与家庭线** | "我很怕，能跟谁说？家里人要做什么？" | 强烈建议 | 家属早筛（HCC 的 HBV 筛查/疫苗）；遗传咨询（乳腺/卵巢） |
| L8 | **复诊与随访线** | "下次什么时候、带什么去？" | 必上 | 影像随访间隔；带瘤生存的复查节奏 |
| L9 | **资料与导出线** | "我能不能整理好拿去给医生看？" | 必上（M5 可延后解析） | 私密内容默认不导出；导出快照与「已过时」标记 |
| L10 | **试验与线索线** | "还有没有我能参加的研究？" | 按癌种 | 需真实登记库支撑，无库就不做入口 |

三条固定贯穿机制（不是功能线，是横切层）：

1. **指标分级层**：CTCAE v5.0 阈值表，只对有绝对阈值的项做分级（见 [23-METRIC-GRADING-AND-ALERTS](23-METRIC-GRADING-AND-ALERTS.md)）；
2. **一图秀 / 时间轴层**：多指标 + 事件同轴，独立归一化，单点不连线（见 [16-ONE-CHART-SPEC](16-ONE-CHART-SPEC.md)）；
3. **指南出处与节奏层**：四把刻度尺，处置推荐不进产品（见 [25-GUIDELINE-BRIDGE](25-GUIDELINE-BRIDGE.md)）。

## 3. 对比矩阵怎么用（走查表）

拿「成熟癌种（默认乳腺，v0.12.0，已装机）」当基准，逐行列本癌种。**对比的目的不是抄，是逼出"为什么不同"。**

| 维度 | 填什么 | 判定口径 |
| --- | --- | --- |
| 一级/二级数量 | `N 个一级 / M 个二级` | M < 20 → 结构性不足 |
| 该线是否有独立入口 | 有 / 合并进别处 / 无 | 「无」必须写理由，不能留空 |
| 二级拆法 | 现状 / 记录 / 资源 / 导出 四段中缺哪段 | 缺「记录」= 只读不可用；缺「导出」= 出不了门 |
| 本癌种特有的表达 | 一句具体的话或一个具体字段 | 写不出具体字段 = 这条线还没想清楚 |
| 私密与共享 | 哪些默认不进一图秀/摘要/导出 | 心理、家庭、生育等内容必须逐项标注 |
| 不可计算项 | 哪几个数看一眼就好，不做趋势/不做差值 | 标志物、症状评分常见 |
| 明确不做 | 与理由 | 写下来才算"决定过" |

### 3.1 示例：小肝宝 v0.1 的走查结论（真实记录）

| 维度 | 小粉宝 | 小肝宝 v0.1 | 判定 |
| --- | --- | --- | --- |
| 营养 | 独立一级 + 3 二级 | 「生活与家庭」里一张表（体重/小腿围/握力/食欲/限盐） | **严重不足**：HCC 的核心是肌少症 + 腹水限盐 + 味觉改变，一张表压不住 |
| 心理 | 独立一级 + 4 二级，私密区默认不外流 | **完全没有** | **缺失** |
| 指标分析 | 「指标检测」子页：分组卡 + 分级徽章 + 背面区间 + `needsUln` | 一图秀里两条折线（白蛋白、AFP） | **严重不足**：没有卡、没有分级、没有分组 |
| 二级结构 | 27 | 0 | **结构性缺陷** |
| 收藏与导出 | 问题清单可编辑、导出快照、源变标「已过时」 | 问题混在复诊页，无导出 | 不足 |
| 资料解析 | 文档导入 + 草稿核对 + MinerU | 无（属 M5） | 已知延后，不算缺口 |

结论写法示范：**不是"再加几个模块"，而是"补一层二级结构 + 四条独立功能线"。** 这句话决定了改动是重排而非追加。

## 4. 补齐时的三条纪律

### 4.1 不照抄基准癌种的命名与分组

HCC 最终是 9 个一级 / 27 个二级，和乳腺**数量接近、分组不同**，这是有意的：

| 一级 | 二级 | 为什么这样切 |
| --- | --- | --- |
| 我的肝 | 肝病背景 / 肝功能储备 / **门脉高压** | 门脉高压单独成页——它是**第三条独立风险线**，塞进「安全线」会被读成肿瘤并发症 |
| 我的瘤 | 肿瘤负荷 / 标志物 / 分期与可切除性 | 分期与可切除性放一起，因为两者都是"医生写下的话"，不是算出来的 |
| 治疗与转化 | 治疗历程 / **转化评估** / 方案与出处 | 转化是 HCC 独有的决策节点 |
| 指标分析 | 指标卡片 / 趋势对照 / 分级说明 | 分级用 CTCAE，×ULN 型必须靠那张化验单的参考上限 |
| 营养与体重 | 当下困扰 / 进食与体重 / 肌少症线索 | 三件 HCC 特有的事：肌少症、限盐、食欲味觉 |
| 心理与家庭 | 当下感受 / 我的记录 / 支持资源 / **家里的事与早筛** | 心理 + 家属合并，因为 HCC 的家庭维度主要就是 HBV 筛查与疫苗 |
| 复诊与回顾 | 复诊记录 / 待办与问题 / 试验线索 / 报告与导出 | 补「收藏与回顾」线 |

**判据**：任意两个癌种的工作台并排看，**一级名称一致率 > 70% 且二级顺序一致 → 说明没有认真做本癌种的场景调研**，只是换了标题。

### 4.2 每补一条线，必须同时补它对应的"接不住"场景

新增功能线不写场景，等于没有验收标准。小肝宝这次补了四条二级场景（S13–S16），格式固定：

```text
S13 血象低与乏力
患者原话：这次白细胞 2.8，人也没劲，是不是该停？
页面接住：指标分析 → 指标卡片（WBC 卡正面显示 2.8、较前次 ↓、CTCAE 2 级徽章、来源与日期）
         背面：为什么是 2 级、区间从哪来、这张单子的参考范围
不做什么：不说"要停药"，不给出就诊紧迫度；只给「数值 + 分级 + 上次值 + 何时复查」四件事
```

一段场景 = **患者原话 / 页面接住 / 明确不做什么**。第三项缺了，功能线一定会越界说结论。

### 4.3 私密内容必须是数据结构属性，不是界面开关

心理与家属线落地时，`viewpoint` 表加了 `visibility TEXT NOT NULL DEFAULT 'shared' CHECK (visibility IN ('shared','private'))`，而不是在前端做"隐藏"。

原因：私密内容一旦进了摘要、导出、一图秀，就无法回收。**默认值必须是 `shared`（不破坏既有数据），但写入口必须显式选择，且三处出口（一图秀 / 摘要 / 导出）各自过滤一遍**——过滤写在一个函数里，比写三处 `if` 可靠。

## 5. 家属线的通用设计：只加「提示」，不加「判定」

各癌种的家属线几乎都会被问同一句话：**要不要加早筛提醒？** 答案是加，但必须拆成两件不同的事：

| | （1）家庭内传播防护 | （2）高危人群随访提醒 |
| --- | --- | --- |
| 回答什么 | "家里人要查什么、打什么疫苗" | "隔多久查一次" |
| 数据 | 每位成员一行：感染状态（阳性/阴性/**未检测**/未知）、疫苗（完成/部分/未接种/未知）、日期 | 距上次检查的月数、参考间隔 |
| 输出 | 把"未检测""未接种"标成待办线索 | 只给客观间隔："距上次 8 个月，参考间隔 6 个月" |
| 禁止 | 不写"你应该去打疫苗"；不写隔离、不写传染风险分级 | 不写"你该去查了"；不出风险高低、不出概率、不做 LI-RADS/BI-RADS 式分级 |

三条硬约束：

1. **「未检测」≠「阴性」**，界面上必须是两种状态，不能合并成一个灰点；
2. 参考周期是**参考值**，实际由医生按个人情况定，界面明写；
3. 家属提醒与患者本人的复诊节奏**分表存放**，不互相推算。

## 6. 验收：怎么证明"功能线补齐了"

页面不报错、截图好看，都不能证明补齐。用这三组断言：

| 断言 | 做法 | 反例（会漏） |
| --- | --- | --- |
| **结构断言** | 断言一级数、二级数、每条一级下的二级 id 列表 | 只断言"侧栏有 9 项"，漏掉二级为空 |
| **场景断言** | 每条 S 场景都能定位到具体二级页 + 具体卡片，并断言卡片上的关键字段存在 | 只断言页面 200 |
| **巡检矩阵** | 27 个二级 × 3 个宽度（1440 / 1080 / 860）逐页跑无头：溢出、空页、控制台错误、坏请求 | 只跑一级页（实测能少抓 5–6 倍问题） |

实测口径参考（小肝宝 v0.2.0）：`{pages:81, overflow:[], emptyish:[], errors:[], bad4xx:[]}`；3D 指标卡专项：`count=15, h=276, perspective=1100px, transition=0.48s, backface=hidden, cols=2, 点击/键盘/换页持久化全通过`。

| L6 | 营养与体重 | | | | | | |

填完先自检三问：

1. 有哪条线是"另一个癌种的工作台原样搬过来、只改了标题"？→ 改内容或写清为什么通用；
2. 每条线的二级里，"记录"和"导出"这两段在不在？→ 缺一段就是只读摆设；
3. 有没有一条线回答不了任何一句患者原话？→ 删掉，别为了凑数。

## 8. 边界（写在最后，避免被当成规范）

- 本文给的是**候选池与判定口径**，不是"必须 9 个一级 / 27 个二级"。数量是走查下限，不是目标。
- 癌种专属判断（如"门脉高压要独立成线"）来自该癌种的临床结构，换病种必须重新论证，**不要照抄这条切法**。
- 家属早筛只做提示与客观间隔，不构成筛查建议；具体是否检查由医生按个人情况决定。
- 心理线不接真人咨询、不做危机分级；出现自伤念头直接提示联系当地急救或治疗团队。
