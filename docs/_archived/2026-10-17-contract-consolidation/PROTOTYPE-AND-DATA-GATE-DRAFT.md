# HTML原型先行与数据模型演进

2026-10-17补充。对新项目及尚未确认的业务范围生效，已有用户确认按版本和范围继承，不追溯否定已授权工作。

## 业务开发顺序

需求/场景与领域数据边界草案 → HTML交互工作台UI → 实际浏览器预览 → 用户确认版本/hash及功能范围 → 对应数据/API与业务UI开发 → 原型一致性和真实业务验收。

HTML可附本地CSS/JS，不以网络构建服务为打开前提。默认用明确标记的模拟数据；不读真实病历或携带凭据。不必在原型前冻结数据库，但应检查关键语义、来源和流程可恢复性。初始化接入骨架可保留，不当成业务开发或完成。

原型须让用户实际走通导航、二级任务、返回/取消、输入→结果→回顾；逐步补齐空/加载/失败重试、长内容弹窗、窄窗、大字、键盘和减少动效。确认可以按模块，但用户要求整体确认时遵循其范围。首页已确认不能推出所有二级页面已确认。

在UI-DESIGN/PARITY记录入口、版本/hash、预览环境/尺寸、实际操作、待验证项和确认原话/人/日期。静态截图、生成成功、自动检查、独立审查都不能替代用户确认。原型模拟保存不能声称写入正式业务库。未经确认不启动对应业务实现。

## 数据设计的四个边界

1. 稳定领域事实和关系：主体、资料、观察、业务事件、来源、revision、修订历史。
2. 工作流：定义版本、实例状态、待办、跳过/取消/重开、转换原因与时间；流程完成不自动成为业务事实。
3. 页面读模型：看板、详情、时间线、摘要由同源事实投影，接口版本明确；导航和布局不成为表名或所有权。
4. 偏好、缓存、快照：可重建与不可重写分别管理；快照引用输入版本，更正后可提示过时。

采用最小足够设计，不因“可扩展”强加通用工作流引擎、无限JSON或全量事件溯源。业务关键字段/关系保留校验，有限扩展有命名空间、类型和schemaVersion。

## 建库前变化走查

SCHEMA至少说明：改导航/重排/多视图时怎样不动事实；新增可选字段/指标时怎样读取旧记录；插入/跳过/重开/并行步骤时旧实例如何继续；来源更正/删除怎样传播到当前视图、缓存和历史快照；旧库/旧客户端怎样兼容、迁移、备份和恢复。区分未填/未知/不适用/零值，区分发生时间和录入时间。

每种变化写出“事实不变项、投影/配置/API变化、需要迁移的真实语义变化、可验证证据”。迁移递增且可追踪，不能删库兼容；回退应用版本不等于数据库能降级。先用代表性旧记录和关键任务验证，再冻结实施合同。
