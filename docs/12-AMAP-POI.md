# 可选能力：高德地图与 POI

适用于找地点、周边服务、门店/机构匹配、旅行规划等位置类工作台。按需接入，不是所有主题的必需依赖。本指南复用接入方法和故障经验，不携带任何项目Key，也不自动注册高德技能/MCP。

## 官方入口与版本

文档核对日期：2026-10-16。接口、授权、额度和产品能力变化时按当期官方文档调整；核对过文档不代表某个账号或Key已经获得调用权限。

## 1. 先选能力与地图方案

| 需求 | 可选能力 | 设计时明确 |
| --- | --- | --- |
| 名称/类别找地点 | 文本POI搜索 | 地域约束、分类码、分页、是否包含连锁分支 |
| 周边地点 | 周边POI搜索 | 中心点、服务允许的半径、排序、返回数量及覆盖范围 |
| 确认候选 | 按POI ID读取详情 | 名称、行政区、地址、坐标匹配；不能只按同名覆盖 |
| 地址定位 | 地理编码 | 结果可能是地址点，不一定是有稳定ID的业务POI |
| 底图、缩放与标记 | 高德JS API；或授权静态地图+独立交互库 | Key类型、坐标系、资源署名、性能及交互边界 |
| 路线/其它服务 | 相应官方API | 单独核验权限、参数和时效，不由POI成功推断它可用 |

本地后端代理Web服务可以把Web服务Key保存在本机，前端只访问工作台自己的鉴权接口；静态图方案需要自己实现视野刷新、叠点与缩放，不等同完整JS地图SDK。选择JS API时按其官方浏览器Key/安全配置接入，不能把Web服务Key或其配置方式直接套过去。

API和工具服务分开：业务页面可通过本机适配层稳定查询；Agent使用高德技能/MCP时，仅调用原生会话实际注册的工具，不把页面的Key写入提示词，也不因包里有技能说明就宣称工具已可用。

## 2. 申请与配置采用渐进披露

申请概要：登录开放平台→应用管理创建应用→添加Key，使用Web服务方案时选择“Web服务”→核对目标接口权限/额度→在工作台配置并检查连接。提供上面的官方申请和控制台链接，具体步骤折叠展示。

摘要常显“未配置/已配置/检查失败”，不要回显完整Key；详细申请步骤、输入和排查按需展开。配置保存成功与真实连接成功分开：配置检查只能说明凭据存在，一次地理编码成功也不能证明POI、静态图、路线等服务都有权限。

凭据由项目的后端配置层保存到专用本机位置或适用的宿主安全存储；避免进入Git、包、日志、URL截图、Agent prompt及导出文件。页面只能提交新值或读取配置状态；配置接口沿用宿主鉴权。参考项目采用受限权限文件与原子替换，新项目按平台核验，不硬编码个人路径。

## 3. 后端适配统一入口

推荐链路：业务页→工作台同源鉴权API→固定的高德端点→JSON/图像校验→业务候选读模型。由后端读取Key并加入请求；固定允许的操作/端点，不接受浏览器传入任意代理URL。

服务端校验关键词长度、地域、分类、坐标、分页、半径和ID数量。请求必须超时，取消/重试有上限；检查HTTP结果与高德业务状态及错误码。返回面向用户的可恢复错误，不把带Key的完整上游URL或原始异常栈回显到前端。

已核对的POI2.0端点示例：`/v5/place/text`、`/v5/place/around`、`/v5/place/detail`。v5搜索采用 `region`、`city_limit`、`page_size`、`page_num` 等当版参数；旧v3适配可能采用 `city`、`offset`、`page`，不要混传。可选详情字段通过当前版本支持的 `show_fields` 请求，不能把未返回字段补成事实。

缓存键包含操作、有效查询参数和配置代次；有大小/时效上限，换Key后失效。关键词输入防抖，地图移动后按需请求；等待中旧响应不得覆盖新查询。按服务条款确定数据保存/展示范围，不把有分页的搜索接口当可无限抓取的全国目录下载源。

## 4. POI归一化与业务匹配

可复制示例：[POI候选归一化函数](../examples/amap-poi-normalize.mjs)。它不联网、不读Key、不存库，只把原始记录转成安全可用的候选；真实调用和失败处理仍由项目适配层落实。

- 不假定字段始终是字符串：空数组、数字、对象、空字段都要校验，不能直接对 `typecode` 调用 `startsWith`。一条坏记录不能让整批展示失败；缺坐标可作为未定位候选，不伪造0,0。
- 使用 `provider + POI ID` 去重，业务实体与地点分支分开；同名机构、入口、停车场、旧址等不能仅凭名称合并。地理编码没有POI ID时，进入手工/Agent核实，不伪造供应商ID。
- 候选预览名称、行政区、详细地址和地图点位，支持按业务单选/多选/全选；用户确认后才保存或加入清单。类别、坐标与业务约束仍由后端验证。
- 供应商事实与用户资料分开。刷新地址/类别不覆盖收藏、私人笔记、去过状态或业务审批结果；来源与获取时间随候选保留。

## 5. 坐标、距离与范围不能含糊

数据模型保存经度、纬度与CRS；高德适配使用对应的高德坐标体系（GCJ-02），不要直接与WGS84点位混画。来源不明的坐标先标未知，必要转换明确输入输出CRS，不重复转换。Web服务的 `location` 为经度在前、纬度在后；Leaflet常用数组为纬度在前，适配时显式交换，禁止靠变量名猜。

地图连线只是站序时要明确说明，直线距离不称驾车距离。业务筛选半径与供应商单次搜索半径分别处理；本次核对的v5周边搜索上限为50,000米，因此“100km内”不能直接当作一次API请求保证完整覆盖。需要更大范围时比较地域搜索、合适的多边形/分区查询或合法本地目录方案，限制请求数量、按ID去重并按真实距离过滤；覆盖不全如实说明。

分页与条数上限同样影响覆盖；不能把第一页20条写成“全部地点”。显示来源、查询范围、已加载条数和必要的继续查询入口。

## 6. 地图失败时仍能完成地点业务

分层定位：接口/Key→POI返回→坐标→底图图像→标记与视野。点位正常而底图403不代表地点搜索坏了；不要通过轮换公共瓦片域名规避服务限制，使用有权使用的服务并保留署名/图面信息。

静态图响应需检查真实图像和MIME，高德可能返回错误JSON而非图片，HTTP200也不能直接当图像成功。视野请求防抖并带代次：新图加载成功后再替换旧图，迟到结果丢弃，卸载清理监听、计时器与图层。地图/网络失败时保留列表、收藏、编辑和已有结果，不展示假的底图。

## 7. POI信息遵守通用可信度原则

POI存在、地址匹配、分类、常规营业时间和当前真实营业/服务状态是不同主张；返回详情不等于每项已核实。评分只标注实际供应商和已知尺度，不冒充其它点评平台。价格、服务资格、临时停业或预约等按业务需要另取权威来源，未知明确留白。

保留来源、获取/核实时间、有效条件及冲突状态，用户采纳不等于完成外部事实核验；同样适用于任何类型的地点。完整原则见[外部信息可信度](05-AGENT-AND-RESOURCES.md)。

## 8. 最小检查与复用边界

| 检查 | 预期 |
| --- | --- |
| 无Key/无权限/额度或网络错误 | 说明具体失败阶段、可恢复；本地业务仍可用，错误不误记为空结果 |
| 真实连接 | 对实际采用的POI/地图等能力各做一次必要检查，记录日期；不把一次调用当所有权限已验证 |
| 空数组/数字typecode、缺ID/坐标、同名分支 | 不整批崩溃、不伪造坐标或ID、不错误合并 |
| 坐标/半径/分页 | 不偏移；查询范围与覆盖描述一致；直线与路线距离分清 |
| 换Key、快速查询/移动、卸载 | 缓存失效，旧响应不盖新状态，监听和请求可清理 |
| UI与结果闭环 | 配置说明可展开；搜索→详情→勾选确认→业务保存/Agent核实→回顾可完成 |
| 包与公开产物 | 没有真实Key；示例不带个人配置，也不假定Agent已具备高德工具 |

复用本指南、归一化示例和已有检查记录；只对新项目实际启用的能力补验。脚手架不向所有工作台自动安装地图SDK或添加联网依赖。
