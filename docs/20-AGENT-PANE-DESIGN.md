# Agent 对话面板集成设计（工作台通用模板）

配套提示词：[prompts/DSH-AGENT-PANE-INTEGRATION.md](../prompts/DSH-AGENT-PANE-INTEGRATION.md)。提示词定义**合同**（交互该长什么样），本文档是**落地模板**（该项目怎么落地、哪些条目适用、哪些偏离及理由）。按提示词自身闸口：**先写本设计文档、展示集成状态与未决差异，用户确认后才写业务代码**。示例中出现的乳腺癌工作台细节只是举例，换成任何工作台按同样结构填写。

| 顶栏入口 | 现有按钮清单 | 「AI 对话 / 正在连接… / 收起 AI 对话 / 打开 AI 对话 / AI 对话暂不可用」+ 独立「×」收起控件 |

新项目若要「可拖宽 + 可收起」，可直接照抄乳腺癌工作台 `src/client.js` 的四个部分：顶栏五态按钮、`role="separator"` 的 splitter（含 `aria-valuenow`）、指针拖动按**容器 rect** 夹取、以及**会话恒定挂载只切 display**（卸载会丢输入框与草稿，宿主明确要求不重挂输入树）。宽度区间常量放项目自己的 `lib/layout.js`，由构建注入客户端，别在客户端里写第二份。

### 顶栏结构与视觉（2026-10-19 定稿，细节见提示词）

三段式，职责不许混：**左 = 品牌 + `vX.Y.Z` chip；中 = 一句状态说明（`flex:1`，弱化）；右 = 主操作按钮组（`margin-left:auto` 紧贴右缘）**。

- 左缘是 macOS 窗口按钮区（`--dsh-frame-leading-clearance`），所以**按钮不能放左边**；版本号放这里而不是只藏在业务 iframe 内的右上角——用户找不到。
- 版本号必须由构建注入且与业务页同源；chip 用中性灰，不跟品牌主色（它是元信息）。
- 整条色带必须克制：背景用中性浅灰或品牌色极浅一档，主按钮是**全屏唯一强色块**。乳腺癌真机上被否掉的版本就是"明显粉底 + 饱和按钮"，业务区反而退到后面。
- 五态文案固定：`AI 对话 / 正在连接… / 收起 AI 对话 / 打开 AI 对话 / AI 对话暂不可用`；「×」必须有 `aria-label`。

完整尺寸表、色值角色表、换色规则、反例与验收清单见 **[prompts/DSH-WORKBENCH-TOP-BAR.md](../prompts/DSH-WORKBENCH-TOP-BAR.md)**。

## 2. 版式判定：分两种形态，先判断再套基线

> **2026-10-19 实证修正（重要，先读这一条）**：如果需求里包含「面板可拖动调宽」或「可收起/重开」，**split 形态做不到**，只能选 customFrame。源码依据（`dsh-desktop` `@xyb-dsh-workbench` 分支 v0.11.1，`packages/dsh-desktop-workbenches/client.js`）：
>
> 1. split 下宿主把业务宽度写成**注册时的静态值**，之后不再变：
>    `h('div',{className:'dshWbBody',hidden:customFrame,style:{'--workbench-business-width':`${entry?.layout?.businessWidth ?? 0.36)*100}%`}})`
> 2. 服务（`ctx.reflect.provide('desktopWorkbenches', service)`）只暴露
>    `register / isActive / ownsSession / add / open / home / setMarketOpen / showMarket / ensureSession / currentSession / subscribe`
>    ——**没有** `setBusinessWidth`、`togglePane`，DOM 里也不存在 splitter 节点。
> 3. customFrame 下宿主走另一条分支（同文件约 2000 行）：
>    `h(item.Component, { service, entry, active, conversation: <原生会话挂载点> })`
>    原生会话节点作为 **`conversation` prop 交给插件排版**，于是拖动、键盘调整、收起/重开、宽度记忆都由工作台自己实现。
>
> 因此下方表格里 split 那一列只适用于**用户不要求拖宽/收起**的项目；一旦提出「面板可调」，必须改 customFrame，别再写「用宿主原生面板自带能力」这种无法兑现的承诺（乳腺癌工作台 2026-10-18 犯过这个错，10-19 已改）。

提示词的「Agent 展开默认 35%、可拖 25%–45%」是 **CustomFrame 形态**的基线。工作台若是 split 合同（`businessSide` / `businessWidth`），适用方式不同：

| 提示词条目 | CustomFrame 工作台 | split 工作台（示例判定） |
| --- | --- | --- |
| Agent 展开宽度 35%，可拖 25%–45% | 直接适用 | **不适用**（且**无法**实现拖动/收起：宿主无接口，见上方实证）。原生会话节点由宿主渲染，在业务区**对侧**，宽度随宿主分栏合同；工作台代码里不出现第二份宽度来源。会话栏挤压业务区时，只能调 `businessWidth`（宿主允许 0.25–0.7），且**改完要重装/重启才生效** |
| 双状态稿（主区 + Agent 栏） | 主区 + 右栏 | **形态改为「业务区 + 对侧原生会话占位」**，覆盖的状态不变：默认关/开、会话栏窄/宽、加载/失败、草稿冲突 |
| 顶栏 620–760px 换行、<620 折叠导航 | 归 CustomFrame 布局 | 归宿主 split 布局与业务区响应式共同承担；**业务区断点一律按业务容器宽度算，不按整窗** |

> 提示词允许「项目 SPEC 决定默认值」与「明确确认后偏离」——偏离必须写成表格逐条给理由，不许静默改。

### 2.1 默认位置：会话在右、业务在左（家族统一，不许各仓自定）

**结论**：`businessSide: 'left'`（业务区占左），原生会话面板在最右。乳腺癌工作台 v0.5.x 曾用 `right`，v0.6.0 按用户明确要求改回 `left`——"原生会话面板在最右"是用户定过的，不是实现偏好。

三条理由：

1. **业务区是主体**。患者 90% 的时间在读数、看曲线、填记录；会话是间歇使用。左起阅读流先看到主体，符合"业务区不许退到后面"的既有要求。
2. **右缘是全家族的"操作终点"**。顶栏主按钮、收起「×」都在右缘；会话面板在同一侧，视线不用来回跳。
3. **互补关系能钉死**。`businessWidth + AGENT_PANE.default = 1`（0.65 + 0.35），一条 `assertPanelConfig()` 就能挡住"改了一个忘另一个"。

硬约束：

- 默认值**只有一份**：`lib/layout.js` 的 `PANEL` 与 `AGENT_PANE`，由构建注入客户端；客户端里不许再写 `0.65` / `0.35`。
- customFrame 下宿主不再用这两个值驱动分栏，但 **register 时宿主仍会校验**（`businessSide ∈ left|right`，`businessWidth ∈ 0.25–0.7`，越界直接抛错）。所以照样要传合法值，不能因为"反正不用"就填 0 或省略。
- 不许出现两个宽度来源：自建 splitter 之后，**宿主的 `businessWidth` 只作为注册元信息**，真实宽度由 `AGENT_PANE` 反推；两者不一致会让"首屏布局"和"拖完的布局"对不上。
- 已知代价（照实写进项目文档）：业务区宽度不再由宿主分栏决定，需要自己复测各断点的横向溢出（乳腺癌实测 1040 / 900 / 800 / 700 四档溢出 0）。

### 2.2 可拖动：四条硬约束，缺一条就不是"可拖"

| # | 约束 | 写错的后果 |
| --- | --- | --- |
| 1 | 拖动量按**容器 rect** 夹取，不按 `window.innerWidth` | 窗口有侧栏/窗口按钮避让时，比例换算整体偏移，拖到边界会卡住或跳一格 |
| 2 | `role="separator"` + `aria-valuemin/max/now` + `tabindex="0"` | 键盘用户无法调整；读屏软件读不出当前宽度 |
| 3 | 键盘 `←/→` 步进与拖动同精度（如 2%），`Home/End` 到边界 | 键盘和鼠标得到两套取值，用户复现不了别人的宽度 |
| 4 | 宽度写 localStorage，读回时**过一遍 `clampAgentWidth()`** | 手改过 localStorage 或旧版本存了越界值，打开就是坏布局 |

补充：窄容器（< 760px）改**覆盖式抽屉**（≤420px），业务区不让位，splitter 在该形态下**不出现**（而不是隐藏一个还能 Tab 到的节点）。

### 2.3 顶栏开关是唯一入口，收起不等于结束会话

- 打开/收起的入口**只在顶栏**（五态按钮 + 独立「×」）。面板内部不再放第二组开合控件——两处都能关，用户会以为关的是两件不同的事。
- 收起只切 `paneOpen` 与 `display`，**不调用任何 close / delete 接口**；再点「打开 AI 对话」回到同一会话，输入框草稿还在。
- 原生会话节点**恒定挂载**：宿主明确要求不重挂输入树，卸载会丢输入框与草稿。
- 无会话时按钮是「AI 对话」（点击 `ensureSession`），**不是禁用**；业务区在不依赖会话的情况下必须照常可用。
- 服务缺失才禁用，文案「AI 对话暂不可用」，并在说明里写降级原因（不许自建聊天框兜底）。

## 3. 交互合同逐条落地（每条都填「本项目怎么做」）

1. **入口**：顶栏按钮（图标 + 文字 + 可访问名称），状态四态：`未打开 / 正在连接 / 已连接·会话名 / 暂不可用`。独立收起控件；隐藏 ≠ 结束会话。split 模式下按钮控制的是「业务区是否请求宿主显示会话节点」，状态来自宿主回执，**不由工作台自证**。
2. **会话创建**：首次显式点击才创建/复用；不静默新建；并发与慢返回不重复创建；所有权未知不发送。会话归属用 `owner/repo` 身份，repository 改名影响归属——发布后不改仓库地址。
3. **上下文衔接（工作台差异化的重点）**：从来源页提供「与 Agent 讨论」，生成**可预览草稿**（标来源/时间/核对状态/缺项）。来源页按性质分四类填：
   - **序列类**（指标图）：带序列 + 可比性说明（换方法断线等）；
   - **清单类**（问题/待办）：已是用户确认项，可直接引用；
   - **核对类**（导入候选）：**只带已接受的事实，未核对候选禁止进草稿**——候选进草稿等于替 AI 背书未核实数据；
   - **关注类**：空态时不提供入口。
4. **带入对话**：草稿填入**原生会话输入框**。⚠️ split + iframe 形态下向宿主输入框写草稿**需要宿主 API**——合同未给方法名时**不猜名调用**；拿不到就做「复制到剪贴板」回退，**绝不自建聊天框**。
5. **草稿冲突**：原生输入框已有内容时，提供复制/追加/取消三选，保留用户已有输入。
6. **AI 输出边界**：AI 回复只在原生界面展示；不写回事实/记录表；工作台已有的「看法不是结论」「接受 ≠ 审核」等合同不因 AI 改变。
7. **私密边界**：工作台若有私密数据（默认不进导出/摘要的那类），**默认不进上下文草稿**，逐项显式勾选才带；带私密项的草稿预览中标红「将发送到宿主会话」。

## 4. 数据模型解耦

| 数据 | 归属 | 存储原则 |
| --- | --- | --- |
| 面板展开/宽度等展示偏好 | 工作台 UI | `workspace.settings_json` 等既有机制，清数据即清偏好 |
| 会话归属 / 会话 ID | 宿主绑定 | 不落库；不作为患者病情事实 |
| 一次性上下文草稿 | 会话期 | 默认不持久化完整草稿；只存「最近一次带入摘要」供撤回提示 |
| AI 产生的一切内容 | 原生会话 | 工作台零持久化 |

## 5. 验收清单（按项目改写，但七条骨架不删）

- [ ] 全局顶栏有可见的「AI 对话/打开 AI 对话」入口；入口文案与未打开、连接中、已连接、暂不可用状态匹配宿主真实回执。
- [ ] 可独立隐藏并重开同一个原生会话；隐藏不结束会话，不丢工作台状态或原生草稿。
- [ ] 面板宽度可按当前宿主形态调整。CustomFrame 测鼠标/触控/键盘 splitter；split 只测 Desktop 支持的布局控制，不在业务组件复制宽度来源。
- [ ] 业务区仍是主体：宿主分栏下页面级横向溢出复测为 0（沿用既有实测口径）。
- [ ] 入口四态可观察；隐藏/重开不丢工作台状态（筛选、草稿、滚动位置）。
- [ ] 首次点击至多创建一个正确归属的会话；重复点击/慢返回不重复创建。
- [ ] 各来源页草稿预览含来源/时间/核对状态/缺项；未核对候选不出现。
- [ ] 私密项默认不在草稿；显式勾选后有发送前红色提示。
- [ ] 宿主 API 缺位时走剪贴板回退，无假成功；无权限/版本不兼容可继续用工作台。
- [ ] **V2 实机**：在目标 Desktop RC 里真实渲染原生会话、可输入、可回复；静态 DOM 与开发自测不算验收。
