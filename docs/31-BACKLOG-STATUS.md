# 31 · 回填组织 BACKLOG 状态（M8：发布之后的最后一格）

工作台发布完不等于"社区知道它能用了"。目标池的唯一权威位置是组织的
[`BACKLOG.md`](https://github.com/xyb-openharness-dsh-plugins/.github/blob/main/BACKLOG.md)，
不把自己的进度写回去，外部贡献者看到的还是"未开工"，招募与协作就停在原地。

本文只讲**怎么改那一行**，不讲项目怎么开发。病种无关，所有工作台通用。

## 1. 什么时候做

| 时点 | 动作 |
| --- | --- |
| G1 通过、认领落定 | 维护者把 ⬜ 改成 ⚪/🟡，写上认领人、角色、日期 |
| **M6 装机三层验收通过** | **本仓库侧执行 M8**：把状态推进到 🔵 并带上版本号 |
| 用户在真机确认 V2（Desktop 真加载）+ V3（业务闭环） | 才可推进到 🟢，同时同步 `ROADMAP.md` |
| 版本继续迭代（🔵 期间） | 只更新版本号与日期，不换 emoji |

**M8 不阻塞发布**，但它属于"发布这一轮"的收尾；漏掉不会报错，只会让外部一直以为没开工。

## 2. 状态词表（不许自造）

| 标记 | 含义 | 判据 |
| --- | --- | --- |
| ⬜ | 未启动 · 招募认领中 | 没人认领 |
| ⚪ | 规划中 | 已排波次，未启动 |
| 🟡 | 设计中 | G1 已签、G2 未签 |
| 🔵 | 开发中 | 闸口已签，实现在跑（含"装机过、真机未确认"） |
| 🟢 | 社区可用 | **V1 + V2 + V3 三层全过** |
| — | 观察池 / 团队在编 | 不对外开放认领 |

三条硬规则：

1. **"PR 已合并"≠ 可用**。只有 V1（`npm run check` + `audit`）、V2（Desktop 正确 profile 真加载）、V3（实机核心业务闭环）都过才 🟢。
2. **单向推进**：⬜→⚪→🟡→🔵→🟢。回退必须在该行备注原因，不静默改。
3. **状态列必须带版本号与日期**（`🔵 v0.2.3（2026-10-24 装机三层验收）`）。只写 emoji 等于没写，三天后没人知道它对应哪一版。

## 3. 改哪一列

以 ATTR 的一行为例（`BACKLOG.md` §2.2 第 80 行）：

```
| 80 | 转甲状腺素蛋白淀粉样变性 | 478 | T1 | 🟡 v0.1.0（2026-10-21 认领） | 已认领 · 👤🩺📝 补位 |
```

- **只改第 5、6 列**（状态、招募对象）；
- 序号 `80`、病种名、指南页码 `478`、级别 `T1` **一律不动**——它们是目标池口径，不是进度；
- 招募列跟着状态走：🔵 阶段通常从"👤🩺📝 补位"收窄到"📝🩺 内容补位"（开发不再缺人，缺的是医学核对与内容）。

## 4. 交付判据

1. **走 PR，不直推 `main`**（`.github` 是公开仓库，改动要留痕可回溯）。
2. PR 描述必须写清：仓库名、版本、V1/V2/V3 各自的证据（命令 + 输出摘要）；**没跑过的写"未验证"**，不许一句"已完成"。
3. 合并后回项目 `docs/RELEASE.md` 的「动作」表补一行：PR URL + 合并时间 + 最终状态标记。
4. 达到 🟢 才同步 `ROADMAP.md`。**未达 🟢 不许说"已上架 / 已可用 / 社区可用"。**

## 5. 常见错误

| 错误 | 后果 | 正确做法 |
| --- | --- | --- |
| 装上了就标 🟢 | 外部按"可用"去用，撞上白屏/数据不落盘，信任一次就没了 | 🟢 只认 V2 真加载 + V3 业务闭环 |
| 状态列只写 emoji | 无法追溯对应版本，回退时不知道回到哪 | 一律 `标记 vX.Y.Z（日期 + 一句依据）` |
| 顺手把序号/级别/页码也改了 | 目标池口径漂移，总量统计对不上 | 只碰第 5、6 列 |
| 在 Issue 里说"已更新"但没提 PR | 表里没变，等于没做 | 以合并进 `main` 为准 |
| 仓库 private 导致链接 404 就去改可见性 | 病种仓一律 private 是组织决定，404 属预期 | 保持 private，在 PR 里说明"外部访客 404 属预期" |
