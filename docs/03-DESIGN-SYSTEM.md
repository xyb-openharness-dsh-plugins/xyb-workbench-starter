# 社区界面、动效与技能使用

## 品牌与信息优先级

保留社区温和、清晰、易读的视觉：薄荷绿组织信息，橙色用于一个区域的主要行动，浅粉/浅蓝/暖黄作为低强度分区。正文先满足可读性，不把“小字、低对比、挤很多卡片”当高级感。宿主区域沿用宿主主题；业务主题采用语义 token，深色模式需适配或明确当前限制，不全局强刷白底。

品牌素材见 assets；Logo 保持比例、留透明背景、不要裁头/变形。每页重要位置最多 1–3 处花朵，放标题前并留 8–12px；普通问候段不放。五色花约 12 秒一圈、七色花约 15 秒，装饰 aria-hidden，不表达医疗风险。reduce motion 时停旋转/光晕/翻转，保留可直接切换的交互。

社区默认参考：系统字体，正文 16px/1.65、辅助 13–14px、标题 27–30px，数字 tabular-nums；大字模式整体提高可读性，不只放大标题。按钮至少 44px 操作区。橙色亮底配深色文字，或更深橙底白字，实际计算对比度，不假设橙底白字总达标。卡片圆角 14–20px；组间 24px，组内 12–16px。具体值以已确认原型为准。

首页顺序按任务时效组织：当前/未来待办与计划→变化摘要→维度概览→记录入口；维度数量由业务决定。变化与提示分列，事实/来源/缺失一眼分清；支持语气不做诊断、疗效保证或恐吓。

## 必须先有功能树

有目录持久化与 Agent 协作的工作台，在顶部共用[目录/会话双状态](09-WORKBENCH-STATUS.md)。状态文字配静态圆点；布局和恢复入口统一，不在多个页面复制配置操作或用含糊的保存文案代替状态。

页面树包含所有一级与二级页、折叠内容、配置弹窗。矩阵记录正面/翻面、加载/空/错误、选中/展开、返回路径和结果去向。以高精度原型为合同，技能不能凭美学重新删减功能。

## 渐进披露：辅助信息可找到，主任务始终清楚

**主任务常显，辅助信息按需展开。** 先按用户完成任务所需的信息分类，再决定默认可见性，不通过删功能或缩小字号换整洁。

| 信息层级 | 默认呈现 | 规则 |
| --- | --- | --- |
| 本步输入、主要动作、结果、关键状态 | 常显 | 首屏能辨认当前任务与下一步；主行动有清楚焦点 |
| 低频配置、服务申请步骤、详细参数、来源解释 | 折叠区域 | 标题可发现，摘要显示未配置/已配置/异常；需要时展开，避免每个页面重复 |
| 首次使用说明、流程教学 | 💡帮助浮层 | 点击或键盘打开；保留可识别名称，不只靠悬停；主路径CTA仍在页面上 |
| 次要记录、长列表细节、历史版本管理 | 摘要+展开/更多 | 摘要保留判断所需字段；操作对象明确，不与主行动争抢注意 |
| 阻断错误、必要确认、会改变用户决定的重要提醒 | 直接可见 | 不隐藏在折叠项或帮助里；同时提供定位/展开对应设置的入口 |

配置摘要与内容共用同一状态源。比如任何第三方服务的申请指南默认折叠，摘要显示是否已配置；不要只折叠说明却继续常驻一大块空配置表。💡教学用于补充解释，不能成为唯一的下一步指引。关闭和重新打开不丢输入；切换主体时避免沿用其它主体的展开内容或未保存表单。

优先使用原生 `details/summary` 实现简单折叠；自定义弹层再处理焦点、关闭、层级和较窄面板。无需持续动画；读屏名称清楚，操作区满足触控尺寸。示例见 [渐进披露组件](../examples/progressive-disclosure.html)，主题与业务可自行替换。

UI检查至少问：用户能否立即找到主任务？辅助内容是否能找到并展开？错误是否无需展开就能发现？窄面板/大字是否仍可读？隐藏内容是否仍在功能清单内、没有被实现时删除？

## 长内容弹窗：内容动，标头不动

用户应始终知道“正在操作什么”，并且随时能退出。适用于选择列表、详情、配置弹窗、抽屉等有边界的浮层，不要求普通业务页面全部吸顶。

- 外壳限制在当前可视区域内，使用三段结构：标题/关闭区、可滚动内容区、按需固定的操作区。标题过长可换行，关闭按钮不被挤走。
- 仅中间内容区滚动；布局采用 flex/grid，内容区设 `min-height: 0; overflow-y: auto`，外壳 `overflow: hidden`，高度考虑 `dvh` 与上下留白。不要让整个弹窗滚动，也不要产生页面、弹窗、列表三重滚动。
- 多选模式、全选、已选数量等高频列表工具保留在内容区上方；提交/下一步按需固定到底部，保持表单关联。短弹窗自然高度，不强撑满屏。
- 固定区域使用不透明主题背景与轻分隔，内容不能透过标题。保留足够内容高度，避免大标题、工具栏挤没列表。
- 原生 `dialog.showModal()` 或等价实现负责模态与焦点约束；打开后焦点可见，Escape/关闭可用，关闭后回到触发按钮。背景不随列表滚动；较窄窗口、大字、键盘 Tab 和区域滚动均需检查。

验收：用超过一屏的真实布局列表，分别滚到中段/底部，标题和关闭位置不变、底部主操作可见、勾选不丢失、提交仍有效；从底部直接关闭。记录宽/窄窗口与大字结果，不能仅用 CSS 字符串断言代替实际渲染。

## 技能如何选

| 时机 | 建议能力 | 交付与限制 |
| --- | --- | --- |
| 新页面/风格明确但未设计 | frontend-design 或同类 UI/UX 技能，选一个主设计者 | token、布局草图、信息层级、可交互原型 |
| 原型已确认，移植正式 UI | image-to-code / 现有工程开发能力 | 功能树→组件映射；不重新发明布局 |
| 可读性/实际效果有问题 | debug-ui / UX 审查 / 浏览器截图 | 在容器宽度、大字、reduce motion 下看真实效果 |
| 包/数据/Agent 集成 | 工程开发/调试技能 | 不以视觉技能代替 API 与持久化 |

技能是可选加速器，不是运行依赖。使用前读 SKILL.md，说明采用什么；与用户/官方约束冲突时按上级约束。没有技能也按本文件执行。不要把已安装技能目录、个人绝对路径或第三方技能代码直接复制进新项目。

## 折线图与翻面合同

- 同一指标最多最近五次，按时间排序；单位不一致不直接连线，缺少两次记录显示原因。
- SVG 参考 `viewBox="0 0 320 62"`，`preserveAspectRatio="xMinYMid meet"`，宽度封顶 320px，高 62px；日期放 SVG 外普通文字，点和线用 non-scaling-stroke。不要用 preserveAspectRatio=none 拉伸坐标/文字。
- 固定视窗只保证几何不变形；仍要检查裁切、数据域、等值、负值、极端数和日期拥挤。真实比较多个单位应分轴或分图，归一化只能比较各自方向并明确说明。
- 卡片状态按实体/指标 ID 分别保存，不用单一布尔值；连续点多张各自保持，刷新数据不无故复位；切换患者/项目按规则重置或按主体恢复。
- 前后面 backface-visibility 与 transform-style 同时正确设置；WebKit 环境必要时加前缀。SVG 在隐藏/翻面后显示时，ECharts 类库要在尺寸可用后 resize，用 ResizeObserver/清理实例处理。
- 避免总览背面只放“最近 N 次”大标题压缩曲线。趋势应保留线、点、首末日期、必要数值与等价数据表。纯 CSS/字符串断言不能证明浏览器图形正常。

离线可直接打开 examples/metric-card.html 查看独立状态和等比示例。原型 screenshot 不等于 Desktop 业务容器 screenshot，两者都要对照。

## 互动共创与开发者确认

UI 质量是单独验收的交付项。新设计优先采用一个匹配任务的专用设计技能，将审美和交互检查显式化；常见实际名称为 design-taste-frontend、frontend-design 或同类，使用前核对本机名称。仅使用可用技能，不把技能安装当成初始化前提。

按照 [互动设计流程](07-INTERACTIVE-DESIGN.md) 先对话，再制作可交互原型、实际预览并由开发者确认。填写 [UI 设计记录](../templates/UI-DESIGN.md)，记录所选技能、确认范围、原型版本与未验证事项。未经确认的探索稿不替换既有高精度原型。技能指导不能替代内容完整性和实际渲染检查。
