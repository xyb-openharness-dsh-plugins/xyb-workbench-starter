# 32 · 整页视图（Full-Page View）规范

来源：2026-10-25 用户对 `dsh-shopping-workbench` 的评审意见——

> 「注意点击打开新页面，空间和内容更加丰富的设计，页面关闭后返回工作台主页或前一页。这个设计很不错，保留到脚手架，现有弹窗空间太小，功能无法扩大。」

这条规范把该意见固化成家族可执行的设计：**内容多的东西不要塞弹窗，点开就是一整页；关掉要能回到刚才那一页，不是回到顶部。**

可运行参考实现：`assets/patterns/page-view.js` + `assets/patterns/page-view.css`，演示见 `examples/page-view.html`（走本地端口）与 `examples/page-view-standalone.html`（单文件、双击可开）。项目实例填写 `templates/FULL-PAGE-VIEW.md`。

> **`file://` 的坑（必读）**：ES module 在 `file://` 下被 CORS 拦，`<script type="module">` 直接白屏。
> 而家族的硬要求是「原型双击 `index.html` 就能开」。所以**原型里要内联**，不要 `import`：
> 把 `page-view.js` 的 `export ` 去掉、包一层 IIFE 挂到 `window.createPageView`，CSS 整段塞进 `<style>`。
> 参考做法看 `examples/page-view-standalone.html`（就是由上面两个文件生成的）。宿主里的正式页面可以正常 `import`。

---

## 1. 为什么不是弹窗

弹窗（`<dialog>` / 居中卡片）在上一个癌种里被用成了万能容器：详情、编辑、图表、报告全部塞进 480–640px 宽的盒子。后果是三条，且都不是审美问题：

1. **内容被压缩成摘要**：一屏放不下就砍字段，砍到最后用户看不到他真正想看的原始报告原文。
2. **结构无法生长**：弹窗里再加页签 → 再嵌弹窗，第二层就只有 300px 可用，功能到此为止。
3. **上下文被切断**：关掉弹窗，用户不记得自己是从哪张卡点进来的，只能凭记忆重新找。

整页视图解决的是这三条：**宽度给足、层级可以往下长、返回有栈**。

## 2. 三层视图模型

| 层 | 名字 | 何时出现 | 关掉回到 |
| --- | --- | --- | --- |
| L0 | 主页 home | 工作台常驻界面 | — |
| L1 | 整页 page | 从主页任一入口点开 | 主页，且停在原来的滚动位置 |
| L2+ | 二级整页 sub-page | 在整页里继续点开 | 上一层整页，且停在原来的滚动位置 |

**没有 L3 上限，但每加深一层必须在顶栏显示层级路径**（如 `主页 › 病理报告 › 2026-03 术后病理`），否则用户不知道自己在哪。

## 3. 弹窗还留着，但收窄用途

不是所有浮层都要改成整页。判据只有一条，写死：

> **预计内容高度超过 1.5 屏，或需要内部多区块切换（页签/分栏/列表+详情）→ 整页；否则 → 弹窗。**

| 用途 | 形态 | 理由 |
| --- | --- | --- |
| 确认提交 / 删除二次确认 | 弹窗 | 一句话，不需要滚动 |
| 单字段小修改（改个日期、选个部位） | 弹窗 | 3 行以内 |
| 记录详情（化验单、影像、病理原文） | **整页** | 要放下原文、来源、时间线 |
| 新增/编辑多条数据 | **整页** | 表单会超过一屏 |
| 全屏图表 / 一图秀放大 | **整页** | 空间就是内容 |
| 报告预览与导出 | **整页** | 需要连续阅读 |
| 日历 / 时间轴全景 | **整页** | 网格密度决定可用性 |
| 逐题量表作答 | **整页** | 题量大，且要能中途返回不丢 |

家族里现有把"详情"做成弹窗的实现**不回溯改造**（与三层信息边界同一口径：新规则自生效日起对新项目生效），但在下一轮迭代修该页时按本规范升级。

## 4. 导航栈与浏览器返回键

`PageView` 内部维护一个栈，四个操作：

| 操作 | 行为 | 栈变化 |
| --- | --- | --- |
| `open(key, opts)` | 压栈并渲染；已在栈顶则忽略（防重复点） | depth +1 |
| `back()` | 退一层；`depth===1` 时等价 `close()` | depth −1 |
| `close()` | 清空栈，回主页 | 归 0 |
| `home()` | `close()` 的别名，供文案用 | 归 0 |

与 `history` 的绑定是**硬要求**，不是增强项：

- 每次 `open` 调 `history.pushState({pv:depth}, '', '#page=' + key)`；
- `popstate` 事件里按 `event.state.pv` 同步栈深，读到 `undefined` 视为回主页；
- 因此**手机/触控板的返回手势 = 返回上一层**，用户在系统层面的肌肉记忆直接可用；
- 刷新页面时 `location.hash` 要能把对应那一页重新打开（深链），打不开就回主页并提示，不许白屏。

栈**不持久化到数据库**，只活在会话里：整页视图是看东西的地方，不是状态机。

## 5. 布局规格（数字写死，不许各地自创）

| 项 | 值 | 说明 |
| --- | --- | --- |
| 遮罩层 | `position:fixed; inset:0`，`--pv-scrim` | 只允许**一层**遮罩，多层不叠灰 |
| 面板内边距 | `inset: clamp(8px, 1.2vw, 16px)` | 留一条缝看见底下的主页，明确"这是浮起来的" |
| 面板圆角 | `14px` | |
| 顶栏高度 | `56px`，`position:sticky; top:0` | 返回/标题/关闭三个位置固定 |
| 内容宽 | `max-width:1180px; margin:0 auto` | 与一图秀的阅读宽一致 |
| 内容内边距 | `24px clamp(16px, 1.6vw, 28px) 56px` | 底部多留，避免最后一行贴边 |
| 滚动 | `.pv-body{overflow:auto; overscroll-behavior:contain}` | **只有这一处滚**，宿主 body 不许出现滚动条 |
| 窄屏 ≤760px | `inset:0`，圆角 0 | 手机上就是整屏，不做悬浮卡片 |
| 层级 | overlay `z-index:60`，二级 `62` | 每层 +2 |

字号不写死，一律 `calc(NNpx * var(--tz))`，沿用家族的 `--tz` 三档（1 / 1.15 / 1.32）。

## 6. 焦点、滚动与减少动效

四条，缺一条用户就会迷路：

1. **记住触发者**：`open` 时存 `document.activeElement`，`close/back` 后 `focus()` 回去。焦点丢到 `body` 是键盘用户最常踩的坑。
2. **每层记住自己的 scrollTop**：退回来时恢复；回主页时主页的 `scrollTop` 也必须恢复（这是用户最直接感知的一条）。
3. **Esc 语义与 `back()` 一致**：深 1 层时 Esc = 关闭，深 3 层时 Esc = 退一层，不许一按全关。
4. **`prefers-reduced-motion: reduce`** 时不播入场位移，但**终态必须完全可见**（不是隐藏）。

焦点陷阱按最简可用实现：Tab 到层内最后一个可聚焦元素时回到第一个。不为它引入依赖库。

## 7. 验收 A1–A10

每个用整页视图的页面都要逐条给证据（DOM 断言或录屏），"看起来对"不算。

| 编号 | 判据 | 反例 |
| --- | --- | --- |
| A1 | 打开后宿主文档**滚不动**（真滚轮打遮罩），滚的是 `.pv-body` | 双层滚动、背景跟着走 |
| A2 | Esc 一层一退，栈空回主页 | 一按全关 |
| A3 | 浏览器返回键等价 `back()` | 返回键直接跳出工作台 |
| A4 | 关闭后焦点回到触发元素 | 焦点落 `body` |
| A5 | 返回主页时滚动位置与点开前一致 | 跳回顶部 |
| A6 | 390 宽无横向溢出（`scrollWidth <= clientWidth`） | 表头撑破 |
| A7 | 带 `#page=xxx` 的地址刷新后仍在该页 | 白屏 |
| A8 | 减少动效下终态可见 | 元素停在 `opacity:0` |
| A9 | 顶栏标题与实际内容一致，无「未命名」 | 复用同一个标题 |
| A10 | 每层同时有**返回**与**关闭**两个入口 | 只有 ✕ |

## 8. 五条反例（比规则记得住）

1. **「大号弹窗」**：宽度仍 `480px`，只是变高 → 没有解决空间问题，不算整页。
2. **只有 ✕**：从第三层想回第二层只能重走一遍，白丢滚动位置。
3. **关掉跳顶部**：主页滚动位置丢失，用户重新找卡。
4. **每层各画一层遮罩**：三层叠出深灰，底下内容全黑。
5. **用 `confirm()` 拦返回**：只有"有未保存内容"时才允许拦一次，其余时候拦路就是拦路。

## 9. 与既有规范的关系

- **07 号交互设计**：整页视图是"渐进披露"的容器形态，披露层级可以更深，但**一次只披露一层**的纪律不变。
- **16 号一图秀**：放大查看时进整页视图，图的 R1–R12 合同不因变大而放宽。
- **三层信息边界**：整页给的是空间，不是判断。页面越宽越容易顺手写"提示""建议"——红线不变。
- **30 号响应式**：390/768/1280 三档断点按本规范第 5 节的 `inset` 与 `max-width` 执行。
