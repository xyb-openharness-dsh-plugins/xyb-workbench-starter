# MinerU 云端解析开发指南（PDF 报告 → 候选）

适用于要导入 PDF 化验单、出院小结、检查报告，并从中抽取结构化指标的工作台。按需接入，不是所有主题的必需依赖。本指南把乳腺癌、GIST、胰腺、宫颈四个工作台已真实跑通的接入经验固化为通用规则；不携带任何 Token，也不替任何项目注册账号。

> **v2（2026-10-22）**：v1 把 Token 优先级写成「显式 > 环境变量 > 密钥文件」，这正是后来"换了新 Token 还是 401"的根因，本版纠正为 **文件优先**；同时补入「设置页手工维护 Token」的读写契约、密钥文件落点、Token 失效的出路、LaTeX 单位与 `.html` 拒收。§1 是可以直接照着做的原则清单，后面各节是依据。

参考实现：社区仓库 `xyb-openharness-dsh-plugins/xyb-workbench`（`dsh/mineru.js`、`dsh/settings.js`、`dsh/extract.js`）、`xyb-community/cervical-workbench`（`dsh/settings.js` 的可写版本 + `dsh/routes.js` 的设置接口）、`lib/zip.js`（零依赖 ZIP 读取）。可复用的纯函数示例：[mineru-labparse-align.mjs](../examples/mineru-labparse-align.mjs)。

## 1. 十条开发原则

按"踩过坑才知道"的顺序排，前六条是必须遵守的，后四条是界面侧的。

| # | 原则 | 违反后的真实现象 |
| --- | --- | --- |
| 1 | **只走 HTTP API，不包装本机 CLI** | GUI 进程 PATH 只有 `/usr/bin:/bin:/usr/sbin:/sbin`，找不到二进制，报 ENOENT，用户无从排查 |
| 2 | **Token 优先级：显式 > 密钥文件 > 环境变量** | 环境变量里残留一把过期 Key，界面存了新 Token 也不生效，报 401，看着像"Token 坏了" |
| 3 | **Token 只有一份实现、一个文件** | 设置页写 A 文件、解析读 B 文件，界面显示"已保存"，解析照样 401 |
| 4 | **Token 原文永不回给界面、不进日志、不进错误消息** | 凭据出现在截图、日志、报错里，等于泄露；界面只需掩码 + 来源 |
| 5 | **表格先 `htmlTablesToPipes()` 再按位置对齐** | 整表被压成一行，8 个指标写成同一个数，**静默错读、不报错** |
| 6 | **解析失败不产候选、不静默降级** | "云端失败就本地正则凑一份"，两套口径的数据混在一起，事后无法区分 |
| 7 | **设置页必须能手工填 Token，并如实回显来源与文件路径** | 只读文案等于把"换 Key"这件事赶去改文件，患者做不到 |
| 8 | **保存要原子写、600、坏文件不覆盖** | 写一半断电得到空文件；把用户手改坏的 JSON 直接覆盖掉，等于销毁现场 |
| 9 | **Token 失效要给三个动作，不是一句报错** | 一句 `401` 之后患者不知道去哪、点什么，功能等于废掉 |
| 10 | **错误消息里的"申请地址"就是 Token 故障的约定标记** | 前后端各自猜状态码，一边改了另一边不认，提醒时有时无 |

## 2. 路线选择：统一走 HTTP API，不用本机 CLI 包装

社区里存在两种实现，功能看起来差不多，但在"装到用户机器上"这一步差别很大。**结论是本指南只维护 HTTP 一条路线。**

| | HTTP API v4 客户端 | 本机 CLI `mineru-open-api` 包装 |
| --- | --- | --- |
| 代码量 | 约 300 行，零依赖 | 约 80 行，但要 spawn 外部进程 |
| 用户侧前提 | 只需要一个 Token | **还要装一个二进制并在 PATH 上** |
| 错误判定 | 结构化（HTTP 状态 + 业务码） | 靠 stderr 正则猜（`401|unauthorized|expired`…） |
| 模型选择 | 显式传 `pipeline` / `vlm`，可做受控回退 | 走 CLI 默认，行为随 CLI 版本漂移 |
| 轮询与超时 | 自己控制节奏、可中断、可重试 | 受 CLI 内部实现约束 |
| Token 来源 | 显式 > 密钥文件 > env，可回 `source` | 还多一个 `~/.mineru/config.yaml`，三处抢优先级 |

四条实际理由：

1. **多一个二进制，就多一个装不上的理由。** 桌面宿主（GUI 进程）的 `PATH` 通常只有系统四个目录，`nvm`、`.npm-global` 都不在里面；用户把 CLI 装在 node 版本目录下，插件就找不到，报"没有找到 mineru-open-api"。我们无法替用户安装，也不该把这类失败留给用户自查。实测：装到 Desktop 后 GUI PATH 下 `execFile('mineru-open-api')` 直接 ENOENT。
2. **CLI 唯一的独有能力，HTTP 也能做。** `flash-extract` 免鉴权、免 Token，走的是纯 HTTP：`POST https://mineru.net/api/v1/agent/parse/file`，body `{"file_name":"report.pdf","language":"ch"}`。实测（2026-10-22）传 `.txt` 返回 `-30002 file type '.txt' is not supported by the lightweight API` 而不是 401，说明它确实不校验 Token。
   **但这条通道最终没有采用**：它只出 markdown、不保证表格结构，而我们的下游强依赖表格位置对齐；同一份报告两条通道产出不同排版，核对成本反而上升。跨工作台统一口径时用户明确"flash 不用了"，代码里的引擎标签与兜底一并移除——**只有 API v4 一条通路，认证失败就报错 + 给申请链接，不假装降级**。
3. **stderr 判错不可靠。** CLI 路线要把 `401`、`unauthorized`、`token expired` 等字样拼成正则，上游改一句文案就会误判成可重试，白烧一次额度。HTTP 拿到的是 `response.status` 与 `code`，判断是确定的。
4. **两处 Token 源会互相掩盖。** `.secrets/mineru.json` 与 `~/.mineru/config.yaml` 同时存在时，谁生效取决于实现细节。**2026-10-22 起彻底删掉 config.yaml 分支**，本机只认一个 JSON 密钥文件。

统一口径：

- **唯一通路**：API v4 四步 + Token。
- **默认模型 `pipeline`**（跨工作台统一）；接口明确拒收时才回退 `vlm`。`pipeline` 对空格分列的表格可能串位，`vlm` 可能"补"出原文没有的内容——两个代价都写进设置页选项说明，让用户知道自己在换什么。
- **不再新增** CLI 包装；已有 CLI 实现的仓库按 §14 的顺序迁到 HTTP。

## 3. 协议（API v4）与实现要点

```
① POST https://mineru.net/api/v4/file-urls/batch   → { batch_id, file_urls[] }
② PUT  <file_urls[0]>           （上传原件，**不设 Content-Type**）
③ GET  /api/v4/extract-results/batch/{batch_id}    → state: pending|running|converting|done|failed
④ GET  <full_zip_url>                              → zip：full.md / *_content_list.json
```

接口、鉴权与额度以 [mineru.net 官方文档](https://mineru.net/) 当期为准；核对过文档不代表某个账号已有调用权限。

- `code !== 0` 或 `state === 'failed'` 都算失败——**不把"跑完了"当"解析对了"**，更不把空字符串当成功结果。
- 上传那一步 **不要设 Content-Type**，设了会被拒。
- 批次接口在 `done` 后不返回页数（`pages` 为 null）；需要页数时从 `content_list` 的 `page_idx` 上限推。
- ZIP 解包若手写（零依赖），只做中央目录 + deflateRaw，不支持 ZIP64 时明确报错，不猜结构。
- 鉴权自检技巧：拿 Token 查一个不存在的任务，返回业务错误码（如 `-60012`）而不是 401，即 Token 有效——不用真消耗一次解析额度。
- **代理是已知缺口**：Node 内置 `fetch` 不认 `HTTP_PROXY`/`HTTPS_PROXY`（curl/CLI 会认）。检测到代理变量时，网络类错误要直接写明"当前版本的内置请求不走系统代理"，否则用户会去查网络、查 Token，查半天都不是原因。真正的代理支持需要 `undici` 的 ProxyAgent，未做就不要假装有。
- **文件类型白名单要跟实测走**：v4 批量接口拒收 HTML（`model_version 'vlm'/'pipeline' cannot process html files`，`-10002`），所以白名单里不要放 `.html`；留着它等于承诺一个一定失败的入口。`.txt` / `.md` / `.csv` 也不走云端，本地解析即可。

## 4. Token：来源、优先级、落点

### 4.1 优先级（这一条写反过，代价很大）

```
显式传参 > 密钥文件 > 环境变量 > 随包公益 Token（有该能力的仓才有这一级）
```

**文件必须排在环境变量前面。** 真实事故（2026-10-22）：本机环境里留着一条早已过期的 `MINERU_TOKEN`，用户在设置界面换成新 Token 后请求仍用环境里那把，云端返回 401 `user token expired`，现象是"我明明换了 Key 还是不行"。实测三把 Key 的结果：环境变量 → 401 expired；文件里的新 Key → 有效；随包公益 Key → 有效。

配套要求：

- 状态接口与错误消息**必须如实报来源**（`secret-file` / `environment` / `bundled-community` / 空），否则被盖住时无法自查。
- 复现测试时用 `env -u MINERU_TOKEN`（或在测试里显式注入空 env）才验的是文件分支。
- 文档与注释里不要写"env 可以覆盖文件"——它排第二，只能兜底。

### 4.2 密钥文件落点

| 场景 | 落点 | 理由 |
| --- | --- | --- |
| 开发 / 自用（仓库内已有文件） | 仓库 `.secrets/mineru.json` | 沿用既有约定，不惊动本地开发 |
| 装进 Desktop（无仓库内文件） | `~/.<品牌>/secrets/mineru.json` | **包目录会随插件升级整份替换**，写在包里的 Token 会静默消失 |
| 测试 / 排障 | `CERVIPAL_MINERU_SECRET` 之类显式环境变量指定文件 | 让用例互不干扰，不碰真实凭据 |

判断顺序：`显式指定文件 env` > `仓库内 .secrets/mineru.json（仅当它已存在）` > `用户目录`。

> 只落地在包里是早期做法，代价是用户升级一次插件就得重新填 Token，而且**依赖目录本来就不该存用户数据**。已有包内文件的部署继续沿用，新部署一律写用户目录。

### 4.3 三条硬规则

1. **不写进源码、文档、测试**。发布检查扫全仓库；`.gitignore` 必须有 `.secrets/`（漏过一次，测试用的假 Token 落进了工作区）。
2. **不进日志、不进错误消息、不回给界面**。只给来源与掩码（`sk-u****54`）；状态接口的返回体里**没有 token 字段**。
3. **不进发布包**。`files` 白名单里没有密钥目录。

## 5. 设置页手工维护 Token（v2 新增）

### 5.1 上一版错在哪

v1 时代为了"不假装有状态"，把设置页做成一句只读文案：「Token 只从本机 `.secrets/mineru.json` 读取（此处不显示状态与掩码）」。用户反馈很直接：**还是要能自己在界面里填**。

三个具体问题：

1. **把维护成本推给用户**：换 Token 要去文件管理器找隐藏目录、手改 JSON。这不是"如实"，是"没做"。
2. **只读文案掩盖了真假问题**：更早的版本写死 `已配置（掩码：mr-****）`——不管有没有 Key 都显示已配置，且 `mr-` 与真实 `sk-` 前缀对不上，是假绿灯。
3. **保存了但不生效**：设置页保存后弹窗不关、没有反馈，用户不知道存没存；优先级又排在 env 之后，存了也没用。

### 5.2 接口契约（两条链路共用一份路由）

```
GET  /api/<topic>/settings/mineru
→ 200 {
    configured: boolean,        // 有效 Token 是否存在（文件或 env 任一）
    source: 'file'|'env'|'none',
    sourceLabel: string,        // 直接显示给用户的一句话
    masked: string,             // 'sk-u****54'；无则空串
    file: string,               // 显示用路径，主目录缩成 ~
    fileExists: boolean,
    tokenUrl: string,           // 申请 / 重置地址
    permissions: string|undefined,  // '600'
    error?: string              // 文件坏了的说明；不是"没配"
  }

POST /api/<topic>/settings/mineru
  body {token: "sk-..."}      → 保存，返回同 GET 的状态
  body {action: "clear"}      → 清除 token 键，返回同 GET 的状态
  400 invalid_token           → 用户输入问题（空/太短/超长/含空白/非法字符）
  500 settings_write_failed   → 文件坏了、写不进去（环境问题，不要归到用户头上）
  405 method_not_allowed
```

要点：

- **状态接口必须可写**。只读状态是 v1 的遗留；一条 `GET` 无法完成"手工维护"。
- 若项目的设置本来就整表提交（如 `POST /settings/config` 一次带 `parseMode` / 模型 / Token），可以不复刻独立路径，但**语义要等价**：Token 的校验、落盘、清除各是一条独立分支，且返回体同样只给掩码与来源。
- 区分 400 与 500：把环境问题报成"格式不对"，用户会反复粘贴同一个正确的 Token。
- `health.capabilities` 里加一项 `mineru-settings`，前端据此决定是否显示输入框（旧宿主 + 新前端时不会出现点了没反应的按钮）。

### 5.3 只有一份实现

Token 有三个使用者：解析客户端要读、路由要给状态、设置页要写。**三处各写一遍 JSON 读写，就会出现"界面说已保存、解析却读不到"这种极难查的分叉。**

所以单独一层 `dsh/settings.js`（约 200 行），导出一组纯函数，`dsh/mineru.js` 也 import 它：

| 函数 | 职责 | 关键约束 |
| --- | --- | --- |
| `secretFile()` | 决定当前生效文件 | env 指定 > 已存在的包内文件 > 用户目录 |
| `readMineruToken()` | 读 | ENOENT 返回空串；**非法 JSON 抛错，不当"没配"** |
| `validateMineruToken()` | 校验 | 空 / <8 / >1024 / 含空白 / 非 `[A-Za-z0-9._-]` 分别报错；**不猜上游规则** |
| `saveMineruToken()` | 写 | 校验 → 读旧保留其它键 → 原子写 600 → 返回状态 |
| `clearMineruToken()` | 清除 | **只删 `token` 键**；文件因此变空才删文件 |
| `mineruSettingsStatus()` | 状态 | 掩码 + 路径 + 来源；**不含原文** |

`readMineruToken()` 抛错的理由：文件存在但不是合法 JSON 时，若返回空串，界面会显示"未配置"，用户以为保存失败，实际是文件被别的工具写坏了。

### 5.4 写入的五条要求

1. **先校验再落盘**。校验失败**不创建文件**（否则会在磁盘上留下一个半成品，下次读它就是"已配置但无效"）。
2. **原子写**：`写 tmp（同目录）→ chmod 600 → rename`。同目录是关键，跨文件系统 rename 不是原子操作。
3. **权限 600、目录 700**。Token 是凭据，不是配置。
4. **保留其它键**：读旧内容 → 改 `token` → 写回。用户可能在同一个 JSON 里放了别的字段，直接覆盖等于删数据。
5. **坏文件不覆盖**：解析不了就报错并给出路径，让用户修或删。**不静默重建一个空文件**——那会销毁排查现场。

### 5.5 清除语义

- 只删 `token` 键，不删整个文件（里面可能还有别的设置）。
- 文件因此变空才 `rm`。
- 文件本来不存在时，清除是幂等的成功，不报错。
- 清除**不动环境变量**。若 env 里有 Token，清除后状态会变成 `source: env`——这是对的，界面上要能看出"文件清了但环境里还有一把"。

### 5.6 前端四处细节

| 细节 | 写错的后果 |
| --- | --- |
| 输入框 `type="password"` + `autocomplete="new-password"` | 明文显示在屏幕上；浏览器的密码管理器会往里填账号密码 |
| 保存后**清空输入框** | 掩码状态和输入内容同时存在，用户以为还没保存 |
| 保存后**关弹窗**（成功才关） | 用户反复点保存，不知道有没有生效 |
| 状态区显示**掩码 + 文件路径 + 来源** | 只显示"已配置"，无法判断是哪一把 Key、在哪个文件 |

状态文案示例（真实取值）：

```
尚未配置 Token：扫描件与照片的自动识别会用不了；TXT / MD / CSV 仍在本机解析。
当前生效：sk-u****54 · 已保存于 ~/.cervical/secrets/mineru.json
当前生效：sk-j****qM · 临时使用环境变量 MINERU_TOKEN（未写入文件）
无法读取密钥文件：… 不是合法 JSON（应为 {"token": "sk-..."}）；请修正或删除该文件后重试。
```

### 5.7 验收方式：点一遍，不是断言一遍

单测能证明"函数写对了"，证明不了"界面接上了"。这条链路的验收脚本按真实操作走（本机脚本，不进仓库）：

```
起 dev-server（密钥文件指向临时目录，清空 MINERU_TOKEN）
→ 打开页面 → 点设置 → 切到「文档解析」→ 读初始状态
→ 在输入框里键入 sk-... → 点保存
→ 读状态文案 / 确认输入框已清空 / 读磁盘 JSON / 读文件权限
→ 点清除 → 再读状态与文件
```

实测结果（2026-10-22，宫颈工作台）：

| 步骤 | 观测 |
| --- | --- |
| 初始 | 「尚未配置 Token：扫描件与照片的自动识别会用不了；TXT / MD / CSV 仍在本机解析。」 |
| 填入 `sk-ui-manual-test-abcdef987654` 并保存 | 「当前生效：sk-u****54 · 已保存于 …/mineru.json」；输入框已清空 |
| 读磁盘 | `{"token":"sk-ui-manual-test-abcdef987654"}`，权限 **600** |
| 点清除 | 回到「尚未配置」，文件随之删除 |

**关键词是"同步"**：界面显示的那把 Key 与文件里那把必须是同一把。测试要断言磁盘内容，而不是只断言接口返回 200。

## 6. Token 失效的出路（v2 新增）

解析失败时最没用的一句话是 `401 Unauthorized`。用户需要的是"现在做什么"。

### 6.1 三个动作

界面留一条**独立提醒**（不随下一句话消失），内容四段：

1. **影响范围**：只有扫描件与照片的自动识别受影响；原件完好保存在本机；已确认的指标不受影响。
2. **申请 / 重置入口**：`https://mineru.net/apiManage/token`，可点。
3. **「填入新 Token」**：直接打开设置页，少两步点击。
4. **「让 Agent 提醒我怎么更新」**：把一段提示词放进右侧会话输入框，**由患者自己按发送**，不代替患者发言。

### 6.2 Agent 提示词的三条硬要求

- **给步骤，不给原理**：申请 → 复制 → 设置里粘贴 → 保存 → 回资料库重新解析。
- **警告不要把 Token 发到对话或病友群**：它是账号凭据，贴出来等于公开。
- **必须说明这是工具问题，不是病情变化**，且不许借机给治疗建议。

会话型产品还有个额外动作：**Token 失效期间**，任一页面的"给我建议"提示词都附一句"本机提示：解析用的 Token 失效，请在末尾用一两句话提醒患者更新"。患者不会主动翻设置，这条才让它有被看见的机会。

### 6.3 判定用"约定标记"，不新增状态码

后端把申请地址写进 `NO_TOKEN` 与 `UNAUTHORIZED` 的错误消息里；前端只判断 `failure.includes(tokenUrl)` 是否为真。

- 一处约定、两处引用，前后端不会各猜一套。
- 代价是要保证 `MINERU_TOKEN_URL` 两边字面量一致——在两侧代码注释里互相标注"改一处要同时改另一处"。
- **非 Token 故障不弹**（网络超时、文件本身失败都走各自文案），这条要有测试守住。

## 7. 从 markdown 到候选：抄写，不判断

抽取层只做抄写，不做医学判断。规则表可直接复用：

| 输入 | 规则 |
| --- | --- |
| 指标名 | 只认项目指标字典（内置词表 + 用户别名）；拉丁名要词边界（`CRP` 不会被当成肌酐 Cr） |
| 数值 | 取指标名后第一个数；参考范围 `3.5-9.5` 不会被当成结果 |
| 不等式 | `<0.5` 原样保留、数值字段留空——折成 0.5 就是替用户下结论 |
| 单位 | 归一常见写法（`10^9/L`→`10⁹/L`、`umol/L`→`μmol/L`）；认不出就留空，候选标"缺单位" |
| 日期 | 先看带标签的行（采样/报告日期…），再看前几十行的第一个日期；`2026-02-31` 这种不认 |
| 表格 | 按单元格对齐；整表被塞进一个单元格时**按位置对齐**（见 §8）；`full.md` 的 HTML 表格**先转竖线表**再对齐 |
| 结论 | 不产病理结论、不产"是否复发"、不写判断性字段 |

### 7.1 单位要先剥 LaTeX 外壳（2026-10-22）

真实 `full.md` 的单位是 `$10^9/L$`、`10^{9}/L`，而不是纯文本 `10^9/L`。曾经的离线夹具写的是纯文本，所以单测一直绿，装到桌面端单位列却原样显示 `$10^9/L$`——**夹具比线上干净，是这类"本地过、线上错"的常见来源**。

处理顺序：先剥 `$`、`\(…\)`、`\[…\]`、`\mu`、`\text{}`/`\mathrm{}` 外壳与花括号，再做单位归一；**认不出的只剥壳、不推断**。夹具要用真实 `full.md` 片段（去掉患者信息），不要手写"干净版"。

## 8. 表格对齐：最重要的一条取舍

云端解析会把**整张表塞进一个单元格**（如 `Item CA15-3 CEA …` / `Result 18.6 2.1 …`）。朴素抽取（"指标名后面取第一个数"）会让 8 个指标全写成同一个数——这是真实踩到的事故，第一版就这么错的。

正确做法是**按位置对齐**：第 i 个指标配第 i 个数值/单位；**指标数与数值数不一致就整行放弃**。宁可漏一条让用户手填，也不能把 8 个指标写成同一个数。核心逻辑见 [mineru-labparse-align.mjs](../examples/mineru-labparse-align.mjs)（纯函数，不联网、不读凭据）。

### 8.1 先转竖线表，再谈对齐（最坑的一条）

`full.md` 里的表格**不是 markdown 管道表，而是 `<table><tr><td>` HTML**。若按常规清洗流程先 `replace(/<[^>]+>/g,'')` 剥标签，整张表会被压成一行连续文本：

```
发生部位胃体肿瘤最大径6.8 cm核分裂象计数12 个/50 HPF切缘R0
```

后果不是报错，而是**静默错读**——"指标名后取第一个数"会把 `肿瘤大小` 读成 `6.8`、`核分裂象` 读成 `12`，看着都对，实际是整表串位；化验横表更明显，出现 `白细胞 4.210 10^9/L`、`血小板 21010 10^9/L` 这种黏连值。血压类项目一旦串位，数值会翻十倍。

所以顺序必须是 **① `htmlTablesToPipes()` 转 `| a | b |` + 补一条分隔行 → ② 按位置对齐**，绝不能先剥标签。

`htmlTablesToPipes()` 的四个实现细节，缺一个就会静默少列：

| 细节 | 写错会怎样 |
| --- | --- |
| `colspan="2"` 要补空单元格 | 少一列，后续所有列错位，但不报错 |
| 正则写 `["']?` 而不是 `"?'` | `"?'` 被解析成"可选双引号 + 字面单引号"，`colspan="2"` 完全匹配不上——同样只表现为少一列 |
| 单元格内 `|` 换成 `/` | 管道符会把一行撑成多列，分隔行数量对不上 |
| 首行当表头、第二行插 `| --- |` | 下游按"第二行是分隔行"跳过表头时，表头会被当成数据行解析 |

同源回归测试见 `test/mineru-align.test.mjs`，其中一条是**反例**：断言"先剥标签会把整表压成一行且抽不出任何指标"，防止后人在清洗链里把这一步顺序调回去。夹具 `test/fixtures/mineru-pathology-html.md` 是真实 1 页 PDF 的 `full.md` 原文，不含任何患者信息。

## 9. 失败语义：事务原子，不静默降级

```
发起解析 → 上传/轮询/解包 → 候选写入 + document=parsed + job=succeeded   （同一事务）
                        ↘ 任一步失败：事务回滚 → document=parse_failed + job=failed
                          （候选 0 条，原件保留，可重试；错误码与原文留在任务记录里）
```

- **失败不产候选**：失败状态下候选写入直接拒绝。
- **不静默降级**：不做"云端失败就本地正则凑一份"——两套口径产出的数据没法比较。
- **重试不重置历史**：重复导入不新建文档；重试新增一条任务记录，旧的失败记录留着。
- 重复导入按（主体, 文件哈希）去重，**不重置已解析状态**。
- **错误码要分类，不要一个 500 打天下**：`NO_TOKEN` / `UNAUTHORIZED`（401/403，不重试）／`TASK_FAILED`（文件本身失败，不换模型）／`TIMEOUT`／`NO_MARKDOWN`（zip 里没有 `full.md` 就失败，不返回半份结果）／`NETWORK`（含代理提示）。
- **只有"接口不接受这个模型参数"才换模型**；文件本身失败换模型重试只是多花一次额度，结论还是失败。
- 错误消息不要叠加前缀。曾经出现「解析失败：本地解析失败：…」——后端给所有失败加"本地解析失败"（可解析其实在云端），界面又加一层。**前缀只留最外层那一句。**

## 10. 界面三态与用户控制

"解析中 / 失败可重试 / 成功待核对"三态是界面工作项，不是解析库自带的。每份材料上解析必须由用户显式触发；失败时保留原件和错误信息，重试不清历史；成功后候选进入核对流程，**逐项确认才进事实层**（接受≠审核，审核字段保持空）。云能力告知实际发送路径，属设置页与导入提示的固定内容。

## 11. 代价与知情

| 代价 | 说明 | 处理方式 |
| --- | --- | --- |
| 原件要出本机 | 上传到 `mineru.net` | 导入前明确提示；**不自动上传，必须用户点"解析"**；离线时功能不可用 |
| Token 要保管 | `sk-` 开头的长期凭证 | 只从密钥文件/环境变量读，进 `.gitignore`；发布检查带密钥扫描 |
| 有额度上限 | 单文件 200MB / 600 页；高优先级 2000 页/天 | 超限按失败处理并保留原件，可换方式重试 |
| 结果不保证对 | OCR 与表格还原都会错 | 解析结果**永远只是候选**，逐项核对确认后才进事实层 |

## 12. 实测经验

### 12.1 乳腺癌工作台（2026-10-17）

| 项 | 结果 |
| --- | --- |
| 鉴权自检 | 查不存在的任务返回 `code=-60012`（而非 401）→ Token 有效 |
| 一次完整解析 | 1 页合成 PDF：申请→上传→轮询→下载 **8.6–9.7 秒** |
| 产出 | zip 内 `full.md` + `*_content_list.json` + `layout.json` + `model.json` + `images/` |
| 抽取 | 修完对齐 bug 后 8 项指标值与单位全部正确；报告日期自动识别 |
| 落库 | 候选 → 逐项确认 → 事实表；审核字段保持 NULL |

**未验证**（复用前先确认自己项目的情况）：扫描件/图片 OCR 质量、双栏排版、多页报告、中文项目名识别率、真实报告错读率、额度用尽表现、网络中断重试。

### 12.2 GIST 工作台（2026-10-21，第二处复现）

| 项 | 结果 |
| --- | --- |
| 一次完整解析 | 1 页病理 PDF：申请→上传→轮询→下载 **12.9–18.8 秒**（与模型有关） |
| 产出 | 13 条候选：肿瘤部位/大小/核分裂象/切缘/破裂/危险度/CD117/DOG1/KIT/PDGFRA/SDHB + 报告日期 |
| 抽取 | 修完 HTML 表格坑后值与单位全对；11 条病理字段一次到位 |
| 测试 | 39 → 67 项，新增 28 项覆盖抽取/编排/客户端协议 |

这一轮新踩到、第一处没记录的三点：

1. **环境变量会盖住密钥文件，且现象是 401 而不是"没配"**。对策见 §4.1：状态接口返回来源与掩码，界面一眼看出是哪个在起作用。
2. **"解析中"不要写进库**。只在内存/任务记录里存在；进程退出留下 `解析中` 就是僵尸状态，用户看到永远转圈。库里只允许出现 `待解析 / 待核对 / 解析失败` 三个终态。
3. **导入只改状态，不产候选**。`待解析` 是导入的默认值，不出现 `待核对`——否则用户会以为"导入就有结果了"。

### 12.3 Token 维护相关的三次真事故（2026-10-22）

| 现象 | 根因 | 修法 |
| --- | --- | --- |
| 换了新 Token 还是 401 | 环境变量排在文件前面，请求一直用环境里那把过期 Key | 优先级改为文件优先；错误消息写出"本次使用的是哪一把" |
| 设置页显示"已配置"，其实没配 | 状态是硬编码字符串 `masked: mr-****` | 状态接口按真实文件算；`mr-` 前缀本身就对不上 |
| 设置页填了保存，解析仍读不到 | 界面写 `~/.mineru/config.yaml`，解析读 `.secrets/mineru.json` | 删掉 YAML 分支；读写只走 `dsh/settings.js` 一份实现 |

## 13. 采纳清单与复用边界

接入前逐条过：

- [ ] 用户知情：导入提示写明原件会上传到 mineru.net；解析由用户显式触发。
- [ ] 密钥三条硬规则落实；`.gitignore` 含 `.secrets/`；发布检查含密钥扫描。
- [ ] **Token 优先级是"文件在前、env 在后"**；状态接口返回 `source` 与掩码。
- [ ] **设置页能手工填 Token**：`GET` 有状态、`POST` 能存能清；校验失败不落盘。
- [ ] 写入原子（同目录 tmp + rename）、文件 600 / 目录 700、保留其它键、坏文件不覆盖。
- [ ] 密钥文件默认落用户目录（装机场景），不依赖包内路径。
- [ ] Token 失效给三个动作（申请页 / 填新 Token / 让 Agent 提醒）；非 Token 故障不弹。
- [ ] 抽取层只抄写：指标字典、词边界、不等式、单位归一、整行放弃。
- [ ] **单位先剥 LaTeX 外壳**；夹具用真实 `full.md` 片段，不手写干净版。
- [ ] **表格先 `htmlTablesToPipes()` 转竖线表再对齐**；`colspan` 补空位；写一条"先剥标签会压成一行"的反例测试。
- [ ] 文件类型白名单与实测一致（`.html` 不进白名单）。
- [ ] 失败语义：事务原子、失败不产候选、不静默降级、重试留历史。
- [ ] 候选永远只是候选：逐项核对确认才进事实层；接受不等于审核。
- [ ] 界面三态与重试入口在排期内，不假装"库好了界面就有了"。
- [ ] 未验证项如实写进项目文档，不写"扫描件已支持"。

不做文档理解、不求全量还原版式；只要结构化候选。非 PDF/非报告类文件不强行走这条链路。

## 14. 统一模块与迁移顺序

统一后每个工作台只需要照着拼六个部件，**逻辑只有一份实现**：

| 部件 | 职责 | 判据（怎么算做对了） |
| --- | --- | --- |
| `dsh/mineru.js` | 四步协议 + 错误分类 | 单测覆盖：四步顺序、PUT 不带 Content-Type、401 不重试、模型回退判定、ZIP 读取、缺 full.md 报错 |
| `dsh/settings.js` | Token 读写 + 状态（唯一实现） | 单测覆盖：来源优先级、掩码、校验、原子写与 600、坏文件抛错、清除只删 token 键 |
| `dsh/<topic>parse.js` | markdown → 候选（先 `htmlTablesToPipes`，单位先剥 LaTeX） | 单测覆盖：位置对齐、`colspan` 补位、不等式、单位归一、抽不到返回空、**先剥标签会串位的反例** |
| `dsh/parse.js` | 编排：读原件 → 调用 → 事务写候选 + 置状态 | 单测覆盖：成功不碰事实表、失败不产候选、非可解析格式不发请求、原件缺失 404、重解析不堆积 |
| 设置接口 | `GET/POST /api/<topic>/settings/mineru` | 三态可区分（未配置 / 文件生效 / env 生效）；POST 能存能清；响应无原文 |
| 任务表 | `parse_job`（或 `extraction_run`） | 重试新增一行，旧失败记录保留；`解析中` 不写进 document 状态 |

迁移顺序（按"风险 × 工作量"排）：

1. **清掉写死的 Token 状态**。界面里出现 `已配置（掩码：mr-****）` 这类硬编码就是假绿灯。改成读状态接口。
2. **把 Token 读写抽成一层**。若设置页与解析各有一份路径/解析逻辑，先合并，否则后面每条改动都要改两处、且必然漏一处。
3. **设置接口补成可写**。`GET` 给状态、`POST` 存/清；只读状态是半成品，用户换 Key 还得去改文件。
4. **补 HTML 表格转换**。只认 CSV/行式文本的抽取器，遇到 `<table>` 会整表压成一行（见 §8.1）。移植 `htmlTablesToPipes()` + 一条反例测试。
5. **补任务历史**。只有 `document.status` 没有 `parse_job` 的实现，用户点十次重试在库里看不出痕迹。
6. **CLI 路线改 HTTP**。顺带补上缺失的抽取层——只落 markdown 原文、让用户对着 markdown 手录候选，等于把结构化成本推给患者。
7. 最后统一跑一遍 §13 清单与契约测试，不一致就不算迁移完。
