# 可选能力：MinerU 云端解析（PDF 报告 → 候选）

适用于要导入 PDF 化验单、出院小结、检查报告，并从中抽取结构化指标的工作台。按需接入，不是所有主题的必需依赖。本指南把乳腺癌工作台已真实跑通的接入经验固化为通用规则；不携带任何 Token，也不替任何项目注册账号。

参考实现：社区仓库 `xyb-openharness-dsh-plugins/xfb-workbench` 的 `dsh/mineru.js`（客户端）、`lib/zip.js`（零依赖 ZIP 读取）、`dsh/labparse.js`（抽取）。可复用的纯函数示例：[mineru-labparse-align.mjs](../examples/mineru-labparse-align.mjs)。

## 1. 先决定要不要云端解析

本地优先不等于本地解析。PDF 报告常是扫描件或双栏排版，正则读不出来；一期又不该让用户为导入一份报告去装 Python 模型。所以解析走云端，**原件与解析结果都留在本机**，只把文件内容传给 MinerU 换回 markdown。

代价要写在明处，并在界面上让用户知情：

| 代价 | 说明 | 处理方式 |
| --- | --- | --- |
| 原件要出本机 | 上传到 `mineru.net` | 导入前明确提示；**不自动上传，必须用户点"解析"**；离线时功能不可用 |
| Token 要保管 | `sk-` 开头的长期凭证 | 只从环境变量或本地密钥文件读，进 `.gitignore`；发布检查带密钥扫描 |
| 有额度上限 | 单文件 200MB / 600 页；高优先级 2000 页/天 | 超限按失败处理并保留原件，可换方式重试 |
| 结果不保证对 | OCR 与表格还原都会错 | 解析结果**永远只是候选**，逐项核对确认后才进事实层 |

## 2. 协议（API v4）

```
① POST https://mineru.net/api/v4/file-urls/batch   → { batch_id, file_urls[] }
② PUT  <file_urls[0]>           （上传原件，**不设 Content-Type**）
③ GET  /api/v4/extract-results/batch/{batch_id}    → state: pending|running|converting|done|failed
④ GET  <full_zip_url>                              → zip：full.md / *_content_list.json
```

接口、鉴权与额度以 [mineru.net 官方文档](https://mineru.net/) 当期为准；核对过文档不代表某个账号已有调用权限。

实现要点与踩坑：

- `code !== 0` 或 `state === 'failed'` 都算失败——**不把"跑完了"当"解析对了"**，更不把空字符串当成功结果。
- 上传那一步 **不要设 Content-Type**，设了会被拒。
- 批次接口在 `done` 后不返回页数（`pages` 为 null）；需要页数时从 `content_list` 的 `page_idx` 上限推。
- ZIP 解包若手写（零依赖），只做中央目录 + deflateRaw，不支持 ZIP64 时明确报错，不猜结构。
- 鉴权自检技巧：拿 Token 查一个不存在的任务，返回业务错误码（如 `-60012`）而不是 401，即 Token 有效——不用真消耗一次解析额度。

## 3. 密钥三条硬规则

优先级：显式传入 > 环境变量（如 `MINERU_TOKEN`）> 本地密钥文件（如 `.secrets/mineru.json`，mode 600、进 `.gitignore`）。

1. **不写进源码、文档、测试**。发布检查扫全仓库；示例字符串确实需要时在同行加允许标记。
2. **不进日志**。错误消息只给来源（`env:MINERU_TOKEN`）与掩码（`sk-ib****Ab`），给全串一律视为缺陷。
3. **不进发布包**。`files` 白名单里没有密钥目录。

轮换：拿到新 Token 换文件/环境变量即可，代码里没有硬编码，不需要改任何文件。

## 4. 从 markdown 到候选：抄写，不判断

抽取层只做抄写，不做医学判断。规则表可直接复用：

| 输入 | 规则 |
| --- | --- |
| 指标名 | 只认项目指标字典（内置词表 + 用户别名）；拉丁名要词边界（`CRP` 不会被当成肌酐 Cr） |
| 数值 | 取指标名后第一个数；参考范围 `3.5-9.5` 不会被当成结果 |
| 不等式 | `<0.5` 原样保留、数值字段留空——折成 0.5 就是替用户下结论 |
| 单位 | 归一常见写法（`10^9/L`→`10⁹/L`、`umol/L`→`μmol/L`）；认不出就留空，候选标"缺单位" |
| 日期 | 先看带标签的行（采样/报告日期…），再看前几十行的第一个日期；`2026-02-31` 这种不认 |
| 表格 | 按单元格对齐；整表被塞进一个单元格时**按位置对齐**（见第 5 节） |
| 结论 | 不产病理结论、不产"是否复发"、不写判断性字段 |

## 5. 表格对齐：最重要的一条取舍

云端解析会把**整张表塞进一个单元格**（如 `Item CA15-3 CEA …` / `Result 18.6 2.1 …`）。朴素抽取（"指标名后面取第一个数"）会让 8 个指标全写成同一个数——这是真实踩到的事故，第一版就这么错的。

正确做法是**按位置对齐**：第 i 个指标配第 i 个数值/单位；**指标数与数值数不一致就整行放弃**。宁可漏一条让用户手填，也不能把 8 个指标写成同一个数。markdown 里的 HTML 表格先转 `| a | b |` 再走同一条对齐路径。核心逻辑见 [mineru-labparse-align.mjs](../examples/mineru-labparse-align.mjs)（纯函数，不联网、不读凭据）。

## 6. 失败语义：事务原子，不静默降级

```
发起解析 → 上传/轮询/解包 → 候选写入 + document=parsed + job=succeeded   （同一事务）
                        ↘ 任一步失败：事务回滚 → document=parse_failed + job=failed
                          （候选 0 条，原件保留，可重试；错误码与原文留在任务记录里）
```

- **失败不产候选**：失败状态下候选写入直接拒绝。
- **不静默降级**：不做"云端失败就本地正则凑一份"——两套口径产出的数据没法比较。
- **重试不重置历史**：重复导入不新建文档；重试新增一条任务记录，旧的失败记录留着。
- 重复导入按（主体, 文件哈希）去重，**不重置已解析状态**。

## 7. 界面三态与用户控制

"解析中 / 失败可重试 / 成功待核对"三态是界面工作项，不是解析库自带的。每份材料上解析必须由用户显式触发；失败时保留原件和错误信息，重试不清历史；成功后候选进入核对流程，**逐项确认才进事实层**（接受≠审核，审核字段保持空）。云能力告知实际发送路径，属设置页与导入提示的固定内容。

## 8. 实测经验（2026-10-17，乳腺癌工作台）

| 项 | 结果 |
| --- | --- |
| 鉴权自检 | 查不存在的任务返回 `code=-60012`（而非 401）→ Token 有效 |
| 一次完整解析 | 1 页合成 PDF：申请→上传→轮询→下载 **8.6–9.7 秒** |
| 产出 | zip 内 `full.md` + `*_content_list.json` + `layout.json` + `model.json` + `images/` |
| 抽取 | 修完对齐 bug 后 8 项指标值与单位全部正确；报告日期自动识别 |
| 落库 | 候选 → 逐项确认 → 事实表；审核字段保持 NULL |

**未验证**（复用前先确认自己项目的情况）：扫描件/图片 OCR 质量、双栏排版、多页报告、中文项目名识别率、真实报告错读率、额度用尽表现、网络中断重试。

## 9. 采纳清单与复用边界

接入前逐条过：

- [ ] 用户知情：导入提示写明原件会上传到 mineru.net；解析由用户显式触发。
- [ ] 密钥三条硬规则落实；发布检查含密钥扫描。
- [ ] 抽取层只抄写：指标字典、词边界、不等式、单位归一、整行放弃。
- [ ] 失败语义：事务原子、失败不产候选、不静默降级、重试留历史。
- [ ] 候选永远只是候选：逐项核对确认才进事实层；接受不等于审核。
- [ ] 界面三态与重试入口在排期内，不假装"库好了界面就有了"。
- [ ] 未验证项如实写进项目文档，不写"扫描件已支持"。

不做文档理解、不求全量还原版式；只要结构化候选。非 PDF/非报告类文件不强行走这条链路。
