# 可复用开发与设计方法

本页将已认可的实践写成新项目能执行的规则；业务实体和视觉主题按项目确定，不复制原项目名称、分类或运行时身份。

## 先确定任务阶段，再确定数据约束

若任务包含收集、编排、交付，分别建模。第一步保存候选或清单，不提前要求只有第二步才需要的日期、时长或审批字段；第二步确认顺序、分组与计划；第三步生成结果并可回顾。每步都有清楚的下一步CTA，返回不丢已保存输入。

收藏/长期资料、当前任务清单、已编排项和历史输出职责不同。移出当前清单不顺带取消收藏或删除历史结果；批量确认事务提交，失败不留下半份数据。业务实体不跟随Tab拆成多个事实源，公共目录输入与用户事实分离。

## 原型与正式实现保持一套可追踪合同

已确认原型先整理页面树、二级页/隐藏内容与交互清单，再映射组件/API/数据/结果。后续可交互预览尽量由正式页面生成，旧稿保留为版本对照；偏离有原因和替代验收。共享组件→完整Tab→关联流程成组开发，避免逐按钮全量测试，也避免全站完成才第一次安装。

## 宿主异步操作形成完整状态转换

创建/恢复会话的调用返回不代表宿主当前会话、owner和业务映射已经就绪。适配层等待当前会话与归属确认，再持久化映射和追加草稿；前后验证项目身份和递增代次，超时可重试，切换后丢弃旧结果。打开其它业务项目不自动重绑已有会话。见[双状态规范](09-WORKBENCH-STATUS.md)。

## 先验证产物与边界，再解释页面异常

外部字段可能返回字符串、数组、空值或缺ID；按服务实际结构归一化与校验，逐项展示异常，不能因一项坏值使整批结果不可用。类型、项目身份和修订号仍由服务端做权威校验。

JS语法通过不能证明CSS/图像/字体能用。检查实际构建产物的类型和内容；新增资源同步更新打包清单、资源路由及MIME，并对实际tgz解包后的HTTP响应检查。图形布局与点击交互在真实业务容器验收，字符串出现不证明视觉正确。

本机更新按[安装交付规则](06-VALIDATION-AND-RELEASE.md)做到实际安装版本；只有异常时才展开完整诊断链。更换模型或工具之前，先交接复现、原始异常、已排除假设和实际运行版本。

## 冻结输出，管理状态与内容分开

报告、方案、路书等输出保留生成时的输入快照、模板版本和来源时点。后续修改恢复为可编辑草稿，再生成新版本；存档、软删除与恢复使用独立管理状态，不改历史内容。外部资料刷新以内容摘要识别变化，不伪造用户编辑revision。用户采纳外部更新后新旧版本均可回顾。

固定模板提供完整且稳定的输出结构；Agent互动用于补充个性化要求。两条路径复用同一输入快照和结果登记，不复制聊天，不把生成提示词当Agent已经执行。输出格式必须真实，外部信息合同见[来源与核实原则](05-AGENT-AND-RESOURCES.md)。

## 渐进披露是可复用的UI方法

主要任务、结果和关键状态常显；申请说明、低频配置和参数默认折叠，摘要保留当前状态；💡浮层收纳教学。这样保留功能和解释，又让任务主体清楚。错误、必要确认与会影响当前决定的重要提醒不折叠。详见[UI/UX规则](03-DESIGN-SYSTEM.md)及[可交互示例](../examples/progressive-disclosure.html)。

## 可选宋韵主题：把审美转成参数

适用于文旅、人文和阅读类界面的可选方向；采用前和用户确认，不作为社区统一皮肤。保留经典主题，以语义token切换，共用业务逻辑与数据。

| 要素 | 参考值 | 要求 |
| --- | --- | --- |
| 背景/内容 | 绢色 `#f5f3e9` / `#faf9f3` | 低饱和，保留留白 |
| 正文/次级 | 深青墨 `#2f4947` / `#5d716d` | 不因浅雅牺牲阅读对比 |
| 强调/辅助 | 石绿 `#648f82`、天青 `#e5edf0`、浅黄 `#f0edda` | 主行动清楚，状态仍有文字 |
| 字体 | `FangSong, STFangsong, "Songti SC", serif` | 缺字体有回退，不强制外网下载；大字模式一起考虑 |
| 编排 | 正文16–18px，约1.8行高；组间28–40px；1px细线 | 按任务分类与对齐，不靠卡片堆叠、过多阴影或缩字塞内容 |

可复用提示词：“以书卷排版与边角留白组织信息，使用绢纸底、天青石绿与深青墨字，仿宋/宋体有系统回退；主任务清晰、细线分隔、少阴影。按业务容器响应，非核心说明折叠，辅助教学按需展开；保持正文、状态、焦点与错误可读。”

## 可选配图：生成、落位和加载一起设计

提示词明确用途、风格、透明背景、边角构图、细节密度与色调；保存实际工具、提示词、来源/授权和资源manifest。工具未开放模型参数时不虚称指定型号。图形意象和真实器物/历史作品的陈述分清。

生成图保留alpha并压缩到合适尺寸；功能图标优先可缩放线图，装饰图不承担状态意义。首屏右下角等位置应以标题区受控定位实现，不能靠长页面末尾或大段空白；预留避让区，约束尺寸，窄面板收小或隐藏，装饰 `aria-hidden`。四季花木可以对应页面，但不强制所有主题使用相同图案。

验收覆盖：透明边缘/实际像素、首屏可见性、文字/按钮避让、窄面板与大字、打包清单、资源路径/MIME和真实响应。文件存在不是加载成功，加载成功也不证明布局合适。

## 用更少的重复检查完成交付

位置类任务的供应商适配可复用[高德POI指南](12-AMAP-POI.md)：申请配置折叠、端点/版本白名单、坐标系、分页范围、类型归一化、候选确认、地图降级及独立的Agent工具核验。它是按需能力，不把某个地点类型或业务Key复制成社区默认。

README、CHANGELOG、package、CLI与构建产物版本一致；记录已完成检查的版本和影响范围。已确认的手工结果直接复用，只有改动、失败或缺项才补验。工作台市场投稿采用[独立市场流程](10-MARKET-PUBLISHING.md)，不能用Git push替代，也不必反复电脑操作开发者已经验证的项目。
