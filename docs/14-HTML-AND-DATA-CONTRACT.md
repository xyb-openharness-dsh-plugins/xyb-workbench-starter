# 先审HTML工作台，再实现业务；模型独立于页面

适用所有社区workbench项目。用户目标/场景/流程作为设计起点，经设计者对齐和SPEC关键对话后，必须先交付**可打开、可点击的HTML交互工作台**，由用户确认对应模块后再开发生产功能。静态截图、空模板、文字规格和生成成功不能替代该确认。

## 顺序与确认范围

1. 研究/场景与SPEC，先拟稳定领域关系和候选数据合同，不将页面字段直接冻结为表。
2. 制作本地HTML原型，模拟数据明确标记；记录原型路径、版本/hash、覆盖页面与功能ID。至少走通核心任务及相关二级页、弹窗、草稿/异常/结果回顾，兼顾窄窗/大字/键盘。目标宿主未可用时明确预览环境，不声称已在Desktop实测。
3. 展示实际HTML路径和操作路线，收集用户反馈，记录明确确认人/日期、版本/hash、模块/行为范围和未确认项到docs/PROTOTYPE-REVIEW.md与PARITY。只确认首页不等于全站冻结；后续按模块确认、实施。
4. 对已确认模块细化/复核SCHEMA与API合同，再实现仓储/迁移/API、共享组件与完整模块。已有starter注册/健康壳可保留，不把它当产品功能已确认。UI演示/MockAdapter不等于服务/数据库实现。

实际预览受环境限制时交付HTML并标未验证，可继续静态设计/数据合同讨论；不能绕过工具安全限制或伪造预览证据。若用户当前明确改变流程，按会话授权执行并记录。

## 可演进数据模型

领域事实/证据/来源与核对、主体/作者/权限、计划/实际事件、Agent任务/结果/快照、文件/产物分别建模。稳定ID/revision/外键/时间精度/单位是核心合同；页面、Tab、步骤、卡片展开和模块顺序是易变读模型/交互状态。前端通过用例/命令API写入，禁止直接保存整页state为患者/业务真相。

版本化读模型适配页面，不复制多份事实。普通指标新增走定义目录，有界扩展必须有schema/version/类型/校验，不能用无限JSON回避关系。流程改变不应迫使用户重建档案；真实语义或关系变化才递增迁移，保留备份/失败恢复/旧客户端策略，不清库。

候选提取、用户接受和临床/专业真实性不同；派生结果继承来源revision、核对状态和权限。草稿/正式层、修订失效、导出/记忆传播、并发revision/幂等均需合同。数据架构可在HTML确认前讨论，但不把未确认页面冻结为生产schema。

## 必备的演进走查

页面移位/拆合而事实不变；先问后导入与先导入后问复用同一主体/记录；新增普通指标不改表；源纠正后跨页一致/历史快照标旧版；重复命令/并发冲突可恢复；旧库迁移失败可还原。参见docs/04-DATA.md和templates/SCHEMA.md。

## 工作流定义版本与旧实例

流程有独立的定义版本、实例状态和转换原因/时间，明确插入、跳过、取消、重开与并行步骤时已有实例怎样继续；页面步骤不拥有事实。按实际复杂度保存必要历史，不强制通用工作流引擎或全量事件溯源。数据迁移失败的恢复与旧应用回退分别验证，备份需一致性快照，不能删库兼容。
