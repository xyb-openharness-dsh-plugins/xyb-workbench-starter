# 多轨并列与指标卡：A/B/C 轨怎么分、卡片怎么长、窄屏怎么退

> 来源：小肝宝（HCC）v0.2.0–v0.2.1 两轮落地，用户原话「卡片自适应效果，以及内容结构，分 A/B/C 轨道的思路非常好，可以保存为脚手架经验」。
> 一句话：**轨道是"不可通约的量各自独立"，卡片是"一个指标的一问一答"，自适应是"宽度先变列数、再变内容密度"。**

---

## 0. 什么时候需要多轨，而不是一个大看板

只要病种里存在**两个不可能相加的量**，就必须分轨。典型触发：

| 触发信号 | 例子 |
| --- | --- |
| 同一患者、同一时间，两类数值单位与临床含义完全不同 | HCC 的肝功能储备（g/L、μmol/L、INR）vs 肿瘤负荷（结节 mm、AFP ng/mL） |
| 其中一类"越差"会限制另一类的处置，但不能折算成一个分数 | 肝功能差的人肿瘤小，也可能不能手术 |
| 存在第三条独立风险线，塞进任一条都会被误读 | 门脉高压：既不是肝功能评分项，也不是肿瘤负荷 |
| 分型系统并存，官方不换算 | BCLC 与 CNLC 2022 并列 |

**反例（不该分轨）**：只是采集时间不同、单位相同的两批数（如两次不同医院的血糖）——那是"来源/方法"维度，不是轨道。

## 1. 轨道命名与硬约束

命名用字母 + 一句"它是什么"，不要用"模块一/模块二"：

```
A 轨 · 肝功能储备      ← 决定"能不能承受治疗"
B 轨 · 肿瘤负荷        ← 决定"治哪里、还剩什么手段"
C 轨 · 门脉高压        ← 独立风险线，不并入 A 也不并入 B
```

四条硬约束（写成代码里的注释与断言，不只写在文档里）：

1. **永不加总**：不出现总分、综合评分、健康指数；`sum(a,b)` 在这个病种里就是错的。
2. **永不折算**：不做"A 差 1 分等于 B 差多少"的换算，也不做加权。
3. **各自独立归一化**：同屏双轨图各自缩放，纵轴不共享；共享纵轴等于暗示可比。
4. **分类变量只画节点**：Child-Pugh 分级、LI-RADS、Vp 是类别，不做折线趋势、不算差值。

> 判据：一个页面如果能让用户算出"我总体几分"，说明轨道没分开。

## 2. 卡片的固定结构（正面 / 背面）

### 2.1 正面：一个指标的一问一答

信息层级固定六段，顺序不换：

| 段 | 内容 | 为什么必须在 |
| --- | --- | --- |
| ① 类别眉题 | 小圆点（轨道色）+ 组名，如「安全线 · 血常规」 | 用户先知道"这是哪条线"，再看数 |
| ② 指标名 | 「血小板」，不写缩写 | 缩写只在医生语境里成立 |
| ③ 最近值 + 原报告单位 | 大号 80，小号 10⁹/L | 单位必须来自原报告，不换算成"更方便"的单位 |
| ④ 与前次比较 | ↑ / ↓ / → + 绝对差值 | 只给差值，不给"好/坏"判断 |
| ⑤ 一句说明 | 「在 HCC 里它同时是门脉高压的线索，两件事分开读」 | 276px 固定高，中段不填就空一大块；写边界比留白诚实 |
| ⑥ 记录次数 / 最近采样日 / 来源 + 翻转提示 | 「8 次记录 · 2026.10.14 · 血常规 · 点开看趋势」 | 可信度与出处，永远和数在一起 |

**不在正面出现的**：分级徽章压在数值旁边当结论（徽章只表达"落在 CTCAE 哪一级"，不是"要不要处理"）、趋势图（放背面）、任何"建议"。

### 2.2 背面：只有趋势与依据

| 段 | 内容 |
| --- | --- |
| ① 指标名 + 「最近 N 次」 | 让用户知道看的是哪一段 |
| ② 独立 SVG 折线 | 横轴按**真实采样日期比例**，不按点序号等距；单点只画点、写明"只有 1 次记录，暂不连线"；缺值不补 0 |
| ③ 分级/区间依据 | 「对照 CTCAE v5.0 血小板减少：本值落 1 级；该级区间 ≥75 且 <125 10⁹/L」 |
| ④ 脚注 | 「仅回顾已记录的值 · 点击返回」 |

**不要**在背面加大按钮（"查看详情""返回正面"）；整卡点击即可，键盘 Enter 等价。

## 3. 3D 翻面合同（可照抄）

```css
/* 外卡：透视与尺寸 */
.mcard{display:block;width:100%;height:276px;padding:0;border:0;background:none;
  perspective:1100px;min-width:0;cursor:pointer;font:inherit;color:inherit}
/* 内层：承载旋转 */
.mcard-inner{position:relative;display:block;height:100%;
  transform-style:preserve-3d;transition:transform 480ms cubic-bezier(.2,.7,.2,1)}
.mcard[aria-pressed="true"] .mcard-inner{transform:rotateY(180deg)}
/* 两面：绝对定位 + 背面预转 */
.mface{position:absolute;inset:0;display:flex;flex-direction:column;padding:20px;
  border:1px solid var(--line);border-radius:18px;background:#fff;overflow:hidden;
  backface-visibility:hidden}
.mface.back{transform:rotateY(180deg);background:linear-gradient(165deg,#fdf7f2,#fbfaf7)}
@media (prefers-reduced-motion:reduce){ .mcard-inner{transition:none} }
```

JS 侧三条（比 CSS 更容易错）：

1. **状态存 key，不存 DOM**：`state.flipped = new Set([code])`。整块 `innerHTML` 重建后按 key 复原，否则一换页翻面就丢。
2. **点击只改属性，不重绘**：改 `aria-pressed` + 隐藏面的 `inert`/`aria-hidden`，直接设 `inner.style.transform` —— 重绘会打断 480ms 过渡。
3. **组件只有一份**：同一页面里"看板的卡"和"指标页的卡"必须是同一个函数。小肝宝曾给看板另写了一套近似 markup：
   有 `data-action="flip"` 却**漏了 `data-code`**、内层也是旧类名，结果点击后每一环都"成功"、就是不动，
   用户判定"所有卡片都是静态的"。近似版迟早漏参数。

## 4. 自适应：先变列数，再变密度

### 4.1 两层断点

```css
.metric-grid{display:grid;grid-template-columns:repeat(2,minmax(0,1fr));gap:16px}
@media (max-width:1080px){ .metric-grid{grid-template-columns:1fr} }
```

- **960–1440px**：两列。这是家族统一档。
- **<960px**：一列，卡片仍 276px 高（高度不随宽度缩，否则正反面信息会被裁）。
- **不做三列以上**：三列会把「一句说明」挤成两行，276px 装不下，最后只能删内容。

### 4.2 内容密度怎么退

| 宽度 | 退什么 | 绝不退什么 |
| --- | --- | --- |
| 一列 | 眉题可省略轨道色点、说明缩到一行 | 数值、单位、差值、采样日、来源 |
| 卡片内长文本 | 用 `-webkit-line-clamp` 截断 + `title` | 不截断"缺参考上限"这类状态词 |
| 侧栏 | 二级导航折成横向滚动条 | 不隐藏二级（隐藏等于功能消失） |

### 4.3 断言（无头实测，别靠肉眼）

```js
// 三档宽度都要跑；每档断言三件事
{cols: 2, overflow: false, h: 276}   // 1440
{cols: 2, overflow: false, h: 276}   // 1080
{cols: 1, overflow: false, h: 276}   // 860
```

`overflow` 判 `document.body.scrollWidth > innerWidth`；`h` 判外卡高度，任何一格变化都说明内容被挤出去了。

## 5. 卡片与轨道的接线

一张卡属于哪条轨，由**数据**决定，不由页面写死：

```js
{ code:'platelets', group:'安全线 · 血常规', track:'safety', color:'#8a5a0c', /* … */ }
```

- 分组顺序 = 轨道顺序（A → 安全线 → B → 营养），页面上不做第二处排序；
- 一张卡只属于一条轨；跨轨的指标（如血小板既是血常规又是门脉高压线索）**归一条轨、在说明里写另一层含义**，不要在两处重复出现；
- 轨道色只用在眉题圆点与折线，不用于整卡背景——整卡染色会让六张卡变成六个色块，扫读反而变慢。

## 6. 验收清单（12 条）

- [ ] 页面里没有任何"总分/综合指数/健康评分"
- [ ] 双轨图不共享纵轴，各自标注量纲
- [ ] 分类变量只有节点，没有连线
- [ ] 每张卡正面六段齐全，背面有趋势或明确的"只有 1 次记录"
- [ ] 缺测显式写"没有记录/缺测"，不显示 0
- [ ] 单位来自原报告，未做换算
- [ ] 分级徽章只在 ≥1 级出现（0 级挂徽章会让正常值刷满，反而看不出异常）
- [ ] 翻面状态存 key，换页回来仍保持
- [ ] 点击只改属性不重绘，过渡 480ms 完整
- [ ] 隐藏面 `inert` + `aria-hidden`，Tab 不会停到看不见的一面
- [ ] `prefers-reduced-motion` 下直接切终态
- [ ] 1440 / 1080 / 860 三档：列数 2/2/1，无横向溢出，卡高恒定 276

## 7. 边界

- 276px 是家族约定值，不是"最好看"的值；改它要同时改 §6 的三档断言。
- 轨道数不是越多越好：三条以上通常说明其中一条该降级成"某轨内的一个分页"（小肝宝把门脉高压留在 C 轨，是因为它有独立的出血/套扎/β 受体阻滞剂事实，不是因为它"重要"）。
- 本文只管呈现与结构；数值分级口径见 [23-METRIC-GRADING-AND-ALERTS](23-METRIC-GRADING-AND-ALERTS.md)，一图秀绘制规则见 [16-ONE-CHART-SPEC](16-ONE-CHART-SPEC.md)，完整翻面设计说明见 [24-METRIC-TREND-TAB-DESIGN](24-METRIC-TREND-TAB-DESIGN.md)。
