# README 截图规范：测试截图入 README，说明关键功能（默认生效）

> 来源：用户 2026-10-25 指示——「以后系统测试过程中，截图可以加入 readme，丰富内容，说明关键功能，这个加入到开发脚手架开发流程和规则中。默认启动时规则生效。」
> 本规则**默认启用**：从下一个癌种起，README 必须带关键功能截图；存量仓在下次发版时补齐。

## 1. 什么时候截图
- **G2 原型签认后**：从 `docs/shots/` 精选原型截图入 README（设计态）。
- **M6 装机后**：用真机截图替换/增补（真机态优先，标注"DSH Desktop 实机"）。
- **每次发版前**：刷新截图版本（图内版本号与 README 版本一致）。

## 2. 截哪些（每仓至少 4 张，另加 1 张展开态）
1. **看板**（双主体入口/四点位）——回答"我现在该做什么"；
2. **本癌种差异化的第一页**（如 MEL 自查档案肢端卡 / THY 碘131 / MPM 石棉材料 / GBM 电场）——回答"这个工作台与别的有什么不同"；
3. **一图秀**——回答"变化发生在哪一步"；
4. **关键红线页**（如 MEL 导出私密过滤 / THY 材料零建议 / GBM MRI 并列）——虚线/常驻句可见；
5. **折叠/展开态**（治疗路径折叠卡等交互结构，收/展各一张）。

## 3. 放哪、怎么命名
- 目录：`docs/screenshots/`（与 `docs/shots/` 走查原图分开——README 用精选件）。
- 命名：`readme-<功能>-<版本>.png`（如 `readme-treatment-pathway-0.3.1.png`）。
- README 引用**相对路径**（`docs/screenshots/…`），合并前逐张验证文件存在（破图=返工）。

## 4. 截图质量与红线
- 1440 宽、浅色主题、真实页面渲染（**不是设计稿/手绘图**）、顶部版本号可见；
- 只用演示数据；**不含真实患者信息**；私密内容（FCR/身体意象/证言人）不得入图；
- 一张图只讲一个功能；图下一句"这个功能回答什么"（患者语言），不写实现细节。

## 5. README 结构（固定五段）
```
# 名称（品牌 + 病种）
一句话定位 + 不做声明（不诊断/不建议）
## 关键功能（截图墙：每张图 + 一句患者语言说明）
## 怎么用（安装：Desktop 本地 tgz / profile pnpm add；首次先新建会话）
## 数据与口径（本机优先；登记状态未核实；version）
## 开发（check/probe 命令、docs 索引）
```

## 6. 验收（进 check 链，可断言）
- `check-readme-assets.mjs`（随 init 下发）：README 引用的每个图片路径存在且 <2MB；截图数量 ≥4；文件名含版本；`docs/screenshots/` 非空。
- 合并/发版前人工目视：无破图、无 PII、版本号与 VERSION 一致。
