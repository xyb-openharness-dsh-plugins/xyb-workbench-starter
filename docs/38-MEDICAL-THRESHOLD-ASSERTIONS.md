# 38 · 医学判定口径的断言化（阈值类逻辑）

> 状态：生效（默认规则）。来源：2026-10-26 AML v0.2.0 独立评审实测。
> 适用：任何"按阈值把患者记录分流到不同处置"的功能——发热、低血糖、出血分级、肾功能分期、剂量调整线。

## 0. 一句话

**文案里写对的定义，不等于代码按那个定义在判。** 阈值类逻辑必须被单独抽成可执行函数并配断言，
否则最典型的退化形态是：定义写「≥38.0 持续 >1 小时」，代码写 `v >= 38.3 || v >= 38.0`——
后者在数学上等价于 `v >= 38.0`，时长条件被整个丢掉。

## 1. 为什么必须有这条

AML v0.2.0 实测（P0）：

```js
// 错：38.3 或 38.0 —— 等价于 v >= 38.0
if (val >= 38.3 || val >= 38.0) feverFlag(ts, val, v.author);
```

- **文案是对的**：弹窗里写着「≥38.3℃（或 ≥38.0℃ 持续>1h）」。
- **探针是全绿的**：所有断言都在验"弹窗会不会弹"，它确实弹了。
- **只有逻辑是错的**：单次 38.1℃ 也弹「这是急症信号」。

后果不是"多弹一次窗"，而是**让患者对急症提示脱敏**：反复误报之后，真正 38.5℃ 时会被当成又一次误报。
这类缺陷在医学上是 P0，在任何静态检查里都不显眼。

## 2. 三条硬规则

### 2.1 阈值判定必须是一个可单独执行的纯函数

```js
/* 返回 { level: 'none' | 'watch' | 'fever', why } —— 只做分流，不做医疗建议 */
function classifyTemp(ts, v, priorTemps) { ... }
```

- **不许内联在事件处理里**。内联了就没法在 Node 里单独跑，只能靠正则猜——而正则猜不出等价变换。
- **返回值必须带 `why`**（为什么判成这一档，含具体分钟数/数值）。这行 `why` 要显示在弹窗里：
  患者看到"因为 38.1℃ 已持续 92 分钟"比看到"这是急症"更能理解，也让我们自己无法含糊。
- **多档而不是布尔**。`none / watch / fever` 三档比 `fever: true/false` 多出的 `watch` 正是
  "未达阈值但需要复测"的那一档——真实临床里这一档最常被忽略。

### 2.2 断言必须覆盖"边界 + 时长 + 无效值"三类

最低用例集（AML 的 `check-fever-rule.mjs` 是参考实现，9 条）：

| 类别 | 例子 |
| --- | --- |
| 边界值 | 恰好在线上（38.3）、线下一位（38.2）、线上一位（38.4） |
| 时长条件 | 跨度 90 分钟（成立）/ 30 分钟（不成立）；更早那条是否也达阈值（37.9 不计入持续） |
| 无效值 | `NaN`、空串、负数 |
| **元断言** | 把**旧的错误写法**写回来，断言它必须让某条用例失败 |

元断言是这条规则的核心：它证明"这套用例真的抓得住那个退化"，而不是"用例恰好都过了"。

### 2.3 时长类条件必须有"同一事件"的边界

「持续 >1 小时」不是"两条记录时间差 >1 小时"这么简单：

- 要找**同一发热事件**里的更早记录，不能跨事件算（昨晚 38.5 与今早 38.1 不是一次持续发热）。
- 更早那条也必须在阈值以上（37.9 不计入"在 38.0 以上持续"）。
- 时间跨度取"从最早的达标记录到当前"还是"相邻两条"，必须写清并在断言里固化。

## 3. 落地清单

| 落点 | 要求 |
| --- | --- |
| `public/app.js`（或原型） | 判定抽成具名函数，返回 `{level, why}`；阈值写成具名常量（`FEVER_SINGLE`），不写字面量 |
| `scripts/check-*.mjs` | 从源码里抽出该函数在 Node 里真实执行（`new Function` 包常量 + 函数体），断言 ≥6 条用例 + 1 条元断言 |
| `package.json` | 该断言进 `npm run check`，不是可选项 |
| 弹窗/提示 | 必须显示 `why`（判定依据），让"为什么判成这样"可见 |
| 文档 | 在 `docs/` 里写明阈值来源（机构 + 文件 + 版本），并注明"未取得原件"的情况 |

## 4. 反模式（都见过）

| 反模式 | 为什么坏 |
| --- | --- |
| `if (a >= 38.3 \|\| a >= 38.0)` | 等价于 `a >= 38.0`，短路条件里的强条件被弱条件吞掉 |
| `if (a > 38.3 \|\| b > 38.0)` 写成同一变量 | 复制粘贴时把两个不同变量写成一个 |
| 阈值散落在多处字面量 | 改一处漏一处；必须具名常量 + 单一来源 |
| 只在弹窗文案里写全定义，代码只判一部分 | 文案对、逻辑错，所有探针全绿 |
| 断言只数"弹了几次" | 弹窗确实弹了，但判定错——数次数抓不到 |

## 5. 与其它规范的关系

- 与 30 号（窄宽）无关；与 34 号（AI 发送）无关。
- 与 `LESSONS.md` 的「数量对 ≠ 颜色对」「文案对 ≠ 逻辑对」是同一族：
  **断言必须验语义，不能只验计数或存在性。**
- 医学事实本身仍以各项目的 `research-notes/medical-constraints.md` 为准；本条只管"实现是否忠实于那个事实"。
