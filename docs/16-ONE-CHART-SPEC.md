# 一图秀（多指标时间轴）开发规范

适用：单癌种患者/照护者工作台的"一图秀"页，以及任何"多指标 + 治疗节点 + 时间窗"的趋势视图。

不适用：单指标详情图、静态报告插图、需要严格同一 Y 轴的对比图（那类图必须另行定义坐标轴合同，不能套本规范）。

这份规范不是组件库，是**判断标准**：满足 R1–R12 才算做对；只在验收时看"有没有图"不算。

参考实现：乳腺癌工作台 `prototypes/v0.3`（`docs/UI-DESIGN.md` §3）。参考实现是**一个**正确解，不是唯一解；与规范冲突时以规范为准。

## 0. 先定三个合同，再写代码

一图秀做错的根因几乎都不是图表库选错，而是这三个合同没定。

### 0.1 可比性合同

**不同指标之间不可比，不同测量方法之间不可比。**

- 多序列共用一块画布时，每条线按**自身**量纲归一化，不能共用一个 Y 轴刻度。
- 图上必须有一句可见说明（不是 tooltip 里）："每条线按该指标全部记录范围缩放，不代表不同指标数值可比。"
- 同一指标换了单位、测量方法、测量协议（如手工卷尺 vs 生物电阻抗、不同点位），必须断开或拆成两条序列，不能连成一条趋势。
- 派生值（差值、百分比、BMI）只算不存；图中不出现无法回溯到原始记录的点。

反例：把白细胞 4.2 与体重 58 画在同一 0–60 轴上，再配一句"整体趋势向好"。

### 0.2 归一化合同

- 归一化基准取**该指标全部记录**的 min/max，不是当前时间窗内的 min/max。
  否则切"近 3 月"时曲线形状会整体跳变，用户会以为病情变了。
- 零跨度兜底：`span = hi - lo || max(|hi| × 0.08, 1)`，避免除零把点画到画布外。
- 归一化只用于**画线**；tooltip、图例、点标签一律显示原始值与单位。
- 图例给"全期 min–max"，不只给最新值——只给最新值会被误读成"这就是正常范围"。

### 0.3 事实源合同

- 一图秀、指标卡、就诊准备、导出读**同一份**已确认事实，不各存一份数值。
- 图只呈现已核对记录；草稿、待核、私密内容不进图。私密内容（心理、性健康、生育）必须在数据层就被过滤，不能靠前端不画。
- 更正一条记录后，图、卡、摘要同时更新；旧导出标"已过时"。

## 1. 十二条硬规则

每条给"规则 / 为什么 / 判据"。判据要能在浏览器里观察或断言。

### R1 每条线独立归一化，并在图上写明不可比

- **为什么**：多指标同图的价值是"看到时间上同时发生了什么"，不是"比较数值大小"。共用刻度会让小量纲指标变成一条平线。
- **判据**：选 2 个量纲差异大的指标（如白细胞 4.2 与体重 58），两条线都占满纵向绘图区；图上有一句可见的"不可比"说明。

### R2 单点不连线，空窗口给空态

- **为什么**：一个点连不出趋势；两点之间也不一定是线性变化。空白坐标会让人以为是加载失败。
- **判据**：只有 1 条记录时，DOM 中该序列无 `<path>`，只有 `<circle>`，并有"只有 1 次记录，暂不连线"文案；时间窗内无点时显示空态（"这个时间窗里没有所选指标" + 扩大范围/加选指标的入口），不是空 `<svg>`。

### R3 治疗条与数据区分层

- **为什么**：半透明色带压在曲线上会改变线条颜色，用户会以为那是"异常区间"；治疗标签压在 X 轴上会被裁掉。
- **判据**：治疗条固定在绘图区上方的独立行（手术用菱形+竖虚线，药物/放疗用色条+lane）；关掉"治疗节点"后，数据点坐标与曲线路径完全不变（可断言 `d` 属性不变）。

### R4 只标末点，并做三向避让

- **为什么**：每个点都标数值会糊成一片；首点标签最容易和 Y 轴重叠；多条线末端常在同一高度。
- **判据**：每序列只有最后一个点有数值标签；首点不标；标签距右边界 < 46px 时改为 `text-anchor=end` 并向内/向下偏移；多序列按序奇偶错开 ≥11px；截图里无标签互相覆盖、无标签越出绘图区。

### R5 变化标注按指标类型选口径

- **为什么**：康复测量从 0.5cm 到 1.1cm 是"多 0.6cm"，写成 +120% 会制造恐慌；检验值从 4 到 8 用百分比才合理。
- **判据**：指标定义里带 `cat`（或等价类型）；康复/围度类显示绝对变化（带单位，如 `+0.6cm`），检验类显示百分比；阈值可配（默认 20% 或 0.2 绝对量），不是"有变化就标"。

### R6 绘制动画用 `pathLength=1`，点按序错开

- **为什么**：不同路径长度不同，用固定 `stroke-dasharray` 会导致长短线速度不一致，看起来像卡顿。
- **判据**：每条线 `<path pathLength="1">` + CSS `stroke-dasharray:1; stroke-dashoffset:1`，动画到 0；点以 40–50ms 递增延迟淡入；动画结束后 `stroke-dashoffset` 计算值为 0，线完整可见。

### R7 指标选择 ≤4，全量可滚动，窄屏折叠不隐藏

- **为什么**：超过 4 条线无法分辨颜色与走向；16 个指标平铺会把筛选栏撑到屏幕外。
- **判据**：超过上限时第 5 个复选框不可选或有明确提示；指标列表有独立滚动容器（`max-height` + `overflow:auto`）；≤900px 收进 `<details>`，但**能展开**，不是 `display:none`；每项显示最新值，未选状态清晰。

### R8 时间窗、缩放、图例口径一致

- **为什么**：时间窗改了但图例仍写"全期"，或缩放只改可视区不改轴，都会让人读错时间。
- **判据**：切"近 3 月"后，X 轴首末刻度与窗口一致，点数随之减少，图例仍标"全期"；缩放滑杆改变窗口占比且右端锚定最新日期；时间窗内无点的序列不出现在图例里，或有"该窗口无数据"标记。

### R9 点选固定 + 悬停预览 + 可回源

- **为什么**：手机上没有 hover；只看 tooltip 无法把数值带走或核对来源。
- **判据**：悬停显示"指标/值/单位/日期"；点击后出现固定详情卡，含日期、来源、说明与"查看原文"；再次点击或"收起"取消；固定点有 `active` 视觉态；固定点不在当前窗口时给"该记录已不在当前时间窗"而不是报错。

### R10 网格轨道用 `minmax(0,1fr)`，图表独立滚动

- **为什么**：`1fr` 等于 `minmax(auto,1fr)`，会被子元素 min-content 撑破，导致整页横向溢出——这是最常见的移动端事故。
- **判据**：390px 宽下 `document.documentElement.scrollWidth === 390`；发生横向滚动时，滚动容器是图表自身（`.chart-wrap`），标题、图例、筛选栏不跟着横移；表格类内容换行而不是横滚藏列。

### R11 减少动效下保留最终状态

- **为什么**：`prefers-reduced-motion` 的用户要的是"别动"，不是"别显示"。
- **判据**：开启减少动效后，过渡/动画时长 ≤0.01ms，且显式设置 `stroke-dasharray:none; stroke-dashoffset:0`；曲线、点、翻转后的内容都可见；指标卡翻转仍能切换（只是瞬时）。

### R12 可访问性：图有名字，点有内容，键盘能到

- **判据**：`<svg role="img">` 带 `aria-label`，说明"每条线按自身范围绘制"；每个点有 `<title>`（指标/值/单位/日期）；所有可交互元素是原生 `button`/`input`，Tab 可达，Enter/Space 可用；选中态用 `aria-pressed`；颜色不是唯一区分手段（图例有文字名）。

## 2. 指标卡翻转（与一图秀同源的另一半）

指标卡不是"点开在下面插入一块内容"，那是折叠，不是翻转。做错会同时破坏布局与状态。

> **卡片内容与提醒**另见 [23-METRIC-GRADING-AND-ALERTS](23-METRIC-GRADING-AND-ALERTS.md)：按类别分组、用 CTCAE v5.0 做分级对照、看板提醒把"感受"与"指标"两列并置。本节只管翻转的结构与状态，不重复那边的文案纪律。背面放上分级区间与免责后，务必确认固定高度下页脚仍可见（实测踩过被裁）。

结构：

```
button.mcard[aria-pressed]
└ span.mcard-inner
  ├ span.mface.front
  └ span.mface.back
```

硬要求：

| 项 | 要求 | 判据 |
| --- | --- | --- |
| 固定高度 | 卡片外框高度恒定 | 翻转前后 `getBoundingClientRect()` 的 x/y/w/h 完全一致 |
| 真 3D | `perspective` + `preserve-3d` + `rotateY(180deg)` | 翻转中内层 `transform` 为 `matrix3d(...)`，不是 `height` 变化 |
| 状态独立 | 每张卡状态存 `Set`，互不影响 | 翻一张，其他卡 `aria-pressed` 仍为 `false` |
| 不重渲染 | 只切 class 与 `aria-pressed` | 翻转后页面滚动位置、其他卡展开态不变 |
| 信息等价 | 背面给最近 N 次迷你折线 + 首末日期 + 末值 | 背面不是空白，也不重复正面文案 |
| 单点 | 只有 1 次记录时背面写"暂不连线" | 不画一条水平假线 |

## 3. 状态模型

可直接照抄的形状（字段名可改，语义不能少）：

```js
{
  range: '3m' | '6m' | '12m' | 'all',
  zoom: 40..100,                  // 窗口占比，右端锚定最新日期
  sel: [metricCode],              // 最多 4 个
  toggles: { treatment, keypoints, changes },
  pin: { code, date } | null,     // 固定详情
  flipped: Set<metricCode>        // 指标卡翻转，独立于图表状态
}
```

- 筛选变化只重绘图表区域（`#chart-panel`），不整页重渲染——否则会丢焦点、丢翻转状态、丢滚动位置。
- `pin` 用 `{code, date}` 而不是对象引用：记录更正后仍能按主键找回或明确提示"已不在窗口"。

## 4. 渲染分层（从下到上）

1. 网格线与 X 轴
2. 治疗条（独立行）+ 手术竖虚线
3. 数据线（每条独立归一化）
4. 数据点（末点更大）
5. 变化标签 / 末点数值
6. 交互层（透明命中区、固定态高亮）

层序错了会出现"色带盖住曲线""标签被网格线穿过""点无法点击"。

## 5. 规模与性能上限

| 项 | 上限 | 超过时 |
| --- | --- | --- |
| 同屏序列 | 4 | 拒绝第 5 个并提示 |
| 指标总数 | 30（列表可滚动） | 分组 + 搜索 |
| 单序列点数 | 200 | 聚合（按月）并标注"已按月聚合" |
| 重绘范围 | 图表容器 | 不重渲染整页 |

## 6. 验收断言（可直接执行）

| 编号 | 断言 | 方法 |
| --- | --- | --- |
| C1 | 2 个量纲差异大的指标都占满纵向区 | 读两条 path 的 `getBBox()`，高度差 < 10% |
| C2 | 单点不连线 | 该序列无 `<path>`，有 1 个 `<circle>` |
| C3 | 空窗口有空态 | 文本包含"没有所选指标"，不是空 svg |
| C4 | 关治疗节点不改曲线 | 切换前后所有 `path[d]` 字符串相同 |
| C5 | 只标末点 | 每序列数值标签数 = 1 |
| C6 | 标签不越界 | 所有 text 的 bbox 在 viewBox 内 |
| C7 | 康复类用绝对值 | 变化文案匹配 `[+-]\d+(\.\d+)?(cm|kg)`，不含 `%` |
| C8 | 时间窗联动 | 切近 3 月后首刻度 = 窗口首月，点数减少 |
| C9 | 390 无横向溢出 | `documentElement.scrollWidth === 390` |
| C10 | 减少动效仍可见 | 模拟 `prefers-reduced-motion: reduce`，线的 `stroke-dashoffset` 为 0 |
| C11 | 翻转不位移 | 翻转前后卡片 rect 完全一致，内层含 `matrix3d` |
| C12 | 翻转独立 | 单卡 `aria-pressed=true`，其他为 `false` |

断言脚本不要只抽查一页：逐页跑 `scrollWidth`，逐条记录结果。

## 7. 常见错误（真实事故，不是假设）

| 症状 | 真相 | 处置 |
| --- | --- | --- |
| 点卡片后内容在下方展开 | 展开内容是 button 的**兄弟节点**，结构上不可能翻转 | 改成 `button > inner > front + back`，固定高度 |
| 治疗色带压住曲线 | 色带画在数据区 | 治疗条移到独立行，手术用竖虚线 |
| 0.5→1.1 显示 +120% | 百分比口径套在康复测量上 | 按指标类型选绝对/百分比 |
| 首点标签压住 Y 轴、末点互相重叠 | 所有点都标 + 不做避让 | 只标末点 + 三向避让 + 奇偶错位 |
| 390 宽整页横向溢出 | 轨道写 `1fr`（= `minmax(auto,1fr)`）被 min-content 撑开 | 全部改 `minmax(0,1fr)`，图表独立滚动 |
| 抽了几页没溢出就写"移动端通过" | 抽查不是验证 | 逐页断言，失败页记下来 |
| 减少动效后线不见了 | 只改了 duration，没处理 dashoffset | 显式 `stroke-dasharray:none; stroke-dashoffset:0` |
| 切时间范围曲线形状突变 | 用窗口内 min/max 归一化 | 用全期 min/max |

## 8. 与需求审核、闸口的关系

- HVT 需求审核的 **I 层（交互）** 判据里，"图表怎么写"就按本规范 R1–R12 查；只写"展示折线图"记 0。
- G2 HTML demo：C1–C12 是签认的一部分，不是"开发自测"。
- 指标清单与归一化口径属于需求，不属于实现；改口径要走 SPEC 变更，不在代码里悄悄改。

## 9. 落地清单

新项目接入时按顺序做：

1. 填 `templates/ONE-CHART-SPEC.md`：指标清单（含单位、类型、精度）、分类与颜色、可比性分组。
2. 定三个合同（§0），写进 `docs/UI-DESIGN.md`。
3. 实现 R1–R12，逐条对照 §6 断言。
4. 在 `docs/DEMO-CHECKLIST.md` 增加 C1–C12 签认行。
5. 记录与规范的偏离（哪条、为什么、谁批准），不静默偏离。
