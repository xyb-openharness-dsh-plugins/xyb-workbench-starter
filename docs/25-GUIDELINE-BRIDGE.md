# 指南接入工作台：四层刻度尺（出处 / 适用 / 节奏 / 分级）

> 来源：小粉宝乳腺癌工作台 2026-10-21 ~ 10-22 三轮落地（G0 入库 → G1 出处 v0.10.0 → G2 节奏 v0.11.0 → G3 分级 v0.12.0）。本文件把那一轮抽象成**换病种可照做**的规则，页码与表号只作示例，换癌种必须换成本癌种自己那份指南的真实页码。
> 一句话：**指南进产品，不是"库里有份 PDF"，而是把它拆成四把刻度尺，每把都标回页码；第五样东西——处置推荐——指南里有，产品不能拿。**

---

## 0. 先判断：本癌种到底有没有可结构化的指南

不是每个病种都值得接。按四问筛：

| 问题 | 不通过怎么办 |
| --- | --- |
| 有没有**权威且带页码**的中文指南/共识（学会或卫健委发布）？ | 只有英文指南也可以，但界面必须标语种，别让用户以为看到的是国内口径 |
| 这份文件是不是**能拿到原件**（PDF/官方站），而不是二手摘编？ | 二手摘编不能作为阈值来源，最多做"背景阅读"链接 |
| 里面有没有**时间间隔**（随访频率）或**数值阈值**（分级/关注线）？ | 两样都没有 → 只做 G1 出处，不做 G2/G3，别硬造 |
| 版权允许**引用页码与 ≤200 字摘录**吗？ | 页脚写"违者必究"的，摘录上限压到 100 字以内，且原件不入包（见 §6） |

四问全过再动手。任一条过不去，本癌种的指南层就停在 G1 或者干脆不做，**不要用"通用专家共识"凑**。

---

## 1. 四类颗粒必须分开处理（整件事的地基）

同一份指南里混着四种东西，后两种最容易混，混了产品就一定会说出"你应该……"。

| 颗粒 | 指南里的样子 | 能进产品吗 | 进哪一层 |
| --- | --- | --- | --- |
| **结构** | 分型、分期、路径分支 | 只做"记录落在哪条分支"的标签，**不选方案** | 适用层 L2 |
| **节奏** | 时间间隔（每 3 个月 / 每 12 个月） | 能，用户价值最大的一块 | 节奏层 L3 |
| **阈值** | 数值边界（1–3×ULN、450–480 ms、≤100 g/L） | 能，但必须与 CTCAE **并列**、不合并 | 分级层 L4 |
| **处置** | "推荐 / 建议 / 应 / 暂停 4 周" | **不能**改写成产品语句 | 禁止层 X |

判据一句话：**能写成"指南这一条写的是……"的，可以进；只能写成"你应该……"的，一律不进。**

## 2. L1 出处层：每条引用都能回到"哪一版、第几页、哪张表"

### 2.1 落什么

| 数据 | 内容 | 边界 |
| --- | --- | --- |
| 文档元信息 | 机构、版本名、发布日期、页数、sha256、原件文件名 | 与入库登记**逐字**一致（见 §2.3） |
| 条目引用 | 章节号、页码、表号、≤200 字摘录 | 只摘"写了什么"，不摘"该怎么办" |
| 挂靠关系 | 记录 → 引用（多对多） | 不覆盖已有来源，只追加 |

### 2.2 界面固定两段式

```
指南这里写的是：术后 2 年内每 3 个月随访 1 次。（<机构> <版本> · P208 表 9.5）
你的记录是：最近一次复诊 2026-07-12。
```

- 两段**并置**，中间不加"所以""因此""你需要"。加了就是把出处变成结论。
- 出处行永远可以点开落到具体页；页码对不上就等于没有出处。
- 摘录超 200 字就截断并标"节选"，不要为了完整把整段搬进来。

### 2.3 登记三处必须一致（这一条踩过，且是用户当场问出来的）

G1 之后登记会自然分成三份文件，**它们描述的是同一份文档，任何一处漂移都会让界面说谎**：

| 文件 | 装什么 | 谁读它 |
| --- | --- | --- |
| `guidebooks/manifest.json`（或项目内对应登记） | 原件清单：org / version / published / pages / sha256 | 人查、发布检查 |
| `assets/reference/guideline/refs.json` | 条目引用：页码 / 表号 / 摘录 / 说明 | 界面「指南出处」 |
| `assets/reference/guideline/cadence.json` | 节奏与检查项，**自带一份 document 元信息** | 「随访节奏」卡 |

实际事故：`cadence.json` 里发布日期写成 `2025-12`（原件名 `2025CBCS241218.pdf`，manifest 与 refs 都是 `2024-12-22`）、`version` 写成 `2025`（应为"2025 精要本"）、`org` 只写了一个学会、且**缺 sha256**。界面因此显示了一个不存在的版本。

**对策（可直接抄）**：加一条单测，把三处的 `id / version / published / sha256` 拉平比对，不一致就红。

```js
// test/guideline.test.mjs 思路
const manifest = readJson('guidebooks/manifest.json');
const refs     = readJson('assets/reference/guideline/refs.json');
const cadence  = readJson('assets/reference/guideline/cadence.json');
const doc = manifest.docs.find((d) => d.id === refs.document.id);
for (const k of ['version', 'published', 'sha256']) {
  assert.equal(cadence.document[k], doc[k], `cadence.document.${k} 与 manifest 不一致`);
}
```

**第二条**：`refs.json` 的 `notes`（"这项指南怎么写、工作台怎么处理"）**会原样显示给用户**。所以能力一变，notes 必须跟着改。真实事故：v0.12.0 已经能给 ALT / 肌酐分级，notes 还写着"本地未结构化，暂不启用"——等于界面当场声明一个已经不成立的能力缺口。加一条单测：`notes` 里出现"未启用 / 未结构化 / 暂不支持"这类词时，必须对应代码里确实没启用。

**第三条**：notes 挂错节比缺 notes 更糟。真实事故：原写"10.5 与 10.10 均按 ×ULN 分级"，查原文后发现 10.5 只有按 R 值的肝损伤**分型**（肝细胞型 / 胆汁淤积型 / 混合型），**没有 G1–G4**；分级表只在 10.10，而且那张表标题限定"CDK4/6 抑制剂不良反应"。→ 每条 notes 都要写"在哪一节、那一节到底给了什么、工作台怎么用"。

**第四条**：说明条数一多就别挤成一段。7 条说明塞进一个 `<p>` 会有十几行，页面重心被拉走。改 `<details>` + `<ul>`，标题写"这几项指南怎么写（N 项）"。

## 3. L2 适用层：指南"对谁适用"，用记录算出来，不用问卷问出来

- 派生一组**布尔标签**（纯函数，不落事实表）：如"在用某类药""做过某术式""分期到某档"。
- 来源只用**已有记录**：治疗事件的药名/方案码、病理字段、术式。算不出来的一律"未记录"，**不弹问卷补**。
- 用途只有三件：① 决定随访清单显示哪几行；② 决定指标卡"为什么这条与你有关"；③ 决定节奏取通用行还是分期变体行。
- 文案纪律：写「记录里有 X 用药，指南这一条适用于使用 X 的人」，**不写**"你属于高危人群"。

**药名匹配宁缺勿猜**（真实踩过）：只写"化疗"两个字时匹配不到蒽环类，界面要写"没匹配到具体药名"，不能因为"化疗"就假设用了蒽环。这条必须有单测。

**匹配不了的项要明写原因**：适用人群是"某转移灶 >4 枚"这类**本地没有结构化字段**的条件，列进"无法自动匹配"，**不要**默认判成"不适用"——那是替用户下结论。

## 4. L3 节奏层：把"什么时候该查"变成可核对的窗口，不是催办

### 4.1 节点 = 起点 + k × 间隔，不是"上次复查 + 间隔"

这是最容易写错的一条。若按"上次复查 + 间隔"算，用户一条记录都没有时就永远算不出下一个节点，而"我从没复查过"恰恰最需要看到节奏。

正确做法：**节点落在日历格上**。手术日（或确诊日）+ k×间隔，k 取整数。于是：

- 一次都没记过 → 照样能给出"术后 9 个月""术后 12 个月"两个参考节点。
- `next` 只可能是 `later` / `near` 两种；"已过"描述的是 `previous`（配 `daysSince`）。

**月末夹取必须写对**：1 月 31 日 + 1 个月 = 2 月末（28/29 日），**不滑到 3 月 3 日**。`addMonths` 单独一个纯函数 + 单测。

### 4.2 显示带宽是工作台自己的约定，必须标注

`±30 天` 这类"参考窗口"是界面为了让节点可读而加的带宽，**不是指南内容**——指南只写间隔。界面必须写清：

> ±30 天是工作台的显示带宽，不是指南内容；指南只写间隔。

否则用户会拿着"±30 天"去跟医生对，而指南里根本没有这句话。

### 4.3 三条硬边界（写进文件头）

1. **只算参考节点，不排计划**。
2. **不发提醒、不弹通知**：节点只能转成「想问医生的问题」或「我自己的待办」，且新建待办 `due = null`（没有 due 就没有提醒）。
3. **不做分期判断**：分期没记录时只给通用节奏并写明"未按分期调整"；指南里"某分期可放宽"的注，只在分期**明确落在原文列举范围内**时并列一行提示，**主节奏不动**。

### 4.4 出口

参考窗口可一键变「想问医生的问题」或「我自己安排的待办」。**不写"该复查了"**，不写"逾期"。

### 4.5 验收

- 把术后时间改到 3.5 年，窗口从 3 个月变 6 个月。
- 删掉治疗记录后，相关检查行**消失**（而不是变成"不需要"）。
- 手术日改成未来日期，**不伪造节点**，返回"未到"。
- 一次记录都没有时仍给得出两个节点。

## 5. L4 分级层：与 CTCAE 双轨并列，不合并、不取严

### 5.1 先查一件事：两套口径是不是其实一样

本轮最值钱的发现：**已登记的那几项，指南与 CTCAE 的数值边界其实一致**——ALT/AST 的 (1–3)/(3–5)/(5–20)/>20 ×上限、肌酐的 (1–1.5)/(1.5–3)/(3–6)/>6、QTc 的 450–480 / 481–500 / ≥501。

真正的差异只在两处：QTc 的 3 级增量条件（"较基线 >60 ms"）与 4 级定义（心律失常事件）。

所以做"双标准并列"之前，**逐条比对，不要预设"中国指南一定不一样"**。硬造一个差异，用户看到两张表打架，反而更慌。

### 5.2 并列的显示规则

- **卡片正面只显示一个徽章**（主口径，通常是 CTCAE）。两个徽章并排会把卡片变成对照表。
- 背面第二行给指南口径 + 页码：`◇ 指南 1 级 · 1–3×ULN · P227`。
- 两套口径**级差 ≥1** 时，背面加一句"两套口径在这一条上不一致，见 Pxxx"，**不自动取严**。取严＝替医生做判断。
- 口径一致时也别装作有差异，直接写"两套口径在这条上一致"。

### 5.3 四类"其实不是分级"的东西，别混进来

| 指南里的东西 | 实际是什么 | 产品怎么做 |
| --- | --- | --- |
| 关注线（如 Hb ≤110 或降幅 ≥20 g/L） | 提醒关注的线 | 画虚线 + 标"指南关注线，不是分级" |
| 干预阈值（如 PLT ≤10 预防性输注） | 处置门槛 | **不进分级层**，最多折叠原文 |
| 处置阈值（如 LVEF 降 ≥16% 暂停 4 周） | 处置 | 禁止层，只出原文 |
| 风险评分分层（低/中/高危） | 评分 | 不做计算，只展示原始指标 + 原文分层表 |

判据：**问一句"这是 G1–G4 里的某级吗"**。不是，就不要发分级徽章。指南写"关注"不等于"分级"。

### 5.4 OCR 风险

指南原件常是 OCR 出来的，表格偶有串行。**任何进代码的阈值必须人工回 PDF 核对，提交信息写明核对了哪页**；未核对的只做展示、不做计算。

## 6. X 禁止层与版权

### 6.1 处置推荐：看得见，但不生效

- 允许：折叠块「指南原文（Pxxx）」+ ≤200 字摘录 + 页码。
- 不允许：把"暂停治疗至少 4 周""推荐一级预防""Hb≤100 用 ESA"改写成陈述句、要点列表、勾选项、Agent 回答的主句。
- **文案红线扩词**（在指南语境下拦截）：`应该 / 必须 / 建议复查 / 需要治疗 / 暂停用药 / 可以考虑加用`。现有 `check-wording` 加规则即可，自检清单本身要能出现这些词（标 `wording-allow`）。

### 6.2 数据结构化文件的落点

结构化 JSON **必须放 `assets/reference/guideline/`**（随包分发），**不能**放 `guidebooks/derived/`——装机时包目录会整份替换，`guidebooks/` 不入包，装到 Desktop 上就是缺文件。

### 6.3 原件不入包

页脚写"违者必究"的原件：

- `guidebooks/` 不进 `package.json` 的 `files`；`npm pack` 实测文件数与体积要能证明它没进去（例：59 files / 3.4 MB，不含 `guidebooks/`）。
- 仓库 private；转 public 之前必须先移出（历史提交里也有，要清历史，不是只删当前文件）。
- 界面只出元信息 + 摘录，不出整页图、不出连续多页原文。

## 7. 落地顺序（每一步都能停）

| 步 | 做什么 | 停下来的标志 |
| --- | --- | --- |
| **G0** | 原件入库 + `manifest.json`（org/version/published/pages/sha256/来源/是否 OCR/允许用途） | 能回答"这是哪一版、从哪来、能不能引用" |
| **G1** | `refs.json`（页码 + 表号 + ≤200 字摘录 + notes）+ 纯函数 `guidelineRef` / `refLabel`；卡片背面一行 + 页面折叠表格 | 随便点一条出处都能落到页；三处登记一致单测绿 |
| **G2** | `cadence.json`（间隔 + 检查项 + 药名规则）+ 纯函数 `checkpoints` / `treatmentTags` / `buildFollowupPlan`；节奏卡 | 改手术日能改节点；无记录也能给节点；不发提醒 |
| **G3** | 分级扩项（绝对阈值型 + ×ULN 型，见 [23-METRIC-GRADING-AND-ALERTS](23-METRIC-GRADING-AND-ALERTS.md) §2.1） | 缺参考上限时给 `needsUln` 而不是猜 |
| **G3b** | 双标准并列（`gradeStandard` 并存、级差提示、不取严） | 两套口径一致时界面敢说"一致" |
| **G4** | 适用标签 + Agent 检索（回答必带 refId，无命中就说"指南里没这段"） | 无 refId 的回答不许进界面 |

**不要跳步**：G1 没做就做 G2，节奏卡的每行都没有出处，等于把"工作台自己编的间隔"冒充指南。

---

## 8. 不做

- 不做"指南推荐方案"生成、不做治疗路径推荐、不做预后/复发风险计算。
- 不把分级推荐（I/II/III 级）做成产品菜单。
- 不把指南当知识库喂给 Agent 自由作答；只做"检索 → 引用 → 原文"。
- 界面不出现"指南建议你"这种句式；主语只能是"指南这一条写的是"。

## 9. 验收清单

- [ ] **L1-1** 每条引用能落到具体页；页码与 sha256 与 `manifest.json` 一致。
- [ ] **L1-2** 三处登记（manifest / refs / cadence）的 id·版本·发布日期·校验和一致，有单测钉住。
- [ ] **L1-3** `notes` 不出现已失效的"未启用/未结构化"；出现时必须与代码一致。
- [ ] **L1-4** 引用块是两段并置，无"所以/因此/你需要"。
- [ ] **L2-1** 适用标签全部由已有记录算出；算不出的显示"未记录"，不弹问卷。
- [ ] **L2-2** 只写"化疗"时不猜具体药类，有单测。
- [ ] **L2-3** 缺结构化字段的适用条件列"无法自动匹配"，不判"不适用"。
- [ ] **L3-1** 节点 = 起点 + k×间隔；零记录时也能给节点。
- [ ] **L3-2** `addMonths` 月末夹取正确（1/31 + 1 月 ≠ 3/3）。
- [ ] **L3-3** ±30 天等带宽在界面标明"不是指南内容"。
- [ ] **L3-4** 无提醒、无通知；待办 `due = null`；分期未记录时标"未按分期调整"。
- [ ] **L4-1** 正面单徽章，背面一行指南口径 + 页码。
- [ ] **L4-2** 级差 ≥1 时只说"不一致"，不取严。
- [ ] **L4-3** 关注线/干预阈值/处置阈值/风险评分**没有**被做成分级徽章。
- [ ] **L4-4** 进代码的阈值都有人工回 PDF 核对记录。
- [ ] **X-1** 处置类原文只在折叠块，红线词表已扩，扫描通过。
- [ ] **X-2** 结构化 JSON 在 `assets/reference/guideline/`；`npm pack` 证明 `guidebooks/` 未入包。
