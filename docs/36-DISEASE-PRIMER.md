# 36 · 疾病概要（「?」入口）

> 2026-10-25 用户提出，全家族适用。
> 用户原话：「在每个癌肿项目的 readme 介绍 + 工作台看板，添加一个？图标：点击后介绍疾病精炼概要，
> 包括定义 - 医学资料规范和指南情况，目前治疗全景概要介绍，以及发展趋势。
> 对 Downloads 下所有工作台，补充这个动作，另外把这个要求加入到 starter 脚手架里。
> 纳入要求，以及开发后审计两个节点。」

## 0. 一句话

每个工作台要有**一处**能回答「我得的这个病大概是什么、依据什么文件、现在世上大致有哪些手段、这几年在变什么」，
且**这一处的内容与 README 同源**：README 里能读到，看板右上角的「?」能展开成整页。

## 1. 为什么要有它

患者第一次打开工作台，看到的是「我的记录」。但一个人要能读懂自己的记录，先得知道这个病的**公共背景**：
这个病怎么定义、医生依据哪份指南、指南里列了哪些治疗手段、这些年指南与药物在往哪个方向动。
这些都不是「你的判断」，是**公开信息的整理**——正好落在三层信息边界的第 ② 层，属于本台该做的事。

反过来，如果工作台只讲「你的数据」不讲「病的背景」，患者会拿自己的单点数值去猜全局，
那才是真正危险的地方。**给背景，是为了让人少猜。**

## 2. 四条硬约束

### 2.1 固定四段，顺序不变

| 段 | key | 写什么 | 不写什么 |
|---|---|---|---|
| ① 定义 | `definition` | 这是什么病、WHO 分类口径、常见亚型、好发部位/年龄段的**事实陈述** | 不写「预后差」「恶性程度高」这类判读 |
| ② 医学资料规范和指南情况 | `evidence` | 表格：机构 / 文件全名 / 版本或年份 / 是否取得原件 | 不写「本指南推荐你…」 |
| ③ 目前治疗全景概要 | `landscape` | 指南**列举**的手段，按期别/线序分组；每项只写「是什么、用在哪一期」 | 不排序、不比优劣、不给 ORR/OS 对比表 |
| ④ 发展趋势 | `trend` | 只写**已发生的事实**（见 2.3 白名单） | 不预测、不推荐、不评价 |

四段缺一段即不合格。段内没有内容时写「本台尚未整理」，**不许删段**——删段会让人以为这个病没有这块。

## 2.5 指南原件必须可点（2026-10-27 用户要求，硬约束）

§2.1 ②段的「是否取得原件」列**不允许只写文字**：

| 行状态 | 硬性要求 | 违规样例 |
| --- | --- | --- |
| 已取得原件 | `url` 字段必须存在且为 `https://` 链接（官方 PDF / DOI / PMC / 官网页），渲染为「原件已取得 · 打开/下载 ↗」可点 | ~~「已取得（全文可读）」纯文字~~ |
| 未取得原件 | `secondaryUrl` 必须存在（二次来源链接），渲染为「未取得原件，据二次来源 ↗」可点 | ~~「未取得原件，据二次来源」纯文字~~ |

- 链接由**搜索取得**（官方出版方页 > PMC/DOI > 权威转载），入库前逐条点开验证可达；
- 模式层（disease-primer.js `sourceLine`）对缺链接的行渲染红色「缺链接，违反 36 号 §2.5」标记——评审一眼可见；
- `href` 只接受 `https://`（`javascript:` 等一律丢弃）。

## 2.6 看板状态卡（疾病概要的触发器，2026-10-27 用户点名固化）

看板首卡的**病程状态卡**是疾病概要浮窗的入口，结构四件（缺一即不合格）：

1. **卡头**：`D+N 状态卡 · 距<下一阶段>` 小字（eyebrow 层）；
2. **大字天数**：`第 N 天`（相对锚点日：移植=Day 0 / 诱导=D1；数字 28px 级、品牌色）；
3. **现状行**：当前阶段名（原文）+ 状态（如"已结束 · 恢复期"）+ `下次：<日期>（<事项>）`；
4. **出口按钮排**：主按钮=进入当前阶段核心页（如「看诱导日历（按天）→」）；副按钮=`疾病概要：<病>是什么？`（打开本浮窗）。

状态卡的数字一律由锚点日计算派生，不手填；无锚点数据时整卡显示「待初始化」并指向三步向导（三步初始化见各仓 onboarding）。

### 2.2 全部属于第 ② 层（解释），一句判断都不生成

- 可以写：「NCCN STS V3.2026 把 … 列为可选手段之一。」（有机构、有版本、有原文）
- 不可以写：「这个方案更适合你。」「A 药比 B 药效果好。」「你的分期属于早期。」
- 治疗全景段末尾**必须**有一句固定出口：
  「以上是文献与指南里列出的手段，按病期与线序排列，**不代表任何一项适合你**。选哪一个，这一句需要问你的医生。」

### 2.3 「发展趋势」是本条最容易越界的一段，白名单写死

**只允许**五类内容，每类都必须带日期或版本号：

1. **指南版本更替** —— NCCN V2.2026 → V3.2026（2026-03-12 生效）
2. **监管批件** —— NMPA / FDA / EMA 批准某药用于某适应症（批准日期、批件号可选）
3. **在研登记的规模与阶段分布** —— 「截至 2026-10，中国药物临床试验登记平台可检索到 STS 相关登记 N 条，其中 I 期 x 条 / II 期 y 条」（**只报数量与阶段，不报「即将上市」**）
4. **分类体系更新** —— WHO 第 5 版（2020）取代第 4 版（2013）
5. **指南结构变化** —— 「2025 版新增独立章节：…」（只写「新增了什么章节」这一事实）

**禁止词表**（`scripts/check-wording.mjs` 之外，本模块另有一套，见 `check-conformance.mjs` 的 `primer/趋势段`）：

> 有望 · 即将 · 前景 · 未来可期 · 突破性 · 颠覆 · 革命性 · 首选 · 优于 · 疗效更好 · 建议使用 ·
> 强烈推荐 · 治愈率 · 生存期延长 · 大幅提高 · 迎来新选择 · 里程碑（作为评价用时）

需要表达「在研数量多」时，写数字，不写形容：「登记 47 条，其中 III 期 6 条」。

### 2.4 来源栏：机构 + 版本 + 是否取得原件

每段末尾一行 `来源`，格式固定：

```
来源：NCCN · Soft Tissue Sarcoma V3.2026（2026-03-12）· 原件已取得 · 页码 P12–P18 ｜ WHO · Classification of Tumours 5th ed.（2020）· 原件已取得 · 页码待核
```

- 没拿到原件时必须写「**未取得原件，据二次来源**」，并注明二次来源是什么（如「据 CSCO 2025 版引用」）。
  这一条与家族既有口径一致：**没看到原件，不许假装看到了。**
- 页码不明写「页码待核」，不许编。
- **自采登记数据算一手（2026-10-25 定）**：直接从 ClinicalTrials.gov / ChiCTR / ChinaDrugTrials 拉下来的快照，
  在 `original` 上记 `true`，note 写「自采快照；第三方原件未存档」。它与「指南原件未取得」**分开计**——
  不要把整台都写成「未取得原件」，那会把「我确实拉到过这批登记」也一并否认掉。

## 3. 两个落点，一份数据

### 3.1 README：`## 疾病概要`

位置固定在 README 的**项目简介之后、开发顺序之前**。四段用小标题 `### 定义` / `### 医学资料规范和指南情况` /
`### 目前治疗全景概要` / `### 发展趋势`。

README 里是**正文**（可读的段落），不是「详见看板」——因为读 README 的人（评审、维护者、外部访客）
不一定会打开原型。

### 3.2 看板：顶栏「?」按钮

- 位置：顶栏右侧 `.top-actions` 内，版本号 chip 左侧（`.top-actions` 不存在时退到 `.topbar`，
  再不存在时浮在右上角，见模块兜底逻辑）。
- 形态：**整页视图**（32 号），不是弹窗。理由：四段内容必然超过 1.5 屏，弹窗装不下（用户原话「现有弹窗空间太小」）。
- 展开后与 README 同源：数据来自 `prototypes/vX/primer-data.js` 的 `window.DISEASE_PRIMER`，
  README 段落由同一份数据人工同步（或由脚本生成），**两边四段标题必须一致**（`check-conformance.mjs` 会核对）。

### 3.3 为什么不用 `<dialog>`

`<dialog>` + `showModal()` 会给焦点与 `Esc` 一套默认行为，但**不写 history**：
用户按浏览器返回键会直接退出工作台，而不是收起概要页。这与 32 号定的「history 是导航栈唯一真源」冲突。
所以本模块自带 overlay，open 时 `pushState`，关闭走 `history.back()`。

## 4. 参考实现

| 文件 | 作用 |
|---|---|
| `assets/patterns/disease-primer.js` | 无依赖经典脚本（IIFE），暴露 `window.DiseasePrimer` |
| `assets/patterns/disease-primer.css` | 只定义结构与密度，颜色全部走项目令牌 + 兜底 |
| `examples/disease-primer.html` | 可跑的最小示例（含一份演示数据） |
| `templates/DISEASE-PRIMER.md` | 项目实例模板（四段填空 + 来源栏 + 验收表） |
| `scripts/probe-disease-primer.mjs` | P1–P8 验收探针 + `--self-test` 反向对照 |

### 4.1 用法（三步）

```html
<!-- ① 样式：放在项目 style.css 之后 -->
<link rel="stylesheet" href="primer.css">

<!-- ② 数据：必须先于模块加载 -->
<script src="primer-data.js"></script>

<!-- ③ 模块：body 末尾 -->
<script src="primer.js"></script>
```

不写按钮也可以——模块会自动把「?」插进 `.top-actions`。要自己控制位置时，在 HTML 里放一个带
`data-primer-open` 的空按钮，模块会接管它。

### 4.2 数据结构

```js
window.DISEASE_PRIMER = {
  brand: '小韧宝 SarcPal',
  name: '软组织肉瘤',
  en: 'Soft Tissue Sarcoma（STS）',
  updated: '2026-10-25',
  sections: [
    { id: 'definition', title: '定义', intro: '一段话。', points: ['…', '…'], sources: [
        { org: 'WHO', doc: 'Classification of Tumours, 5th ed.', version: '2020', original: true, page: '页码待核' } ] },
    { id: 'evidence', title: '医学资料规范和指南情况', intro: '…', table: { head: ['机构','文件','版本 / 年份','原件','本台用途'], rows: [ ['NCCN','Soft Tissue Sarcoma','V3.2026（2026-03-12）','已取得','分期与治疗路径的出处'] ] }, sources: [...] },
    { id: 'landscape', title: '目前治疗全景概要', intro: '…', groups: [ { label: '局限期', points: ['…'] } ], sources: [...] },
    { id: 'trend', title: '发展趋势', intro: '…', points: ['…'], sources: [...] }
  ]
}
```

`sections` 少于 4 段、或四个 `id` 不齐，模块照常渲染但控制台报一条 `console.warn`，探针判 FAIL。

## 5. 验收（P1–P8）

| 编号 | 判据 | 怎么测 |
|---|---|---|
| P1 | 顶栏存在可点的「?」，`aria-label` 说明四段内容 | 读 DOM |
| P2 | 点击后出现整页面板，四段标题齐全且顺序正确 | 读 DOM |
| P3 | 面板可见区高度 ≥ 视口 90%（是整页不是弹窗） | 量 `getBoundingClientRect` |
| P4 | 面板打开时 URL 多一条 history 记录；`history.back()` 后面板收起 | 量 `history.length` + 返回 |
| P5 | 「返回」与「关闭」是两个独立入口，都存在 | 读 DOM |
| P6 | 关闭后焦点回到触发按钮，页面滚动位置不变 | 量 `document.activeElement` 与 `scrollY` |
| P7 | `Esc` 只退一层（不刷新、不离开页面） | 按键后仍在本页 |
| P8 | 数据四段齐全；趋势段不含禁止词 | 读 `window.DISEASE_PRIMER` |

反向对照：`node scripts/probe-disease-primer.mjs --self-test` 必须至少 3 条 FAIL。
只报绿不报红的闸门等于没有闸门（LESSONS 第 13 类）。

## 6. 两个节点（用户明确要求）

| 节点 | 位置 | 内容 |
|---|---|---|
| **① 要求** | `AGENTS.md` 硬约束段 + `prompts/ZERO-TO-DEV.md` M1/M4 必查件 + `templates/DISEASE-PRIMER.md` | 新项目从 M1 起就要把四段写进 `docs/DISEASE-PRIMER.md`，M4 原型上线前必须能点开 |
| **② 开发后审计** | `scripts/check-conformance.mjs` 的 `primer/*` 检查项 | README 有 `## 疾病概要` 且四段小标题齐全；原型有 primer 数据文件与入口；趋势段无禁止词；四段标题与数据一致 |

审计只看**文件与代码**，不看文档自述——README 里写「已加 ? 图标」不算数，原型里没有 `data-primer-open`
或 `primer-data.js` 就是没加。

## 7. 不做

- 不做「个性化解读」：不根据用户档案调整概要内容。概要就是公共背景，对所有档案同一份。
- 不做药物剂量、给药方案、副作用处理——那是治疗相关模块的事，且必须逐条带出处。
- 不做「你适合哪条路」的推荐，一句都不做（第 ③ 层）。
- 不回溯改造**已冻结归档**的历史原型；老项目按「下一轮动到就补」处理（与 32 号同口径）。
  但**README 段落**可以补——它不影响原型稳定性。
