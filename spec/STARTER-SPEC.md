# 小胰宝 / 小x宝社区 Workbench 脚手架规格 v1.0

日期：2026-10-15。状态：已完成（文档、模板与离线工具；Desktop 实机不在本脚手架验收范围）。用户已授权本地创建文档、模板与脚手架；不包含自动推送、市场投稿和正式发布。

## 1. 需求补全

服务对象：会使用 Codex/其他编码 Agent，但不熟悉 DSH、数据建模及桌面插件部署的社区开发者。

核心场景：把已确认的业务需求和高精度 UI 原型，可靠地转成可安装、可回顾、风格一致的工作台。一次任务：复制脚手架 → 确认需求 → spec/功能树/契约 → 共享组件与完整页面 → 成组检查 → 本地包 → Desktop 实测 → 按授权发布 → 复盘。

“无依赖”定义为：文档与模板复制不依赖原仓库路径、云服务、专属技能或第三方 npm 库；初始化和检查脚本只用 Node 内置模块。实际工作台仍需要 Git、Node、DSH Desktop 及其运行时 peers，云解析/MCP/数据更新另按项目声明。

## 2. 方案比较与决定

| 方案 | 优点 | 代价 | 决定 |
| --- | --- | --- | --- |
| 一份长提示词 | 易粘贴 | 全量读历史、规则漂移、缺少验收证据 | 不作为主体 |
| 复制小胰宝完整业务仓库 | 快速看到现成页面 | 医疗业务、密钥、数据库和旧限制随之继承 | 只提取可泛化经验 |
| 分层文档 + 项目模板 + 内置模块工具 | 可离线复制、按需读取、可查来源、减少隐式前提 | 需维护小量模板和验收清单 | 采用 |

## 3. 交付结构

- `AGENTS.md`：短规则入口/开发灵魂；事实来源和授权边界。
- `docs/`：新手流程、DSH 合同、UI/UX、数据、Agent、测试部署、踩坑、来源、复盘与验证。
- `templates/`：需求、spec、功能树/差异矩阵、API/schema、任务、验收、发布与故障记录。
- `prompts/`：初始化、继续开发、UI 核对、交接提示词。
- `assets/`：Logo 来源、主题 token、动效与可访问性要求；不携带患者数据、真实密钥和大型业务数据集。
- `project-template/`：包元数据、patch、服务端健康接口、客户端注册入口；没有预置业务方向。
- `scripts/`：无覆盖初始化、包静态检查、脚手架校验；不自动安装 DSH、不自动启动联网服务。
- `reference/`：官网开发规范快照与来源清单；原型只保留路径/hash/提炼规则，不复制整个病情原型作为通用产品。

## 4. 事实与约束

官网开发规范检索到 2026-10-09 版本；本地官方副本是 09-29。布局须按主任务明确选标准分栏或 customFrame；小胰宝 65/35 仅是已确认个案。项目历史目前只有 0.1.15 初始、0.1.22、0.1.26 三次提交；0.1.23–0.1.25 不编造成独立提交。设计目录中大量文档未提交，来源清单须记录工作区状态与 hash。

原型一致性覆盖内容、二级导航、状态、动作、动效；不能只对齐颜色。运行注册用 `ctx.desktopWorkbenches.register(descriptor, Component)`，不沿用旧指南中的伪 injector 示例。测试与验收区分静态、集成、宿主 UI 和外部服务。

## 6. 范围与后续

本次交付开发方法与脚手架，不修改小胰宝业务代码、不创建新业务工作台、不安装示例包、不发布市场。通用模板仅是可检查的接入起点；它不承诺已兼容所有 Desktop 版本。在线能力和平台分发应在具体项目中选型验证。

## 7. 规格验收

1. 在任意新目录可读取全部社区规范，初始化脚本不依赖原 Downloads 绝对路径。
2. 配置要求用户/场景/核心步骤/完成结果以及明确布局；缺失时停止生成。
3. 对已有目标文件预检查，发生冲突时不部分写入，不覆盖用户文件。
4. 无可用凭据、真实患者数据、node_modules、日志全集或多 MB 数据库混入脚手架。
5. 包校验只宣称静态合同通过，不把它当成安装成功、联网成功或 UI 高保真验收。
6. 文档包括完整功能树、原型版本/hash、差异例外、测试证据、实际版本/profile、回滚和数据保留。

## 8. 用户补充范围：心理支持项目

纳入 cancer-psych-support-workbench 的 SPEC、接入日志、开发日志和修复提交；只读保留未提交修改。提炼 service 上下文故障、安装副本核验、generation 投影故障、角色规范到实际 prompt 的追踪和轻量存储选型。模型切换由用户描述，不替代技术根因证据。增加有版本边界的只读归属适配示例、故障注入测试与调试交接提示词。
