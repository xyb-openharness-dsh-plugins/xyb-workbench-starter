# 发布可见性检查（P 层）

HVT 五层检查回答的是"这个场景做出来了没有"。这一层回答另一个问题：

**用户拿到手的那两个界面——HTML 原型首页、装进 DSH 后的应用首页——能不能看出自己在用哪一版？**

它不并入 C（C 仍为 S+M+F+I+A），因为版本号不是某个 HVT 场景的属性，而是**整个工作台的发布属性**。任一 P 项判 0，报告不能写"可发布"，但也不需要因此把某个场景的 C 降级。

## 为什么单列一层

版本号缺失不会让功能跑不起来，所以它在需求评审里几乎总被跳过，直到出这三件事：

1. 用户报了一个 bug，你无法确认他装的是哪一版，只能让他重装。
2. 市场里更新的版本和用户机器上的不一致，但界面看起来一模一样。
3. 回滚时没有可比对的锚点，只能靠文件时间猜。

这三件事都不是"文档没写清"，而是**界面上少了一个字符串**。所以判据必须是界面，不是文档。

## 检查项

### P1 HTML 原型首页可见

对象：`prototypes/<version>/index.html`（或等价原型入口）。

判 1 的全部条件：

- 首屏能看到的两个位置中，至少一处显示 `vX.Y.Z`：顶栏 chip 或页脚。
- 点开"关于/版本"能看到四项：版本号、构建日期、版本来源（`VERSION` / 构建注入）、渠道（prototype / beta / release）。
- 三处（顶栏 / 页脚 / 关于）由**同一个常量**渲染，逐字相同。
- 窄屏（≤600）顶栏可以让位，但页脚版本号仍可见、不换行错位。
- 版本号与仓库根 `VERSION` 文件逐字相同。

判 0 的典型：

- README 里写了 `v0.3.0`，页面上没有。
- 页脚写"设计草案 v0.3"，但那是一个手写字符串，和 `VERSION` 无关。
- 只在"关于"弹窗第三层有版本，首屏看不到。
- 三处各写一个数字，其中一处已经旧了。

### P2 发布应用首页可见

对象：装进 DSH Desktop 后的工作台真实界面（不是原型、不是文档截图）。

判 1 的全部条件：

- 安装后打开工作台，**首屏**能看到版本号（顶栏、页脚或设置页头部任一处）。
- 显示的版本与以下三处一致：`package.json` 的 `version`、Git tag、市场条目版本。
- 刷新/重启后版本号不消失，不依赖某次会话状态。
- 窄容器（业务区宽度 0.65 或分栏）下版本号不被裁掉、不压住功能入口。

判 0 的典型：

- "装机验证通过"的证据只有安装列表截图，没有工作台界面里的版本号。
- 版本号只在 DevTools 的 manifest 里能看到，用户看不到。
- 市场条目是 `0.4.0`，机器上是 `0.3.2`，界面都不显示，无法察觉。

### P3 单一来源

判 1 的条件：

- 仓库根有 `VERSION`（或等价的单一版本文件），页面版本由它渲染或构建时注入。
- 代码里只有一处写死版本号；校验脚本能同时核对 `VERSION`、页面常量、`package.json`。
- 发版顺序固定：改 `VERSION` → 同步清单 → 跑校验 → 记 CHANGELOG → 打 tag。

判 0 的典型：

- `index.html`、`app.js`、`package.json`、README 各写一份。
- 校验脚本只检查 `package.json`，页面无人管。

### P4 可追溯

判 1 的条件（至少满足两条）：

- 版本 chip 的 `title` 或"关于"里有构建日期。
- 有渠道标识（prototype / beta / release），预发布不伪装正式。
- "关于"里能定位到来源（仓库地址或 commit）。
- 发布记录（RELEASE / CHANGELOG）能按版本号查到对应产物哈希。

### P5 状态如实

- 未发布就写"未发布"，不写"已上线"。
- 预发布用 `-rc.N` / `-beta.N` 后缀，不省略。
- 装机成功 ≠ 宿主已加载 ≠ 市场已上架，三者分别写状态，不合并成"已发布"。

## 判定记录格式

```
P1 HTML 首页 1  prototypes/v0.3 顶栏 chip v0.3.0 / 页脚 v0.3.0 · 2026-10-17 / 关于四项齐
P2 应用首页 0  装机截图只有"已安装"列表，工作台界面内未见版本号 → 补顶栏或设置页头部
P3 单一来源 1  VERSION=0.3.0；scripts/check-version.mjs 核对 2 处，退出码 0
P4 可追溯   1  title="v0.3.0 · 2026-10-17 · prototype"
P5 状态如实 1  README 明写"未接入、未发布"
→ 发布门槛：未过（P2=0）
```

## 快速检查

技能自带 `scripts/publish_check.py`，只做定位与一致性核对，不做判定：

```bash
python3 scripts/publish_check.py --project /path/to/workbench
python3 scripts/publish_check.py --project . --json /tmp/publish.json
```

它会报：

- 是否找到 `VERSION` / `package.json` / 原型入口
- 版本号在 HTML 里出现的次数与上下文（是否落在 `footer` / `topbar` / 关于区）
- `VERSION` 与 `package.json` 是否一致
- 是否存在多个互相矛盾的版本字面量

脚本说"页面未出现版本号"时，仍需人打开页面确认一次——它按文本匹配，识别不了构建注入。

## 与闸口的关系

| 闸口 | P 层的作用 |
| --- | --- |
| G2 HTML demo | P1 必过：原型首屏看得见版本号，否则不算可签认的产物 |
| 装机验证（V2） | P2 必过：三种证据里的"真实界面"必须含版本号 |
| 发布（V3 / 市场） | P2–P5 全过；P5 不过就是状态造假 |

## 三条容易走偏的地方

1. **把"文档写了版本"当"界面有版本"。** 判据在 DOM 或截图，不在 README。
2. **把"关于弹窗里有"当"首屏可见"。** 用户不会为了确认版本去翻三层设置。
3. **版本号与 tag 各说各话。** 只核对 `package.json` 不够，页面常量与 tag 必须一起核；否则市场、机器、仓库三处可以同时不同。
