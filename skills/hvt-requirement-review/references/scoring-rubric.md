# 打分与分级

## 1. 三个维度

### V 患者价值（1–3）

| 分 | 锚点 |
| --- | --- |
| 3 | 直接影响安全（是否该立刻就医）、治疗方向沟通（要不要做某个治疗）、或不可逆功能（淋巴水肿、肠功能、肺功能） |
| 2 | 影响日常自我管理、复诊效率、对治疗的理解 |
| 1 | 主要是知识补充或情绪安慰，不做也不影响下一步 |

### S 癌种特有性（1–3）

| 分 | 锚点 | 例子 |
| --- | --- | --- |
| 3 | 换到别的癌种就不成立，术语/解剖/毒性/随访都不同 | 四点位臂围差（乳腺癌腋窝处理）、残余病灶分级（卵巢癌减灭术） |
| 2 | 机制类似但本癌种的组合与表述独特 | 免疫相关不良反应（多癌种共有，但肺癌的免疫肺炎监测重点不同） |
| 1 | 任何癌种都成立 | 记录用药、准备复诊、导出报告、情绪日记 |

**S=1 的场景不是不重要**，它是通用底座，应该在所有工作台都有；但它不能用来证明"本癌种需求扎实"。这类场景只在报告附录列一行"通用能力"，不进差异评价主体。

### F 频次/可及性（1–3）

| 分 | 锚点 |
| --- | --- |
| 3 | 大多数患者在标准路径上都会遇到 |
| 2 | 一部分患者（特定分期/分型/治疗）会遇到 |
| 1 | 少数情境，但一旦遇到价值极高（如急症、生育决策） |

F 只用于**排序**，不用于淘汰。F=1 但 V=3、S=3 的场景（如急症）优先级可以很高。

## 2. HVT 门槛与优先级

```
HVT 门槛：V ≥ 2 且 S ≥ 2
HVT 指数 = V × S          （2–9）
覆盖分 C  = S层+M层+F层+I层+A层  （0–5）
缺口 G    = 5 − C
优先级 P  = HVT 指数 × G   （0–45）
```

优先级分档：

| P | 处置 |
| --- | --- |
| ≥ 24 | 本期必须补，否则不建议进原型评审 |
| 12–23 | 本期补；若排期紧张可拆到原型后第一批 |
| 6–11 | 记入待办，随模块迭代补 |
| ≤ 5 | 只记录，不阻塞 |

## 3. 分级（代替"高/中/低"）

| 级 | 判据 | 报告里的写法 |
| --- | --- | --- |
| **B 阻塞** | HVT 指数 ≥ 6 且 C ≤ 2 | "有场景、无落地：照现有文档做出来必然是泛肿瘤页面" |
| **G 缺口** | HVT 指数 ≥ 4 且 C = 3 | 指明缺哪层（多数是 F 或 A） |
| **W 薄弱** | C = 4 | 指明差的那一层，通常一条验收或一个空态 |
| **U 待核验** | 内容齐但医学/法规口径未核 | 写明待核项、依据层级、谁可以核 |

**不允许出现"部分覆盖""基本满足"这种词。** 每层非 0 即 1，C 是整数；要表达"做了但很浅"，用 W + 说明差在哪。

## 4. 证据怎么写

每条结论必须带以下三种之一：

1. **定位**：`docs/SCENARIOS.md` §S08 第 3 行；`docs/SCHEMA.md` 表 `arm_circumference_set`。
2. **检索**：`grep -c "淋巴\|臂围" docs/*.md` → 0；检索范围 `docs/`，排除 `_archived/`。
3. **实测**：原型中该页面点击后无状态变化（附断言或截图路径）。

写"文档里没有"时，必须同时写检索式与范围；否则读者无法复核，等于没证据。

**检索式必须可复现**：macOS 自带 grep 的 `\|` 不表示"或"，用它做或匹配会返回假 0 命中，据此写下的"全文 0 次"是错的。或匹配一律写 `grep -rnE "甲|乙" --include="*.md" .`。落笔后再抽两条"0 命中"结论，换 `rg` 或 Python 复核一次。统计时要排除 `_archived/` 与本次新写的报告本身，否则会自指命中。

## 5. 不做什么

- 不给"文档质量分"。分数只描述覆盖，不评价写作水平。
- 不因为作者是资深/新手调整分级。
- 不把"参考项目有"当证据。参考项目只用于交互参照，业务规则必须由本癌种自己的来源支撑。
- 不把 U 级混进 B/G/W 统计算"通过率"。U 是内容核验问题，不是文档结构问题，分开统计。
