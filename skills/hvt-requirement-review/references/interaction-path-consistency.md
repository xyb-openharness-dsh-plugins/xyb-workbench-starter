# 交互路径一致性检查（X 层）：开发页面与设计 UX 流程是否同一张图

HVT 五层问"这个场景做出来了没有"，发布可见性（P）问"看得出这是哪一版吗"。X 层问的是另一个问题：

**做出来的页面（HTML 原型 / 开发版），和已签认的交互路径文档（`docs/INTERACTION-DESIGN.md`，标准见 starter `docs/28-INTERACTION-PATH-DESIGN.md`）是同一张图吗？**

它不并入 C（C 仍为 S+M+F+I+A），因为路径一致性不是某个 HVT 场景的属性，而是**整个界面与路径合同的符合度**——和 P 一样是工作台级属性。任一 X 项判 0：G2 不签认；Phase3 parity 一致性不能写达标；但不因此把某个场景的 C 降级。

## 为什么单列一层

路径文档签认之后、页面实现之时，会悄悄发生三类漂移，文档评审发现不了：

1. **导航漂移**：实现时改了入口文案/页签结构，文档没跟上——走查的人按文档找不到入口。
2. **孤儿页面**：原型里长出一个"设计时没人认领"的页面，没有任何场景路径经过它。
3. **通道回弹**：后补的页面忘了双通道纪律，平铺了 9 字段表单、加了裸删除按钮。

这三类都不是"文档没写清"，而是**实现偏离了已签认合同**。所以判据必须落在 DOM 与文档字符串的逐字比对，不在口头走查。

## 前提

项目已有**已签认**的交互路径文档（三张表齐全，见 28 号第 1 节）。没有 → X 层整体记 0，且按 IP1 不得开始/继续 HTML 构建，先补文档再谈一致性。

## 检查项

### X1 页面覆盖（无孤儿页）

对象：HTML 原型或开发版的全部 `(view, sub)`。

判 1 的全部条件：

- **双向**覆盖：①交互路径文档出现过的每个 `(view, sub)` 在实现中存在且可达；②实现中每个 `(view, sub)` 至少被一条场景路径经过。
- 孤儿页 = 0：逐个列出未被任何路径覆盖的页面，列出数为 0。
- 产出的不是"都覆盖了"一句话，而是 `(view, sub) × 路径` 穷举矩阵。

判 0 的典型：

- 导航里多出一个页面，设计评审时没人说得出它服务哪个场景。
- 文档路径里写的页签，实现里被合并/删除且无留痕。

### X2 路径逐字走通

对象：交互路径文档的每一条场景路径。

判 1 的全部条件：

- 从**看板入口**开始按文档点：入口文案 / 导航 key 与文档**逐字一致**（IP3）。
- 步骤序列每一步都能点到位，无"文档写 A、界面是 B"。
- 完成产物与文档一致且**可观察**：记录 +1 / 导出文件 / 清单条目（不是"感觉完成了"）。
- 结束后**一步回首页**（返回 / 顶栏品牌 / 完成 Toast），无死端。

判 0 的典型：

- 入口文案实现时顺手改了，文档没更新（或反之）。
- 任务做完停在深层页，只能靠浏览器后退。

### X3 CRUD 通道一致

对象：每个可写实体的两个通道（对照 CRUD 双通道矩阵）。

判 1 的全部条件：

- 每页**显式编辑入口 ≤ 1**；手工入口收在「⋯ 更多」；表单字段 ≤ 6（IP6）。
- AI 产出走**候选 → 核对 → 确认**闭环，拒收零副作用；无"AI 直接保存"（IP5）。
- **无裸删除**：删除入口一律长成"更正"，全站无"删除记录将不可恢复"式文案（IP8）。

判 0 的典型：

- 原型定稿后新加的页面平铺了长表单。
- AI 演示路径直接把结果写进列表，跳过核对界面。

### X4 无头断言出数字

对象：以上三者的证据形式。

判 1 的全部条件：

- 走查用**无头脚本**按文档逐条断言（DOM 断言），不口头说"都走过了"。
- 输出逐路径 pass/fail **计数**与失败定位（如 `13/13 pass`、`S04: 入口文案不一致 @line 3`）。
- 断言覆盖 X1 的 `(view, sub)` 穷举矩阵。
- 走查方式沿用 LESSONS 2026-10-19 的 harness 模式（DOM shim + 事件委托触发）；注意 `render()` 会重建 DOM，**不能先抓完按钮再逐个点**。

判 0 的典型：

- 证据只有截图或一句"手工点过没问题"。
- 脚本只断言"页面能打开"，不断言路径步骤与产物。

## 判定记录格式

```
X1 页面覆盖 1  34 个 (view,sub) × 13 条路径穷举矩阵；孤儿 0（harness 输出）
X2 路径走通 0  12/13 pass；S04 入口文档"3 天后复查" 实现渲染"复查提醒" → 先改文档留痕再改另一边，重走
X3 通道一致 1  显式编辑入口每页 ≤1（34/34）；表单字段 max=6；grep "不可恢复" 0 命中
X4 无头断言 1  test/path-walk.mjs 按文档 13 条路径断言，13/13 pass，退出码 0
→ G2 门槛：未过（X2=0）
```

## 与闸口的关系

| 闸口 | X 层的作用 |
| --- | --- |
| G2 HTML demo | X1–X4 必过（与 P1 并列）：页面按已签认路径逐条走通才签认；无路径文档时 X 整体 0 且不得开工（IP1） |
| Phase3 parity | 开发版复跑 X2/X3：HTML 与开发版对路径合同的一致性同标；一致性 >98% 的分子分母都要能落到路径条数 |
| 路径变更 | 实现与文档不一致时，改实现迁就文档或改文档迁就实现都可以，但必须**先改文档并留痕**再改另一边——不允许实现先行、文档追认 |

## 三条容易走偏的地方

1. **拿"页面都在"当 X1 过。** 孤儿判定是双向的：文档里的页面实现缺了、实现里的页面文档没认领，都算 0。
2. **截图与口头走查代替断言。** 没有脚本计数与失败定位，X4 记 0；回归时也无法判断哪条路径坏了。
3. **把 X 混进某个场景的 C。** 路径一致性是工作台级属性，进 C 会把单场景覆盖分搅浑；它和 P 一样只卡闸口，不卡场景分。
