# 五层落地检查

一个 HVT 场景"真的做了"，要同时满足五层。少一层，实现者就会自己发挥；这不是文档不完整，是**规格让位于实现者的想象**。

## 层 S：场景条目

**出现在**：`SCENARIOS.md`、`SPEC.md` 的场景表、`PATIENT-JOURNEYS.md`。

判 1 的条件（全部满足）：

- 有**触发**："患者在什么情况下打开它"（症状、报告、医生一句话、某个时点）。
- 有**患者动作**：依次做什么，最少几步能拿到结果。
- 有**产物**：做完拿到什么（一份材料、一个问题、一张表、一次记录）。
- 有**失败恢复**：没资料、断网、低精力、资料矛盾时还能不能继续。
- 有**边界**：哪些话不能说、哪些判断不给（例如"不评价可切除性"）。

判 0 的典型：

- 只有医学解释段落，没有患者动作。
- 只有功能名（"淋巴水肿管理"）没有三要素。
- 只有 happy path，没写"资料缺失怎么办"。

## 层 M：模块与页面

**出现在**：`CORE-MODULES.md`、`UI-DESIGN.md`、`SPEC.md` 导航章节。

判 1 的条件：

- 有明确的二级页归属（哪个一级 → 哪个二级）。
- 页内有区块清单（顶部状态 / 主区 / 侧栏 / 次要入口），不是只有页面标题。
- 与相邻页面的边界写清（例如臂围测量放"上肢与淋巴水肿"，不散落在"指标检测"和"病情汇总"两处各做一遍）。
- 数据来源写清（同一份记录被哪几个页面复用）。

判 0 的典型：

- 导航里有这个名字，但正文没有页面内容。
- 内容散在三个页面各写一段，没有归属。
- 页面只描述"用户可以查看…"，没有可操作区块。

## 层 F：字段与数据模型

**出现在**：`SCHEMA.md`、`SCHEMA-SPEC.md`、`DATA-FLOW-SPEC.md`、`API-CONTRACT.md`。

判 1 的条件：

- 该场景离不开的**关键字段**在表里（不是只有一张"记录"总表）。
- 带**单位、精度、时间语义**（采样日 vs 报告日、仅月份）。
- 带**可比性约束**：不同方法/协议/测量者不能连成一条趋势，且有字段承载这个区分。
- 带**来源与版本**：原件、修订、更正链。
- 派生值**只算不存**（除导出快照），口径写在数据流文档里。

判 0 的典型：

- 只有 `notes TEXT`，把结构化信息塞进自由文本。
- 有数值没有单位/方法，趋势图会把不同方法拼一起。
- 派生值落库，且没有重算规则。
- 一张"事件表"承载所有场景，字段靠 JSON 扩展。

## 层 I：交互与状态

**出现在**：`UI-DESIGN.md`、`CORE-MODULES.md` 的操作与呈现段。

判 1 的条件（该场景涉及图表/卡片/表单时逐条查）：

- **空态**：零条记录时给什么（引导录入，不是空白）。
- **单条**：只有一个点时画不画线（不画）。
- **多条但不可比**：断线并标注原因。
- **窄屏**：390 宽怎么排（换行、滚动容器、折叠），写明不靠横滚藏列。
- **减少动效**：`prefers-reduced-motion` 下怎么降级。
- **键盘/焦点**：可聚焦、可退出、状态变化有 `aria-*`。
- **错误与失败**：保存失败、导出失败、解析失败分别怎么恢复。

判 0 的典型：

- 只写"展示折线图"。
- 卡片"点击展开"没有说明是翻面还是折叠（这是最容易被实现错的一类）。
- 没有空态，实现者就自己造一个"暂无数据"。

## 层 A：验收

**出现在**：`ACCEPTANCE.md`。

判 1 的条件：

- 一条验收只描述**可观察结果**，不描述意图。
- 有**操作步骤**（点哪里、输入什么）与**期望**（DOM/数值/文案/文件内容）。
- 覆盖该场景的**至少一个异常路径**（资料缺失、单位不同、单条数据）。
- 编号可被 SPEC/模块文档引用。

判 0 的典型：

- "支持 X 记录"（无法判通过）。
- "界面美观、交互流畅"（不可测）。
- 只测 happy path。
- 验收条目存在但没和场景/模块编号挂钩，改需求时不联动。

## 层间关系

| 情况 | 含义 | 处置 |
| --- | --- | --- |
| S=0 但 M/F 有 | 模块是凭空长出来的，没有患者任务来源 | 要么补场景，要么删模块 |
| S=1 但 F=0 | 场景写得动人，做不出来 | 最高优先级补字段 |
| S/M/F=1 但 I=0 | 会做出一堆静态页 | 补状态与交互，进 G2 前必须补 |
| 前四层齐但 A=0 | 无法验收，改需求时无人知道是否回退 | 补验收，一条即可 |
| 五层齐但 U 未清 | 结构没问题，内容可能错 | 单独列 U，内容上线前必须核 |

## 判定记录格式

```
BR-HVT-03 腋窝处理后的上肢淋巴水肿
V3 S3 F3 → HVT 9
S1  docs/SCENARIOS.md S08（触发/四点位/差值/失败恢复齐）
M1  docs/CORE-MODULES.md §2 上肢与淋巴水肿（四区块）
F0  docs/SCHEMA.md 只有 measurement.value，无 protocol/paired → 趋势会比较不同点位
I0  UI-DESIGN 未写单条/不可比/窄屏
A1  ACCEPTANCE A9（新增测量→差值→同步）
C=3 → G 缺口，P=9×2=18
```
